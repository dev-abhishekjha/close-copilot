# UI-03 · App shell: sidebar, top bar, context bar, role-aware nav

## Goal

Every signed-in page sits in one frame: a sidebar and top bar whose links come from the route table, so a role sees only links it may follow, plus a company and month context that pages use as their default. The home page stops listing API paths and links to real pages.

## Context

- Ticket: `tasks/frontend-plan.md`, sections 3, 4 and 10 (`UI-03`). Regulated because it touches `routes.go` role wiring: owner review, Opus spec and diff review, and G5.
- **Role checks stay in the route table and middleware.** Hiding a link is a convenience, never the control. The shell must not add a code path that decides access: it asks the existing `Server.allows(role, method, path)` and nothing else.
- **No page handler is edited to get the shell.** `Server.render` (`server.go:237`) is where every page is rendered. It attaches `ShellData` to the request context; `templates.Base` reads it with `ShellFrom(ctx)`. A request with no principal (login, errors before auth) gets no shell and the old plain frame. The login page therefore stays as it is. `render` also serves htmx fragments and pages rendered from POSTs: build the `ShellData` lazily, only when `Base` asks for it (store a func or a small struct in the context), and set `Path` to `/` whenever the request method is not GET, so the context form's `next` is never a POST-only URL.
- CSP (`middleware.go:20`) unchanged: no inline script or style. The shell loads `/static/js/ui.js` (UI-02) with `<script src defer>`; it is the only added script.
- Do not edit `middleware.go`, `auth.go`, `approvals.go`, `internal/approvals/**` or `config/users.yaml` (the last acceptance line checks).

### ShellData (package `templates`, file `shell.go`)

```go
type NavItem struct{ Label, Href, Icon string; Current bool }
type NavGroup struct{ Title string; Items []NavItem }
type Crumb struct{ Label, Href string } // Href empty for the last crumb
type ShellData struct {
    User, Role, CSRFToken string
    Nav        []NavGroup
    Companies  []string // empty when the runs backend is not configured
    Company, Month string // the validated context
    Path       string   // request path, for the context form's "next"
}
func WithShell(ctx context.Context, d ShellData) context.Context
func ShellFrom(ctx context.Context) (ShellData, bool)
```

`Layout` (pages.go) gains `Crumbs []Crumb` (optional; no page sets it yet). `Layout.User`, `Role` and `CSRFToken` stay for compatibility; when a `ShellData` is present it wins.

### Navigation

A table in `shell.go` (not user-editable), each entry `{Group, Label, Icon, Path}` with `Path` a GET route pattern. An entry is shown only when `s.allows(role, "GET", Path)` is true. Because `allows` reports false for a path that is not in the route table, pages that do not exist yet (`/findings`, `/ask`, `/proposals`, `/documents`, `/system`) stay hidden until their ticket adds the route, with no change here.

| Group | Label | Icon | Path |
| --- | --- | --- | --- |
| Work | Dashboard | `home` | `/` |
| Work | Close runs | `play` | `/runs` |
| Work | Findings | `alert` | `/findings` |
| Work | Ask | `message` | `/ask` |
| Review | Approvals | `check-circle` | `/approvals` |
| Review | Proposals | `file-text` | `/proposals` |
| Reference | Documents | `book` | `/documents` |
| Reference | Audit log | `shield` | `/audit` |
| Reference | System | `server` | `/system` |

`allows(role, "GET", "/")` matches the catch-all `GET /` row, not `GET /{$}`; both are `anyRole` today, so comment the Dashboard entry to say UI-04 must keep them in step. A group with no visible item is not rendered. `Current` is set for the item whose `Path` equals the request path, or is the longest prefix at a `/` boundary (`/runs/abc` highlights Close runs; `/` matches only `/`). With today's routes: viewer and maker see Dashboard and Close runs; checker also sees Approvals and Audit log.

### Context (company and month)

- Cookie `cc_ctx`, value `url.Values{"company":..., "month":...}.Encode()`. Build it with the existing `s.cookie("cc_ctx", v, "/", 365*24*3600, time.Time{})` (`auth.go:415`), which already sets `HttpOnly`, `SameSite=Lax` and `Secure` per `s.secureCookies`; do not write a second cookie builder (read its signature first and adapt the call if it differs, without changing the session cookie's behaviour). It is a preference, not a credential: it is **not signed and is always revalidated**.
- `Server.contextFor(r) (company, month string)`: parse the cookie; the company is used only if it is in the list from `ListCompanies`; the month only if it matches the existing `monthRE` (`runs.go:49`). A value longer than `maxCompanyLen` (`ratelimit.go:37`) or a cookie over 512 bytes is ignored. Anything else (missing, malformed, unknown) falls back independently: company to the first listed company (empty when the backend is not configured), month to the previous calendar month in UTC from `s.now()` (a close runs after the month ends).
- The company list used by the **shell** is cached for 30 seconds in the server (mutex or `atomic`), so a page view does not query the database each time. `renderRuns` (`runs.go:377`) and `/api/ask` (`ask.go:116`) keep their own direct `ListCompanies` calls unchanged; a cache error returns the stale list if there is one, else none, and logs once per failure with `slog`. The cache never holds anything user-supplied.
- `POST /context`, roles `anyRole`, form fields `company`, `month`, `next`. It sits behind the same CSRF and same-site checks as the other POST routes (the route-table wrapper already provides them). It validates as above, sets the cookie, and redirects `303 See Other` to `safeNext(next)`. Invalid values are ignored and the cookie keeps the last valid or default value; they are never reflected. Body capped by the server-wide limit.
- `runs.go` `handleRunsPage` (`:409`): read `company` and `month` from `r.URL.Query()` and pass them to `renderRuns` as the start-form prefill (templ escapes them; they are not validated, the same as the POST error path today); for each field that is empty, use the matching value from `contextFor`. Nothing else in `runs.go` changes.

### Frame (templ, `shell.templ`, used by `Base` when `ShellFrom` is ok)

- Skip link "Skip to content" first in the body, targeting `<main id="main" tabindex="-1">`.
- Sidebar `<nav aria-label="Main">`: brand, groups with a visible heading, items as links with the UI-01 icon, `aria-current="page"` on the current one.
- Top bar: breadcrumbs when `Layout.Crumbs` is set (`<nav aria-label="Breadcrumb">`, `<ol>`), the context form (company `<select>` when `Companies` is non-empty, month `<input type="month">` with a `pattern` fallback, an "Apply" button, hidden `csrf_token` and `next` = `Path`), the user name, a role chip (keep `class="role"` and `data-role`), and the sign-out form (keep the existing `POST /logout` form with `csrf_token`).
- `dev_components.templ` currently loads `ui.js` itself; remove that tag (and regenerate), because the shell now loads it and a second load could double-bind handlers. `devcomponents_test.go:36` keeps passing since the shell emits the same tag.
- Existing hooks other tests rely on stay: `class="brand"`, `class="user"`, `class="role"` with `data-role`, `action="/logout"`.
- Mobile (under 56rem): the sidebar collapses into a menu with no JavaScript. Render the nav **once**: on small screens the same `<nav>` is revealed by a `<details>` toggle in the top bar through CSS (for example the `<details>` wraps the nav element, and `shell.css` forces it open and hides the summary at wide widths). Never emit the nav twice: that would give two "Main" landmarks and duplicate `aria-current`.
- Light and dark through tokens only. A theme toggle is not part of this ticket.
- All text from `ShellData` (names, company ids) is escaped by templ.

### Home page

`home.templ` stops printing `<code>METHOD /api/...</code>`. Each `homeAction` gets an optional `Href` of the UI page for it (`view-run`, `view-findings`: `/runs`; `start-run`: `/runs`; `approvals`: `/approvals`; `audit`: `/audit`; `ask`, `propose-entry`, `approve-proposal`, `reject-proposal`: none yet, so rendered as plain description text). Items with an `Href` are links; every `data-action="<id>"` stays (the UI-04 dashboard replaces this page; `TestHomeActions` must keep passing). Show the user's role-allowed destinations as buttons using the UI-02 `Button` with `Href`.

## Acceptance (human-readable)

- A viewer, a maker and a checker each sign in and see exactly their links; no role sees a link whose target answers 403.
- Switching company and month in the top bar keeps you on the same page and survives a reload; a hand-edited cookie never breaks a page.
- The login page is unchanged; every existing page renders inside the frame; the page is usable with the keyboard only (skip link, focus order, visible focus).
- `middleware.go`, `auth.go`, the approvals code and `config/users.yaml` are untouched.
