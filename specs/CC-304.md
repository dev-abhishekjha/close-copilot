# CC-304 · Book writer

## Goal

Post every book-side event of a generated world as a submitted ERPNext document, and record the ERPNext name each `ExtID` received. A crash halfway is harmless: rerunning finishes the job without duplicates.

## Context

- Ticket: `docs/implementation-tickets.md`, section `CC-304`. Shared spec: "Money, dates and IDs" (`copilot_ext_id` holds the event's ExtID).
- **Inputs:**
  - `seed.Generate(profile, month, Options{Small})` (CC-302): events with their base account names, paise amounts, `Refs` and `BankRef`; read `internal/seed/world.go`.
  - `seed.Bootstrap` (CC-303) is idempotent and returns `BootstrapReport` with every resolved name:
    - `Accounts` (base name → ERPNext name), `BankAccount`, `InputGST`/`OutputGST`;
    - `Suppliers` (profile id → ERPNext name, keyed by `Meta.SupplierID`);
    - `Customers` (named `CUST-001`…);
    - `ItemTaxTemplates` (GST rate → template), `ExtIDField`.

    Call it first, so the writer never guesses names; read `internal/seed/bootstrap.go`, including the comments on Item Tax Templates and `ItemFor`.
- **ERPNext facts found in CC-303:**
  - India Compliance refuses explicit GST rows (`charge_type: Actual`) unless every item line has an `item_tax_template`. Use the template for the event's `Meta.GSTRate`.
  - It accepts tax amounts within ₹1 of template rate × taxable. The generator rounds per invoice, so amounts match.
  - Saving an invoice auto-creates an `Item Price` record. That's harmless, but don't count it.
  - The dev site has `delete_linked_ledger_entries=1`.
- **Keys:** use the seeder key (`ERP_SEED_API_KEY`/`ERP_SEED_API_SECRET`). Acceptance loads `tmp/erp-keys.env` with `set -a; . file`. Never print secrets, and never read `.env`.
- **Amounts:** ERPNext takes rupees. Send `money.Paise.Rupees()` strings or `json.Number`, never floats (`nofloat` covers `internal/seed`).
- **Dates:** set `set_posting_time: 1` and `posting_date` to the event date on every voucher, so ERPNext doesn't post them today.
- `data/` is git-ignored. `erp_map.json` is output, not a committed file.
- No new dependencies.

## Subtasks (Phase 1: `suite-skeleton`, company `sharma`, `--small` months)

- [ ] **`internal/seed/books.go`:** `WriteBooks(ctx, c *frappe.Client, rep BootstrapReport, w World, opt BooksOptions) (BooksResult, error)`. There is one mapping function per kind. Each document carries `copilot_ext_id` = ExtID, a `remarks` (or `user_remark`) with the event's `Narration`, and the event date.
  - **`sale` → Sales Invoice:**
    - customer = Party; `debit_to` Debtors; `due_date` = posting date + 15 days;
    - one item line: `ItemFor(...)`, qty 1, rate = Taxable, `income_account` Sales, `item_tax_template` for the rate;
    - output-GST tax rows (`charge_type: Actual`, CGST and SGST, or IGST), with `tax_amount` from the event.
  - **`receipt` → Payment Entry:**
    - Receive, party Customer, `paid_from` Debtors, `paid_to` the bank;
    - `references`: the Sales Invoice named by `Refs[0]`, `allocated_amount` = Gross;
    - `reference_no` = BankRef (or the ExtID if there's none), `reference_date` = date.
  - **`gateway_receipt`:** a Payment Entry (Receive) into Payment Gateway Clearing, with the same references.
    - ERPNext may refuse a Payment Entry whose `paid_to` isn't a Bank or Cash account. Clearing is a plain Asset account from CC-303, which this ticket can't change. In that case post a **Journal Entry** instead: Dr Payment Gateway Clearing; Cr Debtors with `party_type: Customer`, `party`, `reference_type: Sales Invoice` and `reference_name`.
    - Pick whichever ERPNext accepts. Document it in `books.go`, and use the same voucher type every time.
  - **`purchase` → Purchase Invoice:**
    - supplier from `Suppliers[Meta.SupplierID]`; `bill_no` = InvoiceNo; `bill_date` = date; `credit_to` Creditors;
    - one item line: `ItemFor`, qty 1, rate = Taxable, `expense_account` = the event's resolved account, and a `description` carrying `Meta.Description` plus the service period when set, and `item_tax_template` when GST applies;
    - input-GST rows (`Actual`) for registered suppliers; none for unregistered ones;
    - `remarks` = Narration.
    - **If ERPNext rejects the laptop's `Office Equipment` (Fixed Asset) account on a Purchase Invoice line, or the annual bill's `Prepaid Expenses` line, stop and report the exact error** rather than picking another account. The fallback touches CC-302, CC-303 and docs, so the orchestrator decides it.
  - **`vendor_payment` → Payment Entry:** Pay, party Supplier, `paid_from` the bank, `paid_to` Creditors, the `references` Purchase Invoice from `Refs[0]`, `reference_no` = BankRef, `reference_date` = date.
  - **Journal Entries:** `voucher_type: Journal Entry`, balanced lines, `cheque_no` = BankRef or ExtID and `cheque_date` = date on any line that hits the bank.
    - `payroll`: Dr Salaries, Cr bank.
    - `bank_charge`: Dr Bank Charges (Taxable), Dr Input CGST and Input SGST (or IGST), Cr bank (Gross).
    - `interest`: Dr bank, Cr Interest Income.
    - `prepaid_amortisation`: Dr Software Subscriptions, Cr Prepaid Expenses.
  - **`gateway_settlement`:** nothing. It's left for the agent; count it as skipped.
  - **Insert, then submit.** A document that fails to submit is reported with the ERPNext message.
- [ ] **Order, parallelism and determinism:**
  - ERPNext names come from naming series, and ground truth (CC-306) points at those names. CC-307 needs two reset-and-seed runs to give identical names. So **post each DocType sequentially in `(Date, ExtID)` order**, and parallelise only across DocTypes.
  - **Stage 1:** Sales Invoices and Purchase Invoices, one worker each.
  - **Stage 2:** the Payment Entries and the Journal Entries, which need stage-1 names. One worker per DocType. With the gateway-receipt choice, that's up to four workers.
  - A failed document stops its worker. Other workers finish their current document and stop. The error lists every failure.
- [ ] **Resume:**
  - Before posting, list each DocType's existing `copilot_ext_id` values (docstatus 0 and 1) for the company and the month's dates.
  - A submitted document is recorded and skipped.
  - A **draft** with our ExtID (a crash between insert and submit) is submitted, not re-inserted.
  - A cancelled one (docstatus 2) is an error naming it.
  - `Refs` resolve through the same map, so a rerun after a crash still links payments to invoices posted in the first run.
- [ ] **`internal/seed/erpmap.go`:**
  - `ERPMap` is ExtID → `{doctype, name}`. `WriteERPMap(dir, m)` writes `erp_map.json` sorted by ExtID with 2-space indent and a trailing newline. `LoadERPMap(path)` reads it back.
  - The path is `data/out/<suite>/<company>-<month>/erp_map.json`.
  - Write the map only after a successful run, so a crash never leaves a partial map that looks complete.
- [ ] **`BooksOptions`:**
  - `StopAfter int`: stop cleanly after posting N new documents (0 = no limit), so tests can simulate a crash;
  - `Workers int`: default 4.

  **`BooksResult`:** per-DocType created, submitted-from-draft, already-present and skipped counts.
- [ ] **`cmd/seed/main.go`:**
  - `seed books --company sharma --month 2026-09 [--small] [--suite suite-skeleton] [--config config/companies] [--out data/out] [--expect-no-changes]`;
  - it runs `Bootstrap` (it must report zero changes, else fail with "run seed bootstrap first"), then `Generate`, then `WriteBooks`, then writes the map;
  - it prints `BooksResult` as JSON;
  - `--expect-no-changes` exits non-zero if anything was created or submitted;
  - `world` and `bootstrap` keep working unchanged.
- [ ] **Unit tests** (`books_test.go`, `erpmap_test.go`), against a fake Frappe (`httptest`, in memory, like CC-303's):
  - every kind maps to the right DocType and fields; a golden file of every write request for a small world goes under `testdata/books/`;
  - Sales and Purchase Invoices carry `item_tax_template` and `Actual` rows that equal the event's taxes;
  - an unregistered supplier's bill has no tax rows;
  - every Journal Entry balances in paise;
  - a resume where the fake holds a submitted document and a draft for two ExtIDs: the first is skipped, the draft is submitted, nothing is inserted twice;
  - a cancelled one errors;
  - `StopAfter` then a rerun gives the same final state as one run;
  - names within a DocType are posted in `(Date, ExtID)` order;
  - `gateway_settlement` posts nothing;
  - the ERP map round-trips and is byte-stable.
- [ ] **Integration tests** (`books_integration_test.go`, `//go:build integration`; skip without the ERP and seed variables):
  - `TestIntegrationBooksResume` on **sharma 2026-08 `--small`** (suite-skeleton's clean month):
    - run `WriteBooks` with `StopAfter: 15`;
    - rerun without a limit;
    - assert that per-DocType counts of submitted documents with a `copilot_ext_id` for the month equal the world's counts by kind (receipts and gateway receipts counted under the voucher type you chose; settlements excluded);
    - assert that no ExtID appears twice (list `copilot_ext_id` across the four DocTypes);
    - a third run creates nothing.
  - `TestIntegrationBooksTrialBalance`, after the above:
    - list every GL Entry of the company with `posting_date` in 2026-08 (`is_cancelled = 0`), summing debit and credit in paise with `internal/money`; they must be equal;
    - also check the bank account's net movement equals the sum of `BankDelta()` over book-side events. Settlements are excluded because the books don't record them.

  These tests leave August posted. That's intended: CC-204 tests the trial balance against these books, and CC-307's reset restores the clean backup.

## Acceptance (human-readable)

- A seeded month posts without errors, and per-DocType counts equal the world's event counts.
- The month's GL balances (debits = credits).
- Killing the writer midway and rerunning finishes without duplicates.
- A second `seed books` run for the same month changes nothing.

## Out of scope

- The full trial balance and account history API (CC-204).
- Bank CSV and GSTR-2B (CC-305), planting (CC-306), reset and the `all` subcommand (CC-307).
- Changing CC-302's world or CC-303's bootstrap. If either is wrong, report it.
