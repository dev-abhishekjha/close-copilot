# CC-009 · Snapshot annotation for check evidence arguments

## Goal

A check step that emits a finding in the real workflow no longer fails with `ErrNoSnapshot`, while a ref that no recorded tool result supports still fails closed.

## Context

- Ticket text: `tasks/hardening.md`, section `CC-009` (not in `docs/implementation-tickets.md`). Found in the CC-1103 build.
- Today `matchRef` -> `snapshotCall.supports` (`internal/agent/snapshot.go:176`, `:207`) accepts a ref arg only when the call recorded an argument of that name with an equal canonical value, or when the arg names a value in the call's indexed `keys` (bankrec's `txn_id`, `voucher_no`). Any other arg returns false, so the ref has no snapshot.
- Four checks build refs with args that no recorded call holds, so their check step ends `ErrNoSnapshot` as soon as it emits a finding in the real workflow. The suite so far plants only bank charges, so nothing hit it:
  - `internal/checks/rules.go:99`: `company, month, rule, account` (+ `service_period_start`, amounts) on its refs.
  - `internal/checks/duplicates.go:148-152`: `list_payments`, `list_purchase_invoices` and `list_bank_lines` refs with `company, month`.
  - `internal/checks/gstr2b.go:152`: `company, from, to, books_tax_paise, igst_paise, cgst_paise, sgst_paise` (books side) and a 2B-side map built by `twoBArgs` (read it).
  - `internal/checks/variance.go:196`: `list_purchase_invoices` with `company, month`; `get_account_history` with `company, account, through_month, months`; `list_gl_entries` with `company, from_date, to_date, account`.
- What the readers record (`snapshot.go`): range tools (`list_gl_entries`, `list_purchase_invoices`, `list_sales_invoices`, `list_payments`, `list_bank_lines`, `get_trial_balance`) record `rangeArgMap(company, from, to)` = `company, from_date, to_date`; `get_account_history` records `company, account, months, through_month`; `list_gstr2b_entries` records `company, period` (YYYY-MM). Indexed keys per tool are in the `idx.add` calls at `snapshot.go:290-446`.
- Security properties that must stay (CC-709, CC-506): a ref must carry `company` and can never match another company's call; every ref ID must be a record present in the result; the first matching call in recording order wins; any unsupported ref returns an error wrapping `ErrNoSnapshot` and leaves findings unchanged. Nothing here may loosen "a ref with nothing to match on matches nothing".
- Do not edit `internal/checks/**` (not in `files`). The fix lives in the agent's annotation.

## Subtasks

- [ ] Decide, per recorded tool, how a ref arg is satisfied, and implement it in `supports`/`matchRef` with the rules explicit in code and comments:
  - `month` (YYYY-MM) is satisfied by a call whose `from_date`/`to_date` window covers that month, or, for `list_gstr2b_entries`, whose `period` equals it; `from`/`to` are the same thing as `from_date`/`to_date` for the GSTR-2B books side.
  - `through_month`, `months`, `account` on `get_account_history` still compare equal to the recorded args.
  - Purely descriptive args that carry no evidence (`rule`, `service_period_start`, the `*_paise` tax amounts and similar) are ignored, from a fixed, named list in the code. An unknown arg name still fails; do not turn "unknown" into "ignore".
  - If one of those descriptive args is an amount that the verifier relies on, keep it out of the ignore list and say so in Notes; check `internal/agent/verify_amounts.go` before deciding.
- [ ] Keep company scoping, ID membership and fail-closed behaviour unchanged.
- [ ] Delete `windowArgs` from `internal/agent/injection_test.go` and use the real `PolicyRulesCheck` in `TestInjectionTaintsRecords`; re-run the taint tests.
- [ ] Add a table test in `snapshot_test.go`: one finding from each of `PolicyRulesCheck`, `DuplicatePaymentCheck`, `GSTR2BCheck` and `VarianceCheck` (use their real constructors and the existing synthetic inputs/fakes; add `testdata/` fixtures only if a check needs data the fakes lack) annotated against recorded readers, asserting every ref gets an `Artifact`.
- [ ] Add fail-closed cases: a ref for another company, a ref with an unknown arg, a `month` outside every recorded window, an ID not in the result: each returns `ErrNoSnapshot` and leaves findings unchanged.
