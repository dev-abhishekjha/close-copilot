# CC-806b · Score citation precision and validity

## Goal

`eval score` reports citation validity and citation precision against `evals/golden/citations.yaml` (CC-907), so CC-806's Gate D ("validity 100%, precision at or above the baseline") can be measured and gated, and `eval run` can retrieve (recorded for `--replay`) so the retrieve steps and citations exist to score.

- Ticket text (quoted): "A scorer in `internal/evals`: match each golden case to its finding by the ground-truth keys (never by text); validity = every cited pair exists in the ingested corpus; precision = the cited pair is in the case's `expect` any-of list. Report both in `score.json` and `score.md`, and add a `--require` key. - The golden file (read-only; shape): a YAML list; each case `{id, finding: {scenario, company, month, type, keys: {k: v}}, expect: [{doc_id, section}, ...]}`. `expect` is **any-of**. `finding` keys are the ground-truth keys in `evals/scenarios/<scenario>/ground_truth/<company>-<month>.json`; match by those keys, never by text. The header still says DRAFT and the owner confirms it; load it as-is, and tolerate a missing file only where noted below. Cases exist for `suite-v1` (F01 to F10); `suite-skeleton` has no case (it has no matching planted keys), so a skeleton score has no applicable case.
- Citation format and types: `store.Citation{DocID, Section string}` (`internal/store/runs.go:33`); a finding carries `Citations []store.Citation` (`json:"citations,omitempty"`), already in each run's result JSON (`Result.Findings []store.Finding`, `internal/evals/result.go:42`). A citation matches a pair **exactly** (same `doc_id` and `section` strings after no trimming beyond what the existing `target.matches` does for keys).
- Metric definitions (this ticket decides these; keep them in the `Citations` doc comment):
  - **Applicable case**: a golden case whose `(scenario == suite name, company, month)` is among the scored months and whose `finding` matches a scored finding by type and keys (use `target.matches`, `internal/evals/score.go:523`, over the run's findings, not text). A case whose month ran but whose finding was not produced is `missed` (counts against nothing here; recall already measures it) and is listed, not scored. A case whose month is not in the run is `not_run` and is listed.
  - **Cited**: an applicable case whose matched finding has at least one citation. A finding with no citations is `uncited`.
  - **Validity** = cited pairs that exist in the corpus / all cited pairs, over every citation on every matched finding (not only the golden ones). Report as `Ratio` (`NewRatio(num, den)`, `score.go:99`). With zero cited pairs the ratio is `0/0` and `--require citations.validity>=N/M` fails as unmeasured, as `checkRatio` already does for a zero denominator (read `require.go:260` and copy its behaviour).
  - **Precision** = matched findings with at least one citation in the case's `expect` list / matched findings with at least one citation. An unsupported citation (cites a pair not in `expect`, or nothing in `expect`) fails that finding. Per-case outcomes: `right`, `wrong_section` (cited a `doc_id` in `expect` but no listed section), `wrong_document` (no cited `doc_id` in `expect`), `unsupported` (cited pair not in the corpus), `uncited`, `missed`, `not_run`. Pick one outcome per case in that precedence: `unsupported` if any cited pair is invalid, else `right`, else `wrong_section`, else `wrong_document`.
  - Also report `cited` as a Ratio (`cited / applicable matched findings`) so a model that cites nothing is visible, not hidden by precision's denominator.
- Where validity's corpus comes from: a `CorpusSections` set of `(doc_id, section)` pairs per company (a company's own docs plus the shared ones, as `Store.CitationExists` does, `internal/store/verdicts.go:109`). Live (`eval run`) it is read from `doc_chunks` through the store; for replay it is a recorded fixture (`corpus_sections`, below), so scoring and replay need no database. `eval score` reads the set from the suite's fixture folder (`<fixtures-dir>/<suite>/`), not from Postgres.
- `score.json` / `score.md`: `Score` (`internal/evals/score.go:249`) gets a new field `Citations Citations` (`json:"citations"`) with `Validity`, `Precision`, `Cited` Ratios, `Measured bool`, `Reason string` (why not measured: no golden file given, no corpus fixture, no applicable case) and `Cases []CitationCase`. `score.json` loading is strict (`readStrict`, `score.go:1124`) and sorted-key (`marshalSorted`), so update the `score.json` golden testdata under `internal/evals/testdata/score/` deliberately. - `--require`: add subject `citations` with metrics `validity` and `precision` (ratio form `N/M`, same operators as `recall`), e.g. `--require 'citations.validity>=10/10' --require 'citations.precision>=7/10'`. `ParseRequire` (`require.go:56`) and `Requirement.Check` (`require.go:195`) currently take subjects `overall|clean|unauthorized_writes|verified_rate|<scored type>`; a scored type named `citations` cannot exist, so add the constant `SubjectCitations = "citations"`.
