# CC-204 · Trial balance and account history

## Goal

Functions that return a company's trial balance for any period, and month-by-month totals for one account, computed from GL Entries in exact paise.

## Context

- Ticket: `docs/implementation-tickets.md`, section `CC-204`. Shared spec "MCP tool catalog": the books server's `get_trial_balance` (company, from_date, to_date → account, opening, debit, credit, closing) and `get_account_history` (company, account, months → month, debit, credit, net) will call these in CC-502. Shape the return types so CC-502 can serialise them directly.
- `internal/frappe` (CC-202/203):
  - `List[T](ctx, c, doctype, Query{Fields, Filters, OrderBy, Limit})` pages through results;
  - `GLEntryRaw`/`AccountRaw` with `Domain()` converters, and `Fields[T]()` for the field list;
  - `Call[T]` for whitelisted methods.

  Read `internal/frappe/models.go` and `client_api.go`.
- **No floats:** CC-002's `nofloat` covers `internal/books`. All amounts are `money.Paise`.
- **The accounting rule:**
  - Balance-sheet accounts (root type Asset, Liability, Equity) carry an opening balance made of every earlier entry.
  - Income and Expense accounts start from zero at the fiscal-year start. In India the fiscal year runs **1 April to 31 March**. Their opening is the sum from the fiscal-year start of `from` up to the day before `from`.
- Skip cancelled entries (`is_cancelled = 1`). ERPNext also writes reversing entries on cancel, and both carry `is_cancelled = 1`.
- **Live data:** the shared ERPNext holds Sharma Traders Pvt Ltd (`STPL`) books for 2026-08 and 2026-09 (small months, posted by CC-304), with nothing earlier. The integration test is **read only**: it must never insert, submit or cancel anything. Use the **bot key** (`ERP_API_KEY`/`ERP_API_SECRET`, Accounts User), the key the books MCP server will use.
- No new dependencies.

## Subtasks

- [ ] **`internal/books/reports.go`:**
  - `Ledger` interface, the data source, so tests use fakes:
    - `GLEntries(ctx, company string, from, to time.Time) ([]frappe.GLEntry, error)`: non-cancelled, inclusive dates; `from` may be the zero time, meaning "from the beginning";
    - `Accounts(ctx, company string) ([]frappe.Account, error)`.
  - `FrappeLedger{C *frappe.Client}`:
    - implements `Ledger` with `frappe.List`;
    - filters `company`, `posting_date` between the dates (or `<=` for an open start) and `is_cancelled = 0`;
    - explicit fields via `frappe.Fields`;
    - converts with `Domain()`, wrapping errors.
  - `FiscalYearStart(d time.Time) time.Time`: 1 April of the fiscal year containing `d`, at UTC midnight (e.g. 2026-03-31 → 2025-04-01, 2026-04-01 → 2026-04-01).
  - `TrialBalance(ctx, l Ledger, company string, from, to time.Time) (TB, error)`:
    - `TB{Company, From, To, Rows []TBRow, Totals TBTotals}`;
    - `TBRow{Account, AccountName, RootType, Opening, Debit, Credit, Closing}`, with signed `money.Paise` (debit positive) for Opening and Closing, and Debit and Credit as period totals (≥ 0);
    - `Closing = Opening + Debit − Credit`;
    - leaf accounts only; a row is included if any value is non-zero;
    - rows sorted by `RootType` (Asset, Liability, Equity, Income, Expense), then account name;
    - `Totals` sums Opening, Debit, Credit and Closing.
    - Validate: `from ≤ to`, both UTC midnight (else an error).
    - Fetch the minimum: entries up to `to`, using the opening rule above.
    - **The function checks that `Totals.Debit == Totals.Credit` and that opening and closing each sum to zero, and returns an error naming the gap if not.** A ledger that doesn't balance is a data problem the caller must see.
    - An entry on an account missing from `Accounts`, or with an unknown root type, is an error.
  - `AccountHistory(ctx, l Ledger, company, account string, through string, months int) ([]MonthTotal, error)`:
    - `MonthTotal{Month "YYYY-MM", Debit, Credit, Net}` with `Net = Debit − Credit`;
    - exactly `months` entries (1–36, else an error), oldest first, ending with `through` (`YYYY-MM`); months with no entries give zeros;
    - the account must exist for the company (else an error).
  - Doc comments state the opening rule and the sign convention.
- [ ] **Unit tests** (`reports_test.go`), against a fake `Ledger` and hand-built entries, table-driven:
  - an Asset with entries in the previous fiscal year carries them into the opening;
  - an Expense with entries in the previous fiscal year doesn't, but its entries from 1 April up to `from` do;
  - a period crossing 1 April;
  - a cancelled entry from the fake is excluded (the fake must also honour the filter; test `FrappeLedger`'s query with `httptest`, asserting the filters and fields sent);
  - totals balance on a balanced fixture;
  - an unbalanced fixture returns an error;
  - zero rows are omitted, and the row order is fixed;
  - bad dates, bad months and an unknown account error;
  - `AccountHistory` fills empty months and spans a year boundary (2026-11 … 2027-02).
  - Fixtures can live in `testdata/reports/` as JSON shaped like ERPNext's GL Entry list responses.
- [ ] **Integration test** (`reports_integration_test.go`, `//go:build integration`; skip without the ERP variables):
  - `TestIntegrationReportsTrialBalance` for STPL, 2026-09-01 to 2026-09-30, through `FrappeLedger` with the bot key:
    - totals balance;
    - **cross-check against ERPNext's own Trial Balance report.** Call `frappe.desk.query_report.run` (GET or POST through `frappe.Call`) with `report_name: "Trial Balance"` and filters `company`, `fiscal_year` (look it up, e.g. `2026-2027`), `from_date`, `to_date`, `show_zero_values: 0`;
    - for every leaf account in the report, `closing_debit − closing_credit` (via `money.FromJSONNumber`) must equal the row's `Closing`, and `opening_debit − opening_credit` must equal `Opening`;
    - log the account count compared.
    - If the bot is refused the report (`IsPermission`), fall back to the seeder key **for the report call only**, and say so in a comment.
  - `TestIntegrationReportsAccountHistory`: the bank account (`HDFC Current 0001 - STPL`) for 3 months through 2026-09:
    - July is zero, August and September are non-zero;
    - September's `Net` equals the TB row's `Debit − Credit` for the same account.
  - Read only.

## Acceptance (human-readable)

- Total debits equal total credits for any period, which both the tests and the function assert.
- For seeded September, every account's opening and closing balance matches ERPNext's Trial Balance report.

## Out of scope

- The MCP tools that expose these (CC-502).
- Multi-currency (the books are INR only); period closing vouchers.

## Notes

- ERPNext's Trial Balance report rows include group accounts and a total row. Compare only leaf accounts (rows whose `account` is a non-group account in `Accounts`).
