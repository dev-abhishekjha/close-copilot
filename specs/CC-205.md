# CC-205 · Harden the Frappe client, probe and API-user script

## Goal

The Frappe client refuses unsafe queries and calls, every request has a deadline, and the probe and setup script handle the API secrets as carefully as the client does.

## Context

- Ticket text: `tasks/hardening.md`, section `CC-205`. It collects the CC-202 G5 findings (N1, N3, N4, N5, N6, N9) and the CC-201 G5 findings on the probe and `deploy/erpnext/api-users.sh`. Read it first; this spec only adds what has changed since it was written.
- **CC-104 already did part of finding 7.**
  - The probe client holds its key and secret as `config.Secret`, with `GoString` and `Format`.
  - `config.Secret` is pointer-backed.
  - What's left for the probe: `CheckRedirect`, the 403 rule, and check (d).
- **`frappe.Secret` (finding 6):**
  - Don't build a second secret type. Change `New` to `New(cfg config.Config, key string, secret config.Secret) (*Client, error)` and delete `frappe.Secret`.
  - Inside the client, `Reveal()` is called only where the `Authorization` header is built and in `redact`.
  - Update every caller listed in `files`, one line per call site: `frappe.New(cfg, cfg.ERPSeedAPIKey.Reveal(), cfg.ERPSeedAPISecret)`, and tests use `config.NewSecret("…")`.
  - Compile with and without `-tags=integration` to find them all.
- **Probe (finding 7):** switching the probe to `internal/frappe` is preferred.
  - If the probe needs a raw request the client doesn't offer, keep its own client but give it the same redirect and `PermissionError` rules.
  - Either way, `TestClientFormattingHidesCredentials` (CC-104) must still pass.
- **`IsNotFound` (finding 4):** it now also requires `exc_type` `DoesNotExistError`.
  - Audit `internal/seed/bootstrap.go`, which uses `IsNotFound` in its lookup and cleanup paths.
  - Change it only if the stricter rule changes its behaviour.
  - Run `go test ./internal/seed/...` to show it still works.
- **Protected path:** `docs/erpnext-schema/README.md` is protected, which is why this ticket is `human_review`. The only change there is the env-loading example (`set -a; . tmp/erp-keys.env; set +a`). Nothing else in `docs/` changes.
- **Secrets:**
  - Never read `.env`, and never print a value from `tmp/erp-keys.env`.
  - Integration tests load keys from the environment exactly as they do today.
  - Test values are made up (`sk-test-123`).
- **`shellcheck`** isn't installed on this machine, so acceptance uses `bash -n`. Write the scripts as if shellcheck will run: quote expansions, no `eval`, no unchecked `cd`.
- **ERPNext lock:** the integration tests read and write the shared ERPNext. Take `tmp/erpnext.lock` (the orchestrator does this). Don't reset ERPNext.
- No new dependencies.

## Subtasks

- [ ] **`Query` validation (N1):**
  - `Fields` entries match `^[A-Za-z_][A-Za-z0-9_]*$`, optionally prefixed with `` `tab<DocType>`. `` (DocType: letters, digits and spaces).
  - Allow aggregates only if a current caller uses one; `grep` the callers and list what you found in the report.
  - `OrderBy` is one or more comma-separated `<field> asc|desc` (case-insensitive), with `<field>` under the same rule.
  - A violation returns an error wrapping `ErrUnsafeQuery` **before** any request is sent.
  - `Filters` field names follow the same rule.
- [ ] **`Call` (N5):** refuse GET on `frappe.client.*` methods except `get`, `get_list`, `get_count` and `get_value`. Never retry a non-idempotent method (POST, PUT, DELETE).
- [ ] **Pagination (N3):**
  - Also stop when a page's first row `name` equals the previous page's.
  - Add `Options.MaxRows` (default 200,000), with an error when it's exceeded.
  - Fix the error text that blames "ignoring limit_start".
- [ ] **`IsNotFound` (N4):** a 404 counts as not-found only with `exc_type` `DoesNotExistError`. Do the audit above.
- [ ] **Deadline (N6):**
  - When the caller's context has no deadline, the client applies `Options.Deadline` (default 60 s) across all retries and Retry-After waits.
  - A Retry-After longer than the remaining time fails fast.
  - Document this on `New`.
- [ ] **Secret (N9):** the `New` signature change above, plus a test that formats a `*Client` and a `Client` held in an unexported struct field with `%v %+v %#v %p` and through slog text and JSON. No secret may appear.
- [ ] **Probe (finding 7, finding 8):**
  - Switch to `internal/frappe` if practical. Otherwise set `CheckRedirect` to refuse redirects to another scheme, host or port.
  - `isRefused` requires a 403 with `exc_type` `PermissionError`.
  - Run check (d), the System Settings PUT, only when check (c) was refused.
  - Tests for each.
- [ ] **Setup script (finding 10, finding 9):**
  - `api-users.sh` and `lib.sh` refuse to run under xtrace: `case $- in *x*) echo "refusing to run with xtrace" >&2; exit 1;; esac`.
  - `ERP_BASE_URL` must match `^https?://[A-Za-z0-9.-]+(:[0-9]+)?$` before anything is written.
  - Stop advising that `ERP_SEED_*` lines be appended to `.env`; seed keys go only to `tmp/erp-keys.env`.
  - `.env.example` drops `ERP_SEED_API_KEY` and `ERP_SEED_API_SECRET` and adds a comment saying they live in `tmp/erp-keys.env`. `config.FromEnv` still reads them, so make no change there.
  - In the README, change the example from `env $(... | xargs)` to `set -a; . tmp/erp-keys.env; set +a`.
- [ ] **Tests:**
  - `TestQueryRejects` covers each injection shape: `name; drop`, `name)`, `sleep(5)`, `` name` ``, `name desc, (select 1)`, `name asc limit 1`, an empty field, and a filter field `x or 1=1`. It also shows that valid queries from current callers still pass.
  - Tests for the `Call` method allowlist and the no-retry rule.
  - Pagination: a repeated first row, and `MaxRows`.
  - `IsNotFound`: a 404 with and without `DoesNotExistError`.
  - Deadline: a fake server that delays, with a context that has no deadline, fails within `Options.Deadline` plus a small margin.
  - The Secret formatting test above.

## Acceptance (human-readable)

- Every injection shape is rejected before a request is sent, and every current caller still works, with and without the integration tag.
- No call can run longer than its deadline, and no write method is retried.
- No secret appears in any formatting of the client or the probe client, and seed keys are no longer suggested for `.env`.
- G6 owner check: the README change, and the default `Deadline` and `MaxRows`.

## Out of scope

- Allowlists at the MCP tool boundary (CC-502 adds them; this is the second line of defence).
- `config` changes, including the URL-credential rejection from the CC-104 review (separate follow-up).
