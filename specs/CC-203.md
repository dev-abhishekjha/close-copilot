# CC-203 · Typed models and the money package

## Goal

Go structs for every DocType the project uses, with rupee amounts converted to exact paise at the boundary. `internal/money` owns all conversion and formatting.

## Context

- Ticket: `docs/implementation-tickets.md`, section `CC-203`. Shared spec "Money, dates and IDs": money is `money.Paise` (`int64`), display uses Indian grouping (₹1,23,456.78), and dates are `YYYY-MM-DD` at the edges and `time.Time` at UTC midnight inside.
- Field names come from `docs/erpnext-schema/*.json` (real dumps of this site), and `docs/erpnext-schema/README.md` lists which fields the project relies on. Use exactly those names in JSON tags.
- `internal/frappe` (CC-202) decodes with `UseNumber()`, so raw amounts arrive as `json.Number`. `List[T]` and `Get[T]` decode into whatever struct you give them.
- **No floats anywhere in this ticket**, in `internal/money` or `internal/frappe/models.go`/`convert.go`. Parse the number's text. (CC-002's `nofloat` doesn't cover these two packages, but CLAUDE.md requires exact money everywhere.)
- No new dependencies.

## Subtasks

- [ ] **`internal/money`:**
  - `type Paise int64`.
  - `ParseRupees(s string) (Paise, error)`:
    - accepts an optional leading `-` and digit grouping commas (Indian `1,23,456.78` or western `123,456.78`);
    - takes any number of decimals, rounding to paise **half away from zero** (`"0.005"` → 1, `"-0.005"` → -1, `"0.004"` → 0);
    - rejects empty input, letters, two dots, a misplaced sign, a lone comma, and overflow beyond `int64` paise.
  - `FromJSONNumber(n json.Number) (Paise, error)`:
    - parses the number's text, including exponent forms Frappe can emit from Python floats (`1e-05`, `1.18E+3`, `-2.5e2`);
    - is exact and has no float; it uses the same rounding rule;
    - an empty number is an error.
  - `(Paise) Rupees() string`: plain two-decimal rupees with no grouping, e.g. `"1180.00"`, `"-0.05"`.
  - `(Paise) Format() string`: `₹` with Indian grouping (last three digits, then pairs). `Format(12345678)` returns `"₹1,23,456.78"`; negatives are `"-₹1,23,456.78"`; zero is `"₹0.00"`.
  - Everything works for `math.MinInt64` without overflow, or returns or prints a defined result; test it.
- [ ] **`internal/frappe/models.go`:**
  - **Raw structs** mirror ERPNext JSON exactly: `json` tags as the schema dumps name them, amounts as `json.Number`, dates as `string`.
  - **Domain structs** use `money.Paise` and `time.Time` (UTC midnight for dates).
  - Types: `GLEntry`, `Account` (with `RootType`, `IsGroup`, `ParentAccount`, `AccountType`, `Company`), `Supplier`, `Customer`, `PurchaseInvoice` with `Items` and `Taxes`, `SalesInvoice` (with items and taxes if the README lists them), `PaymentEntry` with `References`, and `JournalEntry` with `Accounts`.
  - Include every field the README marks as relied upon, plus `name`, `docstatus` and `company` where they exist.
  - Naming: e.g. `GLEntryRaw` / `GLEntry`; keep it consistent.
  - Purchase Invoice Item is not in the dumps. Use the fields the README notes as checked live: `item_code`, `description`, `expense_account`, `amount`.
- [ ] **`internal/frappe/convert.go`:**
  - One converter per type, `func (r XRaw) Domain() (X, error)` or a free function; pick one style.
  - Converters wrap errors with the field name and the document name, e.g. `GL Entry ACC-GLE-…: debit: …`.
  - Child tables convert too.
  - An empty date stays the zero `time.Time` only where the field is optional in ERPNext; otherwise it's an error.
- [ ] **Tests:**
  - `internal/money`, table-driven:
    - `"0.005"` rounding;
    - negative amounts;
    - `"1,180.00"` with a comma;
    - values over ₹1 crore (e.g. `"12,34,56,789.01"`);
    - Indian grouping of `1234567.8` → `"₹12,34,567.80"`;
    - exponent forms;
    - overflow;
    - every rejection case;
    - a round trip, where `ParseRupees(p.Rupees()) == p` for a spread of values including `MinInt64+1` and `MaxInt64`.
  - `TestModelsDecode`: decode recorded or hand-built JSON (in `internal/frappe/testdata/models/`) shaped like the real list and get responses, including child tables, into the raw structs. Unknown extra fields are ignored.
  - `TestConvert`: raw → domain for every type, including an amount like `"1180.5"`, a `json.Number("1e-05")`, a bad date and a bad amount (each error names the field and the document).
- [ ] **Integration test** (`//go:build integration`, `models_integration_test.go`):
  - Skip unless `ERP_BASE_URL`, `ERP_SITE`, `ERP_API_KEY` and `ERP_API_SECRET` are set.
  - With the bot key, `List[AccountRaw]` all accounts of Sharma Traders Pvt Ltd with the fields the struct names, and convert every one. Fail if any conversion fails, or if any `root_type` is outside Asset, Liability, Equity, Income, Expense.
  - **Read only. Nothing is written to ERPNext.** The books are empty, so this test covers Accounts only.

## Acceptance (human-readable)

- `go vet` and the tests pass, and `go run ./gates/cmd/lint ./...` reports nothing.
- `Format(12345678)` returns `"₹1,23,456.78"`.
- The real site's accounts decode and convert with these structs.

## Out of scope

- Trial balance and account history (CC-204), and any report logic.
- Changing `List`/`Get` or anything else in CC-202's files.

## Notes

- Rounding half away from zero matches the shared spec's `math.Round` rule for ERPNext amounts. Document it on `ParseRupees`.
