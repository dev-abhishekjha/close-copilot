# CC-601 · Finding model, readers and check runner

## Goal

The `Finding` type from the shared specs, a `Check` interface, reader interfaces for books and evidence data, and a runner that executes checks in parallel and stores their findings.

## Context

- Ticket: `docs/implementation-tickets.md`, section `CC-601`.
- Shared specs: Finding, EvidenceRef, Citation, Postgres schema (`findings`), and check inputs.
- Plan row: Phase 1, implementer, standard risk, gates G1–G3.
- In E6 deterministic checks read data through two small interfaces, `BooksReader` and `EvidenceReader`. Direct implementations `DirectBooks` and `DirectEvidence` are backed by `internal/frappe` and `internal/store`. In E7 MCP-backed readers implement the same interfaces so the checks never change. Unit tests use in-memory fakes.
- Checks execute in parallel under an `errgroup` bounded to at most 4 concurrent checks.
- Duplicate findings collapse into one by type and keys.
- Findings are persisted in the store in a single transaction with the close run ID.

## Subtasks

- [ ] **`internal/checks/finding.go`:**
  - `Finding`, `EvidenceRef`, `Citation` types aligned with the shared specs and `internal/store`.
  - Constants for finding types, severity (`high`, `medium`, `low`), action, and status (`open`, `needs_review`, `accepted`, `dismissed`).
  - Helper functions for constructing `EvidenceRef` and computing deterministic deduplication keys.
- [ ] **`internal/checks/readers.go`:**
  - `BooksReader` interface: `TrialBalance`, `GLEntries`, `PurchaseInvoices`, `SalesInvoices`, `PaymentEntries`, `AccountHistory`, `RecurringSuppliers`.
  - `EvidenceReader` interface: `BankLines`, `GSTR2BEntries`.
  - `RecurringSupplier` model.
  - `DirectBooks` implementation wrapping `*frappe.Client`.
  - `DirectEvidence` implementation wrapping the store.
- [ ] **`internal/checks/runner.go`:**
  - `Check` interface with `Name() string` and `Run(ctx context.Context, in Inputs) ([]Finding, error)`.
  - `Inputs` struct carrying `Company`, `Month`, `Books`, `Evidence`, and `Rules`.
  - `Runner` executing checks in parallel with an `errgroup` limit of 4.
  - Deduplicate findings by type plus keys.
  - Set run ID and ensure unique finding IDs.
  - Persist findings in a single transaction.
- [ ] **Tests (`internal/checks/*_test.go`):**
  - Parallel execution of fake checks with concurrency limit.
  - Error propagation on check failure.
  - Deduplication of findings with identical type and keys.
  - Setting run ID and persisting to store in one transaction.
  - Direct readers and fake readers validation.

## Acceptance (human-readable)

- Fake checks run in parallel under `Runner.Run`.
- Duplicate findings collapse into one.
- Findings are stored with the run ID in a single transaction.
- All unit tests pass with race detection enabled.
- `make check` passes cleanly.

## Out of scope

- Specific check implementations (CC-602 through CC-607, CC-1103).
- MCP-backed readers (CC-502, CC-503, E7).
