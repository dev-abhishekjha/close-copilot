# CC-004 · Harden the merge gates, CI and guard hook

## Goal

A pull request can't weaken the gates that judge it, an approval covers exactly the commit that was reviewed, and the guard hook can't be walked out of with `..`.

## Context

- Ticket text: `tasks/hardening.md`, section `CC-004` (findings 1–7 from the CC-001 and CC-202 G5 reviews). Read it first; this spec records the decisions taken since.
- **Approval:** every file here is protected. The owner delegated approval for the build phase on 2026-10-10 (`docs/orchestrated-implementation-plan.md`, "Build-phase operating mode").
- **Finding 6, decided:**
  - Add `.golangci.yml` to `gates.ProtectedPaths` and to `.github/CODEOWNERS`; weakening the linters is weakening a gate. The orchestrator updates the list in `CLAUDE.md` after merge.
  - `tasks/graph.yaml` and `specs/` stay unprotected during the build phase, because the orchestrator edits them on every ticket. The spec-pin rule (subtask 4) still stops a branch from changing its own spec's binding fields.
- **The guard hook changed on 2026-10-10.** It now resolves `root` as the git checkout that holds the edited file (`git -C <dir> rev-parse --show-toplevel`), so each worktree under `.worktrees/` enforces its own `tmp/current-task`.
  - **Keep that behaviour.** Your changes go on top of it: normalise `..`, allow paths outside every checkout, and stop a leading `*` matching across `/`.
  - The hook that actually runs is always the main checkout's copy (`${CLAUDE_PROJECT_DIR}/.claude/hooks/guard-edit.sh`), so editing it in a worktree doesn't change enforcement until merge.
- **CI:** there's no GitHub Actions run to test against locally, and `actionlint` isn't installed. Verify the workflow with a Go test (`TestCIWorkflow`) that parses `.github/workflows/ci.yml` with `go.yaml.in/yaml/v3` (already a dependency) and asserts its structure.
- Tests use `t.TempDir()` git repos (see the existing `gates/*_test.go` helpers). No network.
- No new dependencies. For NFKC folding, `golang.org/x/text` is already indirect in `go.mod`. If you'd have to make it direct, choose the "reject non-ASCII paths" option instead.

## Subtasks

- [ ] **Base-ref gates (finding 1):**
  - In `ci.yml`, check out the PR base ref into a separate directory (`actions/checkout` with `ref: ${{ github.event.pull_request.base.sha }}` and `path: base`).
  - Build `gates/cmd/*` there (`go build -o "$RUNNER_TEMP/gates/" ./gates/cmd/...` with `working-directory: base`).
  - Run those binaries against the PR tree.
  - No step may `go run ./gates/cmd/...` from the PR checkout.
  - `TestCIWorkflow` asserts all of this.
- [ ] **SHA-pinned approval (finding 2):**
  - When the `approved` label is applied, record the PR head SHA (from the `labeled` event payload, e.g. as a step output or a commit status).
  - `gates/cmd/protected` gets a flag `--approved-sha <sha>` (empty means not approved).
  - It fails when protected paths changed and the head differs from the approved SHA, or no SHA was given.
  - A unit test covers: approved at the head (pass), a commit pushed after approval (fail), and no approval (fail).
- [ ] **Unicode-safe matching (finding 3):**
  - Reject any changed path that isn't printable ASCII (a `protected` problem naming the path), or NFKC plus casefold it before matching.
  - Tests: `docſ/x`, full-width `ｄｏｃｓ/x`, `DOCS/x`, `Gates/x.go` and `.CLAUDE/x` are all caught.
- [ ] **Spec pinning (finding 4):**
  - `PinnedSpec` reads the spec from the branch's first commit whose subject is `<ID>: spec` when `main` doesn't have it, not from the branch tip.
  - `SpecPinProblems` compares every front-matter field (id, title, phase, owner_role, risk, approved_by, depends_on, needs_erpnext, files, consumes, produces, acceptance, gates, budget) and reports each changed field.
  - Tests for: a spec on main; a spec only on the branch, edited after its spec commit; and an unchanged spec.
- [ ] **CI concurrency (finding 5):**
  - Label events must not cancel or skip `check` or `integration`.
  - Either give `protected` its own workflow file triggered on `labeled`/`unlabeled`/`synchronize`, with its own concurrency group, or give label events a separate concurrency group, so `check` always runs on `pull_request` `opened`/`synchronize`/`reopened`.
  - `TestCIWorkflow` asserts it.
- [ ] **Finding 6:** add `.golangci.yml` to `ProtectedPaths` and `.github/CODEOWNERS`. Update any gates test that enumerates the list.
- [ ] **Guard hook (finding 7):**
  - Normalise the edited path: resolve `.` and `..` lexically, without requiring the file to exist.
  - Exit 0 for paths outside the resolved checkout root, e.g. memory files under `~/.claude`.
  - Apply role and declared-file checks only to paths inside it.
  - A spec glob's `*` must not match `/` (only `**` does). Keep the current `glob/*` directory-prefix behaviour for `dir/**`.
- [ ] **`TestGuardHook`** (in `gates/hook_test.go`): exec `bash .claude/hooks/guard-edit.sh <role>` with JSON on stdin and `CLAUDE_PROJECT_DIR` set, in a temp git repo, and in a `git worktree` of it with its own `tmp/current-task`. Cases:
  - `tmp/../../x` is blocked while a task is active;
  - a path outside the root is allowed;
  - each role's forbidden paths are blocked in both the main checkout and the worktree;
  - a declared file is allowed and an undeclared one blocked;
  - a worktree's task never affects the main checkout;
  - a `*.go` glob doesn't match `a/b.go`;
  - `security-reviewer` is blocked everywhere inside the root.
