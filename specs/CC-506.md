# CC-506 · Run-scoped tool binding

## Goal

A run can read only its own company and month, and the MCP servers enforce that, not the agent.

## Context

- Ticket: `docs/implementation-tickets.md`, section `CC-506`. Plan row: phase 2, INT builds and the owner reviews, regulated, gate-run check "Out-of-scope arguments return a tool error; contract test". The plan lists this as one of the three parts an interviewer will probe hardest, so favour small, readable code and tests that read as a threat model.
- Why: `MCP_TOKEN_AGENT` alone reads any company. A steered investigator (CC-706) or an injected tool argument must not be able to read another tenant or another month. G5 invariant: "a tool call with another company's name or another month returns a tool error".
- Quoted from the ticket:
  - `Scope{RunID, Company, From, To, Exp}`; `Mint(key, scope)`; `Verify(key, header)`; the header is `X-Run-Scope`.
  - Header format: `base64url(json) + "." + base64url(HMAC-SHA256(MCP_SCOPE_KEY, json))`.
  - **Owner decision 2026-10-11 (deviation from the ticket):** `To` is the last day of the month **after** the run's month, because the registered GSTR-2B check reads purchase invoices and GSTR-2B entries up to the end of the next month (`internal/checks/gstr2b.go:135-141`). `From` reaches back 12 months so `get_account_history` and `list_recurring_suppliers` still work.
  - `Exp` is unix seconds: `deadline.Add(time.Minute).Unix()`.
  - On `/mcp`, a missing, expired or tampered scope gets **401**. A handler refusing an argument returns a **tool error** (not a 401) so the model sees why.
  - `Scope.Allows(company, from, to string) error` returns `out_of_scope: ...` for a company mismatch or `from < s.From || to > s.To`.
  - `cmd/agent mint-scope --company sharma --month 2026-09` prints a header value for manual Inspector sessions.
  - Acceptance: every tool returns an `out_of_scope` tool error for another company or a date outside the window, and **makes no ERPNext or Postgres call**.
- **`Scope.Company` is the company ID** (`sharma`), not the ERPNext name. The ticket's struct comment says "ERPNext company name"; CC-502 decided that every tool takes the ID, and that wins.
- **Window rule:** for run month `YYYY-MM`, `To` is the last day of the **following** month and `From` is the first day of the month 12 months before the run month (`2026-09` gives `2025-09-01` to `2026-10-31`; `2026-12` gives `2025-12-01` to `2027-01-31`). Dates are `YYYY-MM-DD` strings, so string comparison is correct once arguments are parsed and re-formatted.
- Tool arguments to bind (from CC-502's catalog; all books tools take `company`):

  | Tool | Range the scope check sees |
  | --- | --- |
  | `get_trial_balance`, `list_gl_entries`, `list_purchase_invoices`, `list_sales_invoices`, `list_payments` | `from_date`..`to_date` |
  | `get_account_history` | first day of `through_month` minus (`months`-1) months, to the last day of `through_month`. An empty `through_month` currently defaults to `h.now()`; make it default to the **scope's month** when a scope is present |
  | `list_recurring_suppliers` | `books.RecurringWindow(before_month, lookback_months)` |
  | `list_bank_lines` (evidence) | `from_date`..`to_date` |
  | `list_gstr2b_entries` (evidence) | `period` as the first to the last day of that month |

- From `tasks/hardening.md` (assigned to this ticket):
  - **(CC-502 review)** Bind `company` and every date and month argument of all seven books tools server-side, including `before_month` and `through_month`.
  - **(CC-704 G5)** `store.SetFindingExplanation` updates `WHERE id = $1` only. Add run and company predicates (join `close_runs`), return `ErrNotFound` on a mismatch, and add a cross-run integration test.
- Error format: books maps any non-input error to a fixed "unavailable" message (`toModelError`, `internal/books/tools_errors.go:66`), so the scope error needs its own pass-through, like `inputError`. The message names the rule and the run's own window, never the other company's data. Cap any echoed argument at 40 characters (`%.40q`, the style in `internal/agent/workflow.go`).

## Subtasks

- [ ] **`internal/mcpkit/scope.go`** (all with unit tests in `scope_test.go`):
  - `Scope` as quoted, with JSON tags `run_id`, `company`, `from`, `to`, `exp`.
  - `Mint(key []byte, s Scope) (string, error)` and `Verify(key []byte, header string, now time.Time) (Scope, error)`. The key is `[]byte`; callers convert `cfg.MCPScopeKey.Reveal()` at the point of use only. Verify rejects, each with its own subtest of `TestVerifyRejects`: empty key, empty header, no dot, bad base64, bad JSON, unknown fields, wrong MAC (constant-time compare, `hmac.Equal`), expired (`now` is a parameter, never `time.Now()` inside), empty `RunID` or `Company`, unparseable `From`/`To`. A payload tampered after minting fails (flip one byte in the JSON). Verify does **not** require `From <= To`: a scope with `From > To` is valid but `Allows` refuses everything for it (this is what the discovery scope relies on).
  - `(Scope).Allows(company, from, to string) error` as quoted, wrapping a sentinel `ErrOutOfScope` (`errors.Is`) so books and evidence can pass it through; the text starts `out_of_scope:`. When `s.From > s.To`, `Allows` refuses every call.
  - `Window(company, runID string, month string, exp time.Time) (Scope, error)` builds the window above from `YYYY-MM`; test a December month (`To` falls in the next year) and a leap day (`2028-01` gives `To` 2028-02-29).
  - `DiscoveryScope(now time.Time) Scope`: `RunID: "discovery"`, `Company: "-discovery-"`, `From: "2000-01-02"`, `To: "2000-01-01"`, `Exp: now + 1 minute`. The agent transport calls it (see the agent-side subtask). `TestDiscoveryScope` (in `scope_test.go`): it passes `Verify`; `Allows` refuses every call, including the edge call `from=2000-01-02, to=2000-01-01` and any real company.
  - `Scoper` also exposes the company check and the date check separately (`CheckCompany(req, company)`, `CheckRange(req, company, from, to)`) so the books handlers can run the company check before `h.company`.
  - `Scoper`: holds the key and a clock. `NewScoper(key string) (*Scoper, error)` fails on an empty key. `(*Scoper).Check(req *mcp.CallToolRequest, company, from, to string) error` verifies `req.Extra.Header["X-Run-Scope"]` and calls `Allows`; a missing or bad header returns an `out_of_scope` error too (the handler is the second line of defence behind the HTTP layer). **A nil `*Scoper` means unscoped and returns nil**: stdio and in-process tests. A non-nil `*Scoper` with a nil `req.Extra` (in-process or stdio call) returns `out_of_scope`; add a subtest for it. `Verify` rejects a header longer than 2 KiB before decoding it (a subtest of `TestVerifyRejects`). Also expose the verified scope: `(*Scoper).Scope(req) (Scope, bool)`, and `RunID(req) (string, bool)` built on it. Books' `get_account_history` uses `Scope` to default an empty `through_month` to the run month (the month before `To`'s month); a handler must not re-parse the header itself.

## Acceptance (human-readable)

- Every books and evidence tool refuses another company and any date outside the run's 14-month window with an `out_of_scope` tool error, before any ERPNext call and before any data is read from Postgres. (When audit is enabled a refused call still writes its own `audit_log` row, which is intended.)
- Over HTTP, `/mcp` answers 401 without a good `X-Run-Scope`; `/mcp-admin` behaves as before.
- Two runs sharing one registry cannot read each other's data.
- `mint-scope` output works in an Inspector session (manual owner check; the automated proxy is `TestMintScopeVerifies`).
- The audit log records `agent:run/<RunID>` as the actor for scoped `/mcp` calls.
- A cross-run `SetFindingExplanation` is refused.
- The owner can read `scope.go` and its tests in one sitting and explain the threat model.
