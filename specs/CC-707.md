# CC-707 · Ask the books

## Goal

An `Asker` in package `agent` answers a free-form question about one company-month with the same bounded tool loop and citations as the investigator: router first, then number-gathering, then a retrieval plus single forced `emit_answer` call, then the code verifier.

## Context

- Ticket: `docs/implementation-tickets.md`, section `CC-707` (don't open it; quoted here). Plan row: Phase 3, llm-engineer, data-sensitive, 1.5 h, stretch, **promoted** to core because CC-708 shipped. Check: "Answers pass the verifier; citation precision at or above threshold".
- Ticket text: "`POST /api/ask` answers free-form questions about a company-month with the same bounded loop and citations. Questions pass the CC-708 router first. To keep retrieved text away from tool calls, answer in two stages: the investigator loop gathers numbers with read tools and no document text, then the workflow retrieves passages and a single forced `emit_answer` call, with no other tool, writes the answer from both." Subtasks: reuse the investigator loop with an `emit_answer` tool (`answer`, `citations[]`, `evidence_ids[]`) and the same limits and verifier; three canned demo questions, such as "Why did Software Subscriptions jump in September?". Acceptance: "The demo questions get verified answers with evidence links". Files: `internal/agent/ask.go`.
- HTTP shape (shared spec): `POST /api/ask`, role viewer, "Question in, answer with citations out; the CC-708 router screens it first". **The HTTP handler and route are not in this ticket** (the file list has no `internal/web`); deliver the Go API the handler will call, and record the wiring as a follow-up in the PR summary.
- Invariants that bind this ticket (CLAUDE.md): `internal/agent` never imports `internal/frappe`; retrieved document text never reaches a model that can call tools; the investigator has no `search_documents` and no admin tool; every MCP call is scoped to the run's company and month (CC-506); GSTINs, PANs and person names are pseudonymised before any model call (CC-710); every answer can be rebuilt from stored artifacts (CC-709). No new env var. Models: `LLM_MODEL_STRONG` for the loop and the answer, `LLM_MODEL_FAST` only inside `Triage`.

## Subtasks

- [ ] `prompts/ask.txt` and `prompts.Ask` (embed in `prompts/embed.go`): static system prompt for the answer call; passages fenced as data; the model may cite only passages it was given and quote only amounts present in the gathered evidence.
- [ ] `Asker` and `NewAsker(...)` with a required `Triage`, `ToolExecutor`, `Retriever`, `AskStore` (interface: `Begin`, `Finish`, `PutArtifact`, `GetArtifact`, plus `CitationExists`, with `var _ AskStore = (*store.Store)(nil)`), recorder, `NewRedactor` closure and models; `Ask(ctx, AskRequest{RunID, Question, Company, Month}) (AskResult, error)` where `AskResult{Action string, Refusal string, Answer string, Citations []store.Citation, EvidenceIDs []string, Verified bool, Violations []Violation, StepRefs []string}`. A `refuse` or `clarify` decision returns `Refusal` (from `Triage.Refusal` or `ClarifyText`) and calls nothing else.
- [ ] Stage 1, number gathering: the investigator-style loop with the read tools only, no document text, same limits as the investigator (calls, duration, tokens), scoped to the run's company and month; its output is the set of recorded `tool_result` artifacts (the evidence) and the evidence IDs it saw.
- [ ] Stage 2, answer: the Asker (not the model) calls the `Retriever` after stage 1 ends, builds the message from the question (fenced), the stage-1 evidence view and the retrieved passages (fenced), and makes one call with `ForceTool = "emit_answer"` and **no other tool**. `emit_answer` input: `answer` (string, non-empty, capped), `citations[]` (`doc_id`, `section`), `evidence_ids[]`. One corrective retry on a malformed answer, then fail the step.
- [ ] Verify with `verifyAnswer`: every amount in `answer` is grounded in the stage-1 evidence; every citation names a retrieved passage and exists in `doc_chunks` for the company; every `evidence_ids` entry was seen in stage 1; scope matches. A failing answer is not returned as verified: set `Verified=false` with the violations (one re-answer attempt with the violations as feedback is allowed; then return `Verified=false` and a fixed text, never the unverified answer).
- [ ] Record every stage as a step with artifacts so an answer can be rebuilt (CC-709): router, investigate, retrieve, explain, verify, synthesize; resume skips steps already `done`.
- [ ] `DemoQuestions`: three canned demo questions as an exported slice, with one for a Software Subscriptions jump (use the question in the ticket), one on bank charges and one about the month's GST position or a document-backed policy (e.g. a retention or approval rule in the corpus). Check `internal/agent/testdata` and `seed` output for what `suite-skeleton` really supports before fixing the other two.
- [ ] Tests (names are binding): `TestAskDemoQuestions` (each demo question, fake provider scripted, yields a verified answer with at least one citation and one evidence ID); `TestAskRefusedMakesNoCalls` (a refused and a clarify question make zero tool or retrieval calls and the run's `run_steps` hold only the `router` step); `TestAskTwoStageIsolation` (during stage 1 the model is offered no document text and no `search_documents`; during stage 2 the only offered tool is `emit_answer`, and the retrieval call happens after the last stage-1 `Execute`); `TestAskVerifier` (an ungrounded amount, a citation to a passage that was not retrieved and an unseen evidence ID each fail); `TestAskRedaction` (as `TestTriageRedaction`: the question carries the tenant's own GSTIN and a person name, the fake base provider's calls and stored prompt artifacts hold no raw value, for the loop and the answer call); `TestAskRouterErrorFailsClosed` (a store or router error and an over-length question answer nothing); `TestAskLimits` (the ninth tool call, the token cap and the time cap each end the loop as the investigator does, then stage 2 still runs or the question fails closed, stated in Notes).

## Acceptance (human-readable)

- The three demo questions get verified answers, each with evidence IDs and at least one citation, under a fake provider; no test in this ticket calls a real model.
- Refused requests make no tool or retrieval call, asserted from `run_steps`.
- Stage 2 has exactly one tool, `emit_answer`, and document text never appears in a request that offers a read tool.
- `TestInvestigat*` still pass unchanged after the loop extraction.
- Citation precision at or above the threshold is measured by a later scorer (not this ticket); this ticket's tests prove every returned citation was retrieved and exists.
