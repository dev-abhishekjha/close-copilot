# CC-904 · OpenTelemetry tracing into Langfuse

## Goal

One trace per close run covering every check, LLM call and MCP tool call across the agent and both MCP servers, with tokens and cost on the LLM spans, and no prompt text or personal data in attributes.

## Context

- Ticket: `docs/implementation-tickets.md`, section `CC-904` (quoted below; do not open `docs/`).
- Quoted: use the OpenTelemetry Go SDK with the OTLP/HTTP exporter pointed at Langfuse; name attributes after the GenAI semantic conventions. MCP over Streamable HTTP is ordinary HTTP, so wrapping the client transport and the server handler with `otelhttp` carries the trace across services through standard `traceparent` headers. Subtasks: `telemetry.Setup(ctx, serviceName)` with `otlptracehttp` reading the standard `OTEL_EXPORTER_OTLP_*` variables, flushed on shutdown; spans `close_run` (root), `check.<name>`, `explain`, `verify`, `investigate`, `gen_ai.chat` (attributes `gen_ai.request.model`, `gen_ai.usage.input_tokens`, `gen_ai.usage.output_tokens`, plus cost), `mcp.tools/call <tool>` (attributes `gen_ai.tool.name`, `mcp.method.name`); `otelhttp.NewTransport` on the MCP and ERPNext HTTP clients and `otelhttp.NewHandler` around the MCP servers; store the trace ID on `close_runs` and show a link in the run report; never put PII or full prompts in attributes on shared backends, and log prompt text only when `TRACE_PROMPTS=true` locally.
- Plan correction (plan row 6, "Changed"): prompts and responses are kept in Postgres (CC-709) so an answer can be rebuilt for audit; the trace backend never needs them. So there is no reason to send prompt text at all by default.
- Invariants (G5): secrets only from env; `OTEL_EXPORTER_OTLP_HEADERS` is a `config.Secret` (carries the Langfuse auth) and must never reach a log, span attribute, error or report; GSTINs, PANs and person names are never attributes; the `httpx` egress guard stays the outermost wrapper so tracing cannot widen the allowlist (`OTEL_EXPORTER_OTLP_ENDPOINT` is already on it).
- Already present: `go.opentelemetry.io/otel`, `sdk`, `trace`, `otlptracehttp` and `otelhttp` are in `go.mod`; `close_runs.trace_id` exists (migrations/0002_runs.sql) and `store.CloseRun.TraceID *string` is read and written by `UpdateCloseRun`; `.env.example` already lists both OTLP variables. No new dependency or migration is expected; if one is, report it.
- Depends on CC-608 only because both edit `internal/agent/workflow.go`; build after it merges, on top of its `DefaultChecks`.
- Telemetry must be optional: with no `OTEL_EXPORTER_OTLP_ENDPOINT`, `Setup` installs a no-op tracer, returns a no-op shutdown, and nothing else changes behaviour. Tests never contact a real collector: use an in-memory span exporter and `httptest`.

## Subtasks

- [ ] `telemetry.Setup(ctx, serviceName string, cfg config.Config) (shutdown func(context.Context) error, err error)`: OTLP/HTTP exporter from the config's endpoint and headers, resource `service.name`, batch processor, W3C trace-context propagator set globally; no-op when no endpoint.
- [ ] `WrapTransport(http.RoundTripper)` and `WrapHandler(http.Handler)` over `otelhttp`; use them in `httpx` (inside the egress guard) and `mcpkit.BuildHandler`.
- [ ] `telemetry.Provider(llm.Provider) llm.Provider`: `gen_ai.chat` span with `gen_ai.request.model`, `gen_ai.usage.input_tokens`, `gen_ai.usage.output_tokens` and a cost attribute (`gen_ai.usage.cost_usd`); never the messages. Wrap it in `cmd/agent/main.go`.
- [ ] Workflow spans: `close_run` root in `RunClose` and `ResumeClose` (a resumed run is a new trace; record the new ID), `check.<name>`, `explain`, `verify`, and an `investigate` span name reserved for CC-706 (declare the constant, do not emit it). MCP spans `mcp.tools/call <tool>` with `gen_ai.tool.name` and `mcp.method.name`, created on the server side where the tool call is handled, so the trace shows both servers.
- [ ] Save the trace ID with `UpdateCloseRun` and show it in the report as a link built from an env-configured base (add a `LANGFUSE_URL`-style variable to `.env.example` only if a link needs one; otherwise print the bare trace ID).
- [ ] `TRACE_PROMPTS=true` (default false) is the only way prompt text appears, and then only as a span event, never an attribute. Document it in `.env.example`.
- [ ] Tests: one trace across agent client and an `httptest` MCP server shares a trace ID through `traceparent`; every span name above appears for a fake close; no attribute value contains a GSTIN, PAN, the OTLP header secret or a prompt string with `TRACE_PROMPTS` unset; setup with no endpoint is a no-op; the egress guard still refuses a host that is not allowlisted with tracing on.

## Acceptance (human-readable)

- In Langfuse one trace shows the run, its checks, every LLM call with token counts and MCP spans from both servers under the same trace. This needs the owner's Langfuse keys and a live run, so it is a manual check after the merge.
- The scan test proves no secret, identifier or prompt text reaches an attribute.

## Out of scope

- The investigator's spans (CC-706), the web app's request spans (CC-1001) and metrics.
- Changing the egress allowlist, `config.Secret` handling or migrations.

## Notes

- `G4-tier2` is listed because `internal/agent` and `internal/llm` change, but tracing alters no model behaviour: run it against recorded fixtures, with no live model call.
- Wrapping order matters: tracing wraps the transport the guard wraps, so the allowlist is checked before any request leaves. Test it.
- Reports hold no timings today (report.go); a trace ID differs per run, so check the report determinism test and keep the ID out of the stored report artifact if it breaks it, printing it only in the CLI output.
