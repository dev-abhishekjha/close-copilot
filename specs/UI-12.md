# UI-12 · System status page and health indicator

## Goal

A read-only page that shows whether Postgres, ERPNext, the model provider and today's model budget are in order, plus a small health dot in the top bar on every page, without ever showing a secret.

## Context

- Ticket: `tasks/frontend-plan.md` section 6 row UI-12 (S): "System status page and top-bar health dot: Postgres, ERPNext, model provider, daily budget used. Read-only; no secrets shown." Check: "Postgres, ERPNext, model provider and budget shown; no secrets" (`tasks/graph.yaml`).
- **`internal/web` imports neither `internal/frappe` nor `internal/agent`** (frontend plan section 7). New data comes through a backend interface the web package defines and `cmd/agent` fills, like `AskBackend` and `AuditStore`.
- Route hook: `systemRoutes()` in `routes_system.go` returns nil today. Fill it; do not edit `routes.go`. The nav entry `{"Reference", "System", "server", "/system"}` already exists in `navTable` and shows once the route does. `shell_test.go` lines ~168 to 188 list `/system` as an unrouted page: update those expectations (the only allowed edit there, plus the health dot test below). `routes_hooks_test.go` maps `systemRoutes` to `routes_system.go`; keep it passing.
- Roles: `GET /system` is `anyRole`. The page shows fixed status words and numbers only.
- When `Options.System == nil` the route answers 501 after the role check, with the friendly `EmptyState` page used by the other pages (see `auditRoute`, `askHTML`).

## Design

```go
// SystemBackend is what the status page reads. Every method must return within the context deadline.
type SystemBackend interface {
    Postgres(ctx context.Context) error                 // store.Ping
    ERPNext(ctx context.Context) error                  // unauthenticated reachability of ERP_BASE_URL
    SpendToday(ctx context.Context) (SpendToday, error) // model cost for the UTC day
}
type SystemInfo struct {            // static facts, set at wiring time
    Provider     string  // "claude-cli" or "anthropic" (cfg.LLMProvider)
    KeyPresent   bool    // anthropic only: ANTHROPIC_API_KEY is set; never the value
    BudgetUSD    float64 // cfg.LLMDailyBudgetUSD
    ERPHost      string  // host of ERP_BASE_URL only (no userinfo, path or query); "" if unset
}
// Options.System *SystemOptions{Backend SystemBackend; Info SystemInfo}
```

- Status per row: `ok`, `down` (the check returned an error or timed out), `unknown` (not checked yet) and for the model row `ok` when the provider is `claude-cli`, or when it is `anthropic` and `KeyPresent`, else `down` ("API key not set"). **The model provider is never called**: a status page must cost nothing.
- Budget row: spend, budget and a percentage; tone ok below 80%, warn from 80%, danger at or above 100% ("Budget reached: new model calls are refused"). Money is shown as USD with two decimals and is not rupee-formatted (it is a model cost, not ledger money). `BudgetUSD == 0` shows "No budget set". Do not use `float64` arithmetic for money in `internal/web`: take spend as a decimal string from the store and compare with `BudgetUSD` only for display tone (`SpendToday.USD string`, `SpendToday.Fraction float64` computed in the adapter is acceptable; the analyzer `nofloat` governs ledger money only, check `gates/analyzers/nofloat` before choosing).
- Checks run in parallel, each bounded to 2 s, so the page answers in about 2 s worst case. Errors are logged (`log/slog`) and the page shows only the fixed text "Not reachable" or "Check failed". Never put `err.Error()`, URLs with credentials, hostnames of the database or any header in the page or the log line's message.
- Cache: a `systemCache` on `Server` holds the last result with its check time. The status page uses the cache when it is under 10 s old, else refreshes, and shows "Checked <time> UTC" from `s.now`. Only one refresh runs at a time (copy the `companyCache` pattern: mutex guards fields only, never held across a backend call; a clock that goes backwards counts as stale).
- **Health dot (top bar).** `templates.ShellData` gains `Health string` (`ok`, `down`, `unknown`, `""` for no backend). `shellData` fills it from the cache's last overall result and **never waits for a check and never starts one**: only `GET /system` refreshes the cache and a background refresh started by `Serve` every 30 s (when `Options.System` is set) keeps it warm. With no result yet it is `unknown`. The dot is a link to `/system` and carries a text label for screen readers ("System: all checks passing / a check is failing / not checked yet"), shown as a `StatusChip`-style icon plus visually-hidden text, so colour is not the only signal. Style it in `css/shell.css` with tokens only.
- Overall status: `down` if any of Postgres, ERPNext or the model row is down or the budget is reached; `unknown` if nothing has been checked; else `ok`.
- `cmd/agent/system.go`: `systemAdapter` wraps `*store.Store` (Ping, `LLMSpendToday`) and an ERPNext reachability probe. The probe is a `GET <ERP_BASE_URL>/api/method/ping` made with a client from `internal/httpx.New(cfg, httpx.WithTimeout(2*time.Second))` (it enforces the egress allowlist; **do not** use `http.Get` or any API key or secret for this call, the egress analyzer would refuse it and ERPNext's ping needs none). Any 2xx is up; anything else or a transport error is down. If `ERP_BASE_URL` is empty the row shows "Not configured" (status `unknown`), not down.
- `store.LLMSpendToday(ctx, now time.Time) (string, error)` in the new file `internal/store/llmspend.go`: `SELECT coalesce(sum(cost_usd), 0)::text FROM llm_calls WHERE created_at >= $1 AND created_at < $2` over the UTC day of `now`, the same window as `LLMBudgetExhausted` (`runprogress.go:147`). Read-only; no migration.
- Wiring: add `system web.SystemBackend`/info to `serveBackends` and set `opts.System` in `newServeServer`/`serve` (`cmd/agent/serve.go`). `--no-explain` does not matter: the model row still shows the configured provider.
- Static CSS for the page goes in `css/system.css` (a slot exists: `/* System (UI-12). */`); the health dot in `css/shell.css`. Do not edit `app.css`, `components.css` or `design_test.go` (owned by UI-03a), and do not edit `ui*.templ` or `ui.go`: compose `Card`, `StatusChip`, `StatTile` and `Facts` as they are.

## Page

- `PageHeader` "System", subtitle "Read-only health of the services this app depends on."
- A `Card` per row (Postgres, ERPNext, Model provider, Daily model budget): title, `StatusChip` (`ok`/`down`/`unknown` mapped to existing chip statuses; if a status string is missing from `statusChip`, use a neutral existing one, do not edit `ui_basic`), one line of fixed text, and for ERPNext the host from `Info.ERPHost`, for the model the provider name and "API key set"/"API key not set", for the budget a `StatTile` with spend and "of $X.XX".
- Footer line: "Checked 09:00:12 UTC" and a "Check again" link `GET /system?refresh=1` that forces a refresh but is itself rate-bounded: a forced refresh is ignored when the last check is under 2 s old.
- No secrets anywhere: no tokens, keys, DSNs, usernames, full URLs, versions or error text.

## Acceptance (human-readable)

- Open System from the sidebar: four cards with clear status words; stop Postgres or point `ERP_BASE_URL` at a closed port and the matching card and the top-bar dot go down without the page hanging.
- The dot appears on every signed-in page, never slows a page down, and is understandable without colour.
- Look at the page in light, dark and at 420px.

## Out of scope

- Live model calls or model health pings, MCP server status, run queue depth, restart or reset buttons, history or graphs of uptime, alerting, `GET /healthz` changes.
