# CC-608 · Register the Phase 2 detectors in the close workflow

## Goal

A close started by `cmd/agent` runs bank reconciliation plus the five Phase 2 detectors (CC-603 to CC-607), and each variance finding is linked to the finding it relates to before it is stored.

## Context

- Not in the tickets doc: this ticket comes from the Phase 2 merges of 2026-10-11. CC-603 to 607 are merged but `Workflow.checks()` still returns bank reconciliation only, so none of them runs in a close. Do not open `docs/`.
- Gate-run acceptance (graph.yaml): "A close on the suite fixture runs CC-603 to 607; every prepaid finding has a linked variance; recall holds".
- The workflow runs checks one at a time, each as its own step. `runCheck` (workflow.go:671) calls `checks.NewRunner(nil).Run`, which dedupes only that check's findings and persists nothing (store is nil), then `w.Store.FinishWithFindings(ctx, step, refs, fs)` stores them. Findings from earlier checks are therefore already in the store when a later check runs: read them with `w.Store.ListFindingsByRun(ctx, run.ID)` (part of `RunStore`).
- `checks.LinkVariances(findings []Finding) []Finding` (variance.go:207): sets `keys.related` on each `variance` finding to the ID of the first non-variance finding on the same `account` and `month`, or whose `invoice` key is among the variance's `list_purchase_invoices` evidence. Its doc says: call it after `DedupeFindings`, because `related` is part of the dedupe key. It returns a new slice, copies the maps it changes, and leaves a variance that already has `related` set alone. It only links within the slice it is given.
- Consequence: variance must run after every other check, and the link must be computed against the run's already-stored findings plus the variance step's own, before `FinishWithFindings`. Resume is safe because a finished step is skipped (`begin` returns done) and the linked IDs belong to steps that finished earlier.
- `variance` is an unscored type in the evals (`UnscoredTypes` in internal/evals/score.go), so it cannot change precision or recall.
- Finding types raised: CC-603 `duplicate_vendor_payment`; CC-604 `gstr2b_*` (five types); CC-605 `missing_accrual`; CC-606 `prepaid_not_spread`, `misclassified_expense`, `wrong_period_posting`; CC-607 `variance`.
