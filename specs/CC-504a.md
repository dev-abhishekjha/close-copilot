# CC-504a · Audit decorator on every tool

## Goal

Every MCP tool call, read or write, lands in `audit_log` with who made it and what came back.

## Context

- Ticket: docs/implementation-tickets.md, section `CC-504a`. Plan row: Phase 2, INT, data-sensitive; check "Every Inspector call appears in `audit_log`".
- Quoted from the shared specs:
  - `audit_log (id bigserial PK, at timestamptz NOT NULL DEFAULT now(), actor text NOT NULL, server text, tool text, args jsonb, result_count int, latency_ms int, error text)`.
  - "`audit_log` is append-only: the app's database role has no UPDATE or DELETE on it."
  - Ticket: wrap every handler in a generic decorator at registration, so no tool can be added without auditing. The actor comes from the token, never from tool arguments (`agent:run/<id>` once CC-506 lands). Record actor, server, tool, arguments with secrets redacted, result count, latency and error.
- CLAUDE.md invariants that apply: the MCP admin token is used only by `internal/approvals`; write tools exist only on `/mcp-admin`; secrets only from env.
- Facts found while writing this spec (verify, don't trust):
  - **No `copilot_app` role exists anywhere in the repo.** The app connects as the superuser/owner `copilot` (`.env.example`, `deploy/docker-compose.yml`). `REVOKE ... FROM copilot_app` alone would fail, and revoking from a superuser does nothing. The migration must create the role (see Subtasks).
  - `mcp-books` does not open Postgres today; `mcp-evidence` does. `mcp-books` needs `DATABASE_URL` added to its required env list.
  - `internal/mcpkit/auth*.go` is a **protected path**: do not edit it. `Route` has no actor field, so the actor is supplied by a new option on `BuildHandler` (below), not by changing `Route`.
  - CC-506 will later edit `internal/books/tools*.go` and `internal/evidence/tools.go`, the same files as here: CC-506 must start after this merges.

## Subtasks

- [ ] `internal/mcpkit/audit.go`: `type AuditSink interface{ InsertAuditLog(ctx, store.AuditLogEntry) (int64, error) }` (a `*store.Store` satisfies it); `EnableAudit(s *mcp.Server, server string, sink AuditSink)` records the sink per server; generic `AddTool[In, Out any](s *mcp.Server, t *mcp.Tool, h mcp.ToolHandlerFor[In, Out])` registers `h` wrapped so each call writes exactly one row: actor from the request context (never from `In`), `server`, `tool`, `args` (the call's JSON arguments with redaction), `result_count`, `latency_ms`, `error`.
- [ ] Redaction: replace the value of any argument key matching (case-insensitive) `token|secret|password|api_?key|authorization` with `"[REDACTED]"`, at any depth; truncate the stored args to 8 KiB (store a JSON marker if cut).
- [ ] `result_count`: length if the output is a slice or array; 1 for any other successful output; 0 on error. `error`: the error text, or empty/NULL on success. Audit even when the handler panics or returns an error.
- [ ] If the server has no sink enabled, `AddTool` passes the handler through unchanged (unit tests of tool packages stay as they are). The binaries must enable it: `newBooksServer` and the evidence server constructor call `EnableAudit` before `RegisterTools`; a failed audit insert is logged with `slog` and the call returns a tool error (fail closed). Say which you chose in the PR summary.
- [ ] `mcp-books` opens the store (`store.Open(ctx, cfg.DatabaseURL.Reveal())`) and lists `config.EnvDatabaseURL` in its required env.
- [ ] No tool package calls `mcp.AddTool` directly: replace the 9 calls in `books/tools.go` and `evidence/tools.go`. A grep test in `audit_test.go` walks non-`_test.go` files under `internal/` and `cmd/` and fails on any `mcp.AddTool(` outside `internal/mcpkit/audit.go` (use `go/parser`, not a shell grep).
- [ ] `migrations/0005_audit_append_only.sql` (goose, same format as `0002_runs.sql`): create role `copilot_app` `NOLOGIN` if it does not exist (`DO $$ ... IF NOT EXISTS ... $$`); `GRANT SELECT, INSERT ON audit_log TO copilot_app`; `GRANT USAGE ON SEQUENCE audit_log_id_seq TO copilot_app`; `REVOKE UPDATE, DELETE, TRUNCATE ON audit_log FROM copilot_app`. Down: revoke the grants (leave the role).
- [ ] `audit_test.go` (no database; a fake sink): one row per call for books-style and evidence-style tools; actor comes from context and a hostile `actor` argument is ignored; secrets redacted; error calls audited; grep test above.
- [ ] `audit_integration_test.go` (tag `integration`): real Postgres, run migrations, start a server through `BuildHandler` with `WithActors`, drive a real MCP client session over the HTTP handler calling tools, assert one `audit_log` row per call with the right actor/server/tool. Then `SET LOCAL ROLE copilot_app` in a tx: `INSERT` and `SELECT` succeed; `UPDATE`, `DELETE` and `TRUNCATE` fail with SQLSTATE `42501`.

## Acceptance (human-readable)

- Every call in an Inspector-style session (a client calling each tool) appears in `audit_log`.
- `UPDATE` and `DELETE` on `audit_log` are refused for `copilot_app`; the migration applies twice cleanly (`make migrate` no-op the second time).
- Nothing in `internal/` or `cmd/` calls `mcp.AddTool` outside `audit.go`.
- Owner to check: `\du` shows `copilot_app` as NOLOGIN, and the PR summary states the fail-closed choice.
