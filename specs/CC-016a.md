# CC-016a · Eval workflow gates suite-v1 and the suite-v1 baseline

## Goal

A pull request's G4 check replays and compares both `suite-skeleton` and `suite-v1`, inside the one job named `eval (G4)`.

## Context

- CC-016 (merged) made `evals/baseline.json` a version 3 file, `{"version":3,"suites":{"<suite>":{"replay":...,"llm":...}}}`, still reading version 2. The committed file is still version 2 (suite-skeleton replay, llm null). The scorer is built from the base ref in CI, so it already understands version 3.
- **Owner decisions (delegated to the orchestrator, 2026-10-12):** both suites are gated on every eval-relevant pull request; the job keeps its name `eval (G4)` and is not a matrix (a matrix renames the job and breaks the required check); the `llm` tier stays `suite-skeleton` only and stays null (a dispatch or nightly run still fails at "baseline present" for the llm tier; that is known and accepted).
- `suite-v1` replays clean: recall 40/40, precision 66/66, 0 clean-month false alarms, 0 failed runs.
- **Who edits what.** The worker edits `.github/workflows/eval.yml` only. `evals/baseline.json` is changed by the orchestrator, in its own `baseline-update` commit after the workflow commit, made from a scorer candidate (see Notes). Do not edit or write it.
- No actionlint here. The acceptance commands parse the YAML and `bash -n` every `run:` block. The real run is the owner dispatching the workflow after the merge.

## Code map

`.github/workflows/eval.yml` (read the whole file; it is about 330 lines):
- line 53 `env: SUITE: suite-skeleton` is the only place the suite is chosen; every later step uses `$SUITE`.
- "decide the tier" sets `replay` and `llm` outputs. "fixtures present (fail closed)" checks `evals/fixtures/$SUITE/index.json`. "gitleaks over the fixtures" scans all of `pr/evals/fixtures` already. "prepare the code under test" copies the base `evals/baseline.json` to `$RUNNER_TEMP/candidate/baseline.json`.
- "tier 1: replay without the model and score" runs `eval run --replay --no-llm --suite "$SUITE" --results-dir "$RUNNER_TEMP/results-replay"`, reads the manifest from the last line of the output, exports `dir` and `run_rc`, then scores with `--out "$RUNNER_TEMP/score-replay" --baseline-out "$RUNNER_TEMP/candidate/baseline.json" --pricing config/pricing.yaml` using the scorer built from the base ref (`$RUNNER_TEMP/evalbase/eval`).
- "tier 2" runs three model replays for `$SUITE` (dispatch and schedule only, never pull_request). "upload results and the candidate baseline" uploads `results-*`, `score-*`, `noise-llm.json`, `candidate/baseline.json`.
- "baseline present (fail closed)" checks with `jq -e '.version == 2 and .tiers[$t] != null'`.
- "tier 1 gate" runs `eval score "$RESULTS" --out "$RUNNER_TEMP/gate-replay" --compare "$GITHUB_WORKSPACE/base/evals/baseline.json" --require 'unrecorded_bank_charge.recall>=3/3' --require 'clean.false_alarms==0'`, then fails if `RUN_RC != 0`. "tier 2 gate" is the same with the latency and cost thresholds. "job summary" cats `gate-replay/summary.md` or `score-replay/score.md`, and the llm equivalents.

## Subtasks

- [ ] Replace the single `SUITE` with `SUITES: "suite-skeleton suite-v1"` for the replay tier, and `LLM_SUITE: suite-skeleton` for tier 2, its gate and its candidate. Keep the job name, the `on:` triggers, permissions and concurrency exactly as they are.
- [ ] "fixtures present": loop over `$SUITES`; fail closed naming every suite whose index is missing (collect, then fail), same notice text.
- [ ] Tier 1 replay: loop over `$SUITES`. Per suite `<s>`: replay into `results-replay-<s>`, record the manifest directory and the run's exit code in files under `$RUNNER_TEMP` (`replay-dir-<s>`, `replay-rc-<s>`), score into `score-replay-<s>` with the same flags, and `--baseline-out "$RUNNER_TEMP/candidate/baseline.json"` (each call adds or replaces that suite's replay section of the copied file; it ends as version 3 with both suites). A missing manifest fails the step, naming the suite. Keep `set +e` around the run so the loop continues past a failed run, and fail the step at the end if any suite had no manifest.
- [ ] "baseline present": for each tier that will run and each suite that tier covers (replay: `$SUITES`; llm: `$LLM_SUITE`), accept version 3 (`.version == 3 and .suites[$s][$t] != null`) or version 2 (`.version == 2 and .tiers[$t] != null and .tiers[$t].suite == $s`); report every missing `<suite>/<tier>` in the notice, then fail. Update the notice's bootstrap text to say the owner commits `evals/baseline.json` in a `baseline-update` commit (it no longer says "dispatch to get a candidate" for the PR case).
- [ ] "tier 1 gate": loop over `$SUITES`, one `eval score ... --compare` per suite with `--out "$RUNNER_TEMP/gate-replay-<s>"`. Requirements: `suite-skeleton` unchanged (`unrecorded_bank_charge.recall>=3/3`, `clean.false_alarms==0`); `suite-v1` uses `--require 'clean.false_alarms==0'` only (the baseline compare already fails any caught item that is no longer caught). Run every suite even if an earlier one fails, remember the worst exit code, fail if any suite's run exit code was non-zero (message names the suite), and exit non-zero if any score failed.
- [ ] Tier 2 and its gate use `$LLM_SUITE` in place of `$SUITE`, otherwise unchanged. The artifact upload globs still match (`results-*`, `score-*`); add `gate-*` only if the summary needs it.
- [ ] "job summary": for tier 1, cat each suite's `gate-replay-<s>/summary.md` (else `score-replay-<s>/score.md`), with a heading per suite. Tier 2 unchanged.
- [ ] No other change: do not touch the gitleaks pin, the checkout steps, the scorer build or the triggers.
