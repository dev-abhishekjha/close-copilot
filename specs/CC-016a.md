# CC-016a · Eval workflow gates suite-v1 and the suite-v1 baseline

## Goal

A pull request's G4 check replays and compares both `suite-skeleton` and `suite-v1`, inside the one job named `eval (G4)`.

## Context

- CC-016 (merged) made `evals/baseline.json` a version 3 file, `{"version":3,"suites":{"<suite>":{"replay":...,"llm":...}}}`, still reading version 2. The committed file is still version 2 (suite-skeleton replay, llm null). The scorer is built from the base ref in CI, so it already understands version 3.
- **Owner decisions (delegated to the orchestrator, 2026-10-12):** both suites are gated on every eval-relevant pull request; the job keeps its name `eval (G4)` and is not a matrix (a matrix renames the job and breaks the required check); the `llm` tier stays `suite-skeleton` only and stays null (a dispatch or nightly run still fails at "baseline present" for the llm tier; that is known and accepted).
- `suite-v1` replays clean: recall 40/40, precision 66/66, 0 clean-month false alarms, 0 failed runs.
- **Who edits what.** The worker edits `.github/workflows/eval.yml` only. `evals/baseline.json` is changed by the orchestrator, in its own `baseline-update` commit after the workflow commit, made from a scorer candidate (see Notes). Do not edit or write it.
- No actionlint here (and no PyYAML), so `evals/ci/check-eval-workflow.sh` (new, declared) does the checks with ruby, jq and bash, which are installed. `make eval-replay SUITE=suite-v1` can only pass after the orchestrator's `baseline-update` commit (until then the baseline has no suite-v1 section): the worker runs `bash evals/ci/check-eval-workflow.sh` and `make eval-replay SUITE=suite-skeleton`; the orchestrator runs `bash evals/ci/check-eval-workflow.sh --with-baseline` and `make eval-replay SUITE=suite-v1` after its `baseline-update` commit and before the merge (not frontmatter acceptance: the gate would fail them on the worker's tree). The real run is the owner dispatching the workflow after the merge.

## Code map

`.github/workflows/eval.yml` (read the whole file; it is 300 lines; GitHub's default shell for `run:` is `bash -e {0}`, no `-u`, no `pipefail`):
- line 53 `env: SUITE: suite-skeleton` is the only place the suite is chosen; every later step uses `$SUITE`.
- "decide the tier" sets `replay` and `llm` outputs. "fixtures present (fail closed)" checks `evals/fixtures/$SUITE/index.json`. "gitleaks over the fixtures" scans all of `pr/evals/fixtures` already. "prepare the code under test" copies the base `evals/baseline.json` to `$RUNNER_TEMP/candidate/baseline.json`.
- "tier 1: replay without the model and score" runs `eval run --replay --no-llm --suite "$SUITE" --results-dir "$RUNNER_TEMP/results-replay"`, reads the manifest from the last line of the output, exports `dir` and `run_rc`, then scores with `--out "$RUNNER_TEMP/score-replay" --baseline-out "$RUNNER_TEMP/candidate/baseline.json" --pricing config/pricing.yaml` using the scorer built from the base ref (`$RUNNER_TEMP/evalbase/eval`).
- "tier 2" runs three model replays for `$SUITE` (dispatch and schedule only, never pull_request). "upload results and the candidate baseline" uploads `results-*`, `score-*`, `noise-llm.json`, `candidate/baseline.json`.
- "baseline present (fail closed)" checks with `jq -e '.version == 2 and .tiers[$t] != null'`.
- "tier 1 gate" runs `eval score "$RESULTS" --out "$RUNNER_TEMP/gate-replay" --compare "$GITHUB_WORKSPACE/base/evals/baseline.json" --require 'unrecorded_bank_charge.recall>=3/3' --require 'clean.false_alarms==0'`, then fails if `RUN_RC != 0`. "tier 2 gate" is the same with the latency and cost thresholds. "job summary" cats `gate-replay/summary.md` or `score-replay/score.md`, and the llm equivalents.

## Subtasks

- [ ] Replace the single `SUITE` with `SUITES: "suite-skeleton suite-v1"` for the replay tier, and `LLM_SUITE: suite-skeleton` for tier 2, its gate and its candidate. Keep the job name, the `on:` triggers, permissions and concurrency exactly as they are.
- [ ] "fixtures present": loop over `$SUITES`, plus `$LLM_SUITE` when `llm == true` (de-duplicated); fail closed naming every suite whose index is missing (collect, then fail), same notice text.
- [ ] Tier 1 replay: loop over `$SUITES`. Per suite `<s>`: replay into `results-replay-<s>`, record the manifest directory and the run's exit code in files under `$RUNNER_TEMP` (`replay-dir-<s>`, `replay-rc-<s>`), score into `score-replay-<s>` with the same flags, and `--baseline-out "$RUNNER_TEMP/candidate/baseline.json"` (each call adds or replaces that suite's replay section of the copied file; it ends as version 3 with both suites). A missing manifest fails the step, naming the suite. `set +e` only around `eval run`, so the loop continues past a failed run; the run's exit code is recorded in `replay-rc-<s>` and judged in the gate. A scorer (`eval score`) failure, or a missing manifest, aborts the step under `-e` (an infrastructure error), naming the suite.
- [ ] "baseline present": for each tier that will run and each suite that tier covers (replay: `$SUITES`; llm: `$LLM_SUITE`), accept version 3 (`.version == 3 and .suites[$s][$t] != null`) or version 2 (`.version == 2 and .tiers[$t] != null and .tiers[$t].suite == $s`); report every missing `<suite>/<tier>` in the notice, then fail. Keep one notice: for replay suites, "the owner scores a replay locally (`eval score --baseline-out`) and commits it in a `baseline-update` commit"; for the llm tier, dispatch this workflow and download the `eval-results` artifact.
- [ ] "tier 1 gate": loop over `$SUITES`, one `eval score ... --compare` per suite with `--out "$RUNNER_TEMP/gate-replay-<s>"`. Requirements: `suite-skeleton` unchanged (`unrecorded_bank_charge.recall>=3/3`, `clean.false_alarms==0`); `suite-v1` uses `--require 'clean.false_alarms==0'` only (the baseline compare already fails any caught item that is no longer caught). Select requirements with `case "$s" in suite-skeleton) ...;; suite-v1) ...;; *) echo "::error::no gate requirements for $s"; fail;; esac` so a suite added to `SUITES` later is never gated with no requirements. Remove `RESULTS` and `RUN_RC` from this step's env; read each suite's `replay-dir-<s>` and `replay-rc-<s>` files, and if either is missing or empty, emit `::error::` naming the suite and count it as a failure (fail closed). Run every suite even if an earlier one fails, remember the worst exit code, fail if any suite's run exit code was non-zero (message names the suite), and exit non-zero if any score failed.
- [ ] Tier 2 and its gate use `$LLM_SUITE` in place of `$SUITE`, otherwise unchanged. The artifact upload globs still match (`results-*`, `score-*`); add `gate-*` only if the summary needs it.
- [ ] "job summary": for tier 1, cat each suite's `gate-replay-<s>/summary.md` (else `score-replay-<s>/score.md`), with a heading per suite. Tier 2 unchanged.
- [ ] **`evals/ci/check-eval-workflow.sh`** (new, `bash`, `set -euo pipefail`, run from the repo root; `--with-baseline` also checks `evals/baseline.json`). It must fail on today's unchanged `eval.yml` and pass on the new one. Checks: (a) the job is named `eval (G4)` with no `strategy`; `grep -q 'SUITES: "suite-skeleton suite-v1"'` and `grep -q 'LLM_SUITE: suite-skeleton'` hold; no `$SUITE` or `${SUITE}` remains (`! grep -nE '\$\{?SUITE([^S_A-Z]|$)'`); (b) secrets only in tier 2: with ruby, the steps whose `to_s` contains `secrets.` are exactly `["tier 2: replay with the model, three runs, and noise"]`; (c) scorer from the base ref: no `go run ./cmd/eval score` or `go run ./cmd/eval noise` line, and every `--compare` line names `$GITHUB_WORKSPACE/base/evals/baseline.json`; (d) every `run:` block passes `bash -n`; (e) fail-closed test: extract the "baseline present (fail closed)" step's `run` to `tmp/`, run it with `bash -e` and stubbed `GITHUB_WORKSPACE`, `RUNNER_TEMP`, `GITHUB_STEP_SUMMARY`, `SUITES`, `LLM_SUITE`, `REPLAY`, `LLM`: against `git show main:evals/baseline.json` (version 2) it must exit non-zero naming `suite-v1/replay` when `REPLAY=true`; against a generated two-suite version 3 file with `LLM=false` it must pass; with `LLM=true` it must exit non-zero naming `suite-skeleton/llm`; (f) unchanged parts equal `git show main:.github/workflows/eval.yml`: the `on:` block, `permissions`, `concurrency`, `services`, `timeout-minutes`, and the checkout, setup-go, scorer-build and gitleaks steps (compare by step name with ruby). With `--with-baseline`: `.version == 3`, `.suites | keys == ["suite-skeleton","suite-v1"]`, both `llm` sections null, and `jq -S .tiers.replay` of `git show main:evals/baseline.json` equals `jq -S '.suites["suite-skeleton"].replay'` of the new file.
- [ ] No other change: do not touch the gitleaks pin, the checkout steps, the scorer build or the triggers.

## Notes

- The orchestrator makes the baseline commit this way, from a clean tree at the branch head (so the section's `commit` field is meaningful): copy `evals/baseline.json` to a temp file **outside `evals/`** (the scorer refuses outputs there), run `eval run --replay --no-llm --suite suite-v1` then `eval score <dir> --baseline-out <temp copy> --pricing config/pricing.yaml`, review mechanically with `bash evals/ci/check-eval-workflow.sh --with-baseline` after copying it over `evals/baseline.json`, and commit it on its own as `baseline-update`. Both files are protected paths (`gates/protected.go`); the owner's delegation (2026-10-12) stands in for the `approved` label, as for CC-013's truth change. The commit order on the branch is harmless: CI reads the base tree, and the merge brings both commits to `main` together.
- For `suite-v1` only `clean.false_alarms==0` plus `--compare` is required (the compare fails lost catches and clean-month alarms, not a new false alarm in an error-bearing month). A precision floor `--require` for `suite-v1` is a possible later tightening and is the owner's call.
- Regulated: security review and the Opus diff review run before the merge. Review focus: no secret or token is exposed to pull request code; the scorer still comes from the base ref; the baseline is read from the base tree; fail-closed behaviour is kept for a missing suite, tier or fixtures index.
