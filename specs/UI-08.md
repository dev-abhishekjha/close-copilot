# UI-08 · Ask page

## Goal

A page where any signed-in user picks a company and month, asks a question about the books and reads the answer with its verification status and citations, using exactly the same backend, validation and rate limit as `POST /api/ask`.

## Context

- Ticket: `tasks/frontend-plan.md` sections 4 and 10 (`UI-08`). Data-sensitive: `/api/ask` reaches a model, so G5 runs. A question and an answer are customer data: never logged, never put in an error, never cached.
- **The page is a twin of the API, not a new path to the model.** Both call the same `AskBackend.Ask` after the same validation. Refactor `handleAPIAsk` (`ask.go`) into a shared function (for example `s.runAsk(ctx, company, month, question) (AskOutput, askFailure)`) used by both handlers; `POST /api/ask` must behave byte-for-byte as today (status codes, JSON bodies, messages): `ask_test.go` passes unchanged.
- **Rate limit (the part that must not be missed).** `rateLimit` (`ratelimit.go:155`) throttles only `/api/*`, and `POST /api/ask` has the tighter `s.limits.ask` bucket (1 request a second, burst 3 by default, per user). A new HTML route would otherwise bypass it. Make `POST /ask` use the **same `s.limits.ask` bucket, keyed by the same user name**, so the form and the API share one allowance (not two). When refused, `POST /ask` answers `429` with `Retry-After` and the Ask page (rendered with an alert "You are asking too fast. Try again in a few seconds."), not the plain-text body used for other non-API paths; `GET /ask` is not throttled. Test both the shared bucket and the page.
- **Nav tests.** Adding the `/ask` route makes Ask appear in the sidebar for every role (the nav table is derived from the route table), so `shell_test.go` `TestShellNavByRole` and `TestShellNavOmitsUnroutedPages` must be updated to expect `/ask` as a routed, visible item. That is the only edit allowed in `shell_test.go`, it declares nothing weaker, and it is listed in the PR summary.
- Route rows to add to `routeTable` (`routes.go`): `GET /ask` and `POST /ask`, both `anyRole`, handlers wrapped like `askAPI` so that when `s.ask == nil || s.runs == nil` the HTML routes answer **501 with a friendly page** (an `EmptyState` "Ask is not set up on this server"), after the role check. Do not edit `server.go`, `middleware.go` or `auth.go`. The nav shows Ask automatically once the route exists (UI-03's nav table); extend `homeActions` only if a test needs it (the existing `ask` action may gain `Href: "/ask"`).
- CSRF: `POST /ask` is a form post behind the existing wrapper (CSRF token and same-site checks apply as for other forms). It is not an htmx request: a plain form post that re-renders the page keeps it working without JavaScript and avoids htmx's no-swap-on-4xx behaviour.
- Retrieved document text never reaches a tool-calling model (CLAUDE.md invariant) and this page adds no model access: it only calls `AskBackend`.
- Shared files are owned by UI-03a: do not edit `ui*.templ`, `ui.go`, `components.css`, `app.css` or `design_test.go`. Page rules go in `static/css/ask.css`.

## Page

- `PageHeader` "Ask the books", subtitle: "Answers come from the verified ledger evidence for the selected company and month."
- Form (`POST /ask`, `csrf_token`): `SelectField` company (from the same company list the API validates against; default from `contextFor`), `Field` month (`type=month`, `pattern`, `placeholder="YYYY-MM"`, default from `contextFor`), `TextareaField` question (`name=question`, `required`, `maxlength=400`, `rows=4`, label and hint "Max 400 characters"), primary `Button` "Ask". Three suggested questions are links to `/ask?q=<text>`; `GET /ask?q=` prefills the textarea (trimmed, cut at 400 bytes on a rune boundary, escaped by templ, never reflected anywhere else).
- Result area (below the form, `id="ask-result"`), by `AskOutput.Action`:
  - `answer`: a `Card` with the answer text in a `<div class="ask-answer">` (escaped, whitespace preserved by CSS only, no markdown and no HTML interpretation), a `VerifiedBadge`, and when `NeedsReview` a warn `Card` "Needs review: this answer could not be fully verified." Violations (when present) as a list: code, field, detail, and the value formatted with `money.Paise(x).Format()` when `ValuePaise` is set. Citations as a list of document id and section (plain text; UI-11 will link them). Evidence ids and step references inside a `<details>` "How this was checked".
  - `refuse`: a neutral `Card` with the refusal text; `clarify`: an info `Card` with the clarification text and the form kept for another try.
  - Unknown action values render nothing but a generic "No answer was produced."
- Errors, each as an alert above the form with the form values kept (question escaped): empty question (400), question too long (400, "question is too long"), bad month (400), unknown company (400), too many attempts for this question (`ErrTooManyAsks` 429), backend failure or timeout (500, the same fixed text as the API: "internal error"; the cause goes to the log without the question), no company selected.
- Status codes of the form post mirror the API's for the same failure, so tests can compare them. A successful answer, a refusal and a clarification are 200.
- Keep it stateless: no history in the session, cookie or database; reloading shows an empty result.

## Acceptance (human-readable)

- A user opens Ask from the sidebar, picks a company and month, asks a question and reads a verified answer with citations, or a clear refusal; mistakes show a clear error without losing the question.
- Hammering the form cannot exceed the API's allowance; the API behaves exactly as before.
- G5 can confirm: no new route reaches the model without validation, rate limit and CSRF; answers and questions are not logged; output is escaped.
