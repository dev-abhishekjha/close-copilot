# CC-019 · Wire the pseudonymiser into the eval's Tier 2 path

## Goal

`eval run` with the agent on masks GSTINs, PANs and individual names before every explainer model call, from `PSEUDONYM_KEY`, the way `cmd/agent` does, and refuses to start without a valid key.

## Context

- Ticket: `tasks/hardening.md`, section `CC-019` (not in `docs/implementation-tickets.md`). Found at the first Tier 2 run on `suite-skeleton` (`results/suite-skeleton/20261013T091848Z`, 2026-10-13), which logged `explainer: no pseudonymiser configured; identifiers are sent to the model unmasked`.
- Invariant (CLAUDE.md, CC-710): GSTINs, PANs and person names are pseudonymised before any model call. `cmd/agent` sets `LLMExplainer.NewPseudonymiser`; `cmd/eval/main.go` never did, so Tier 2 measured a setup the product never runs, and a Tier 2 baseline recorded that way would be invalid. This ticket comes before that baseline.
- **Required behaviour**
  - When the explainer runs (agent on: neither `--no-llm` nor `--no-agent`, with or without `--replay`), a missing or malformed `PSEUDONYM_KEY` is a startup error: the fixed `errPseudonymKey`, exactly `errors.New("eval: " + config.EnvPseudonymKey + " must be 32 random bytes as 64 hex digits to explain findings (see .env.example), or pass --no-llm")` (the `cmd/agent` text with the `eval:` prefix and `--no-llm` as the escape hatch). Fail before the store, the MCP registry or the model provider is opened.
  - With `--no-llm` / `--no-agent` the key is not read or required, and no `Explainer` is built.
  - The key is 32 random bytes as 64 hex digits (`openssl rand -hex 32`); the value is never logged, never put in an error, and never written to `results/` (the manifest's `ManifestConfig` must stay free of it).
- `cmd/agent/main.go:232-247` is the pattern to copy:

  ```go
  var errPseudonymKey = errors.New("agent: " + config.EnvPseudonymKey +
      " must be 32 random bytes as 64 hex digits to explain findings (see .env.example), or pass --no-explain")
  func pseudonymKey(cfg config.Config) ([]byte, error) {
      if cfg.PseudonymKey.IsZero() { return nil, errPseudonymKey }
      key, err := hex.DecodeString(strings.TrimSpace(cfg.PseudonymKey.Reveal()))
      if err != nil || len(key) != 32 { return nil, errPseudonymKey }
      return key, nil
  }
  ```

  and `cmd/agent/main.go:185`: `NewPseudonymiser: func(runID uuid.UUID) agent.Pseudonymiser { return agent.NewRedactor(pseudonymKeyBytes, runID, names) }`, with `names := byID[companyID].IndividualNames()` and a counts-only log line (`log.Info("pseudonymisation on", "individual_names", len(names))`; names are personal data, never log them).
- `internal/agent/explain.go:188`: `(*LLMExplainer).pseudonymiser(runID)` returns `NewPseudonymiser(runID)` when non-nil, else logs the warning once and uses an identity pseudonymiser. After this ticket the warning must not appear on an eval run with the agent on.
- **Names across companies.** `NewPseudonymiser` gets only a run ID, and an eval suite spans companies. Use the union of `IndividualNames()` over the profiles of the companies that appear in the filtered `months` (`byID[m.Company]`), without repeats. Over-masking another company's name is harmless; leaving one unmasked is not. `NewRedactor` already skips empties and case-insensitive repeats.

## Subtasks

- [ ] `cmd/eval/main.go`: add `errPseudonymKey` and `pseudonymKey(cfg config.Config) ([]byte, error)` as in the pattern (hex, `strings`, `encoding/hex` imports), with the hint naming `--no-llm`.
- [ ] Add `newExplainer(...) *agent.LLMExplainer` that sets `NewPseudonymiser` to `agent.NewRedactor(key, runID, names)` and carries the fields `runSuite` already sets (Store, Accounts, FastModel, StrongModel, Log). Pick the smallest signature that lets a test build it without a database (`st` is whatever interface `LLMExplainer.Store` takes). `runSuite` uses it instead of the inline literal. Names come from a small helper `suiteIndividualNames(byID, months)`; log the count only.
- [ ] `runSuite`: when `agentOn`, call the key check (`explainerKey(cfg, agentOn) ([]byte, error)`, returning nil, nil when the agent is off) before `OpenReplay`, `store.Open` and `newProvider`, and return its error unchanged. When not `agentOn`, never read the key.
- [ ] Never log the key or the unmasked values; nothing about the key goes in the manifest, the results folder, `slog` fields or error text.
- [ ] Tests (the acceptance `-run` names; all five are required):
  - `TestPseudonymKey` (`main_test.go`): empty, short, long, non-hex and whitespace-padded good keys; bad ones return `errors.Is(err, errPseudonymKey)` and the error text contains neither the value nor any prefix of it; the good one returns 32 bytes. Includes the Tier 2 case: `explainerKey(cfg, true)` with no key returns `errPseudonymKey`, with a key returns the bytes.
  - `TestTier1NeedsNoPseudonymKey`: `explainerKey(cfg, false)` with an empty config returns nil, nil.
  - `TestNewExplainer`: with a key the built explainer's `NewPseudonymiser` is non-nil and returns a non-nil `Pseudonymiser` for a run ID; `suiteIndividualNames` unions two companies' individual names without repeats and ignores companies not in the months.
  - `TestExplainerInputMasked`: an `LLMExplainer` from `newExplainer` with a recording fake provider and a finding whose evidence holds GSTINs (synthetic consts or a supplier GSTIN from `config/companies/*.yaml`; never a real GSTIN): the request the fake provider receives contains no raw GSTIN, PAN or individual name, and holds the masked form (`agent.NewRedactor(key, runID, names).MaskString(gstin)`). Required: the request check. Optional: a round-trip of the unmasked explanation, only if a scripted masked answer is cheap. The test fails if `NewPseudonymiser` is removed.
  - `TestRunSuiteNeedsPseudonymKey` (`main_test.go`): calls `run(t.Context(), cfg, log, args)` with args `run --suite suite-skeleton --scenarios-dir ../../evals/scenarios --config-dir ../../config` (plus a mode) and a `cfg` whose `DatabaseURL` fails at parse (`config.NewSecret("::not-a-url")`; never an empty URL, pgx would try localhost:5432). Cases: no mode, and `--replay --fixtures-dir <t.TempDir()>`, with no key return `errors.Is(err, errPseudonymKey)`; `--no-llm` with no key returns an error that is not `errPseudonymKey` (it got as far as the store). This proves the check is wired into `runSuite` and runs before the store, replay and provider setup; it needs no database or Docker.
- [ ] One eval run for the report (not an acceptance command): `go run ./cmd/eval run --suite suite-skeleton ...` with `PSEUDONYM_KEY` from the owner's environment (never read `.env`; if the key isn't in the run's environment, say so and don't invent one) and **no baseline compare**. Show that the `no pseudonymiser configured` warning no longer appears and that the run starts. Also show that the same command without the key stops at startup with `errPseudonymKey`, and that `--no-llm` still runs. This is a model run on the owner's plan: run it once, on `suite-skeleton` only, writing results outside `evals/`.

## Acceptance (human-readable)

- Agent on and no or malformed `PSEUDONYM_KEY`: `eval run` exits non-zero at startup with the fixed message, before any database, MCP or model call.
- Agent on with a valid key: no "no pseudonymiser configured" warning; the model input holds no raw GSTIN, PAN or individual name.
- `--no-llm` / `--no-agent`: no key needed; behaviour unchanged.
- The key and unmasked values appear in no log line, error or results file.
