# CC-505 · Contract tests and Gate 1

## Goal

Both MCP servers are exercised through the real MCP client over HTTP, and every tool's JSON Schema is snapshotted, so transport, auth and schema changes show up in review.

## Context

- **Ticket:** `docs/implementation-tickets.md`, section `CC-505`. Its technical note shows the client code.
- **In-process servers:** build the handler with `mcpkit.BuildHandler(map[string]mcpkit.Route{"/mcp": mcpkit.NewRoute(server, token)}, log)` behind `httptest.NewServer`, so the bearer-auth middleware is exercised too. Use a made-up token, `contract-test-token`.
- **Books (unit test, no tag):**
  - `books.RegisterTools` (CC-502) over a `frappe.Client` pointed at an httptest fake ERPNext.
  - Reuse or copy the fake from CC-502's `internal/books/tools_test.go`; `contract_test.go` is in the same package.
  - Companies come from a synthetic profile built in the test.
- **Evidence (`//go:build integration`):**
  - `evidence.RegisterTools` takes a concrete `*store.Store`, so it needs Postgres.
  - Start it with testcontainers as `internal/store/store_integration_test.go` does, run the migrations, and load a few synthetic bank lines and GSTR-2B entries through the store's own insert methods.
- **Golden schemas:**
  - One file per tool: `testdata/schemas/<tool>.json`, holding the tool's `inputSchema` and `outputSchema` (if present), its description and annotations, as listed by `ListTools`.
  - Write it with sorted keys and 2-space indent.
  - An `-update` flag (package-level `flag.Bool`, as `internal/seed` tests do) rewrites the files.
  - Without `-update`, a mismatch fails and prints a diff.
- **`docs/mcp.md`** (protected `docs/**`; covered by the owner's build-phase delegation):
  - how to run each server (stdio and HTTP, env vars by name only);
  - how to point MCP Inspector at them (`npx @modelcontextprotocol/inspector`) and call each tool;
  - how to regenerate the schema goldens.

  The Inspector run itself is a manual Gate 1 step for the owner; the contract tests are the automated proof.
- No new dependencies; the MCP SDK client is in the module already.

## Subtasks

- [ ] **`internal/books/contract_test.go`, `TestContractBooks`:**
  - connect with `mcp.NewClient` and `StreamableClientTransport` (bearer token header);
  - `ListTools` returns exactly the seven tools, each with the read-only annotation;
  - call each tool with valid arguments and decode `StructuredContent` into the output struct;
  - assert a key value from the fake (an amount in paise, a count, a `next_cursor` round trip for `list_gl_entries`);
  - call one tool with an invalid argument and assert a tool error (`IsError`), not a transport error;
  - a request without the token gets HTTP 401.
- [ ] **`internal/evidence/contract_test.go`, `TestContractEvidence`:** the same for `list_bank_lines` and `list_gstr2b_entries`, including the `min_amount` and `supplier_gstin` filters.
- [ ] **Schema goldens** for all nine tools, with the `-update` flag.
- [ ] **`docs/mcp.md`** as above.
- [ ] **Move the Docker tests behind the integration tag:**
  - `internal/evidence/bank_test.go` (CC-402) and `tools_test.go` (CC-503) start a testcontainers Postgres in the plain unit tests.
  - That breaks the convention "unit tests never call Docker" and adds about 30 s to `make check`.
  - Move every test that needs Postgres into `bank_integration_test.go` and `tools_integration_test.go` with `//go:build integration`. Keep the shared DB helper in one of them.
  - Leave the pure parsing and registration tests where they are.
  - Afterwards, `go test ./internal/evidence/...` must not start a container, and `go test -tags=integration ./internal/evidence/...` must run all of them.

## Acceptance (human-readable)

- Contract tests drive both servers through the protocol and pass. The books test runs in `make check`; the evidence test runs with the integration tag.
- A changed tool schema fails the test until the golden is regenerated.
- `docs/mcp.md` lets the owner run MCP Inspector against both servers (Gate 1's manual check).
