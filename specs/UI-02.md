# UI-02 · Component library in templ

## Goal

The shared building blocks of the new UI as templ components with a stable props contract, styled by `components.css` on the UI-01 tokens, shown together on a `/dev/components` page that production wiring never enables.

## Context

- Ticket: `tasks/frontend-plan.md`, sections 3, 5 and 10 (`UI-02`).
- Pages today hand-write markup and legacy classes. Every later UI ticket (UI-03 to UI-13) composes these components instead, so the Go signatures below are a contract: change them only with the dependent tickets in mind.
- Hard constraints:
  - Strict CSP (`middleware.go:20`): no inline `style=`, no `<style>`, no inline `<script>` or `on*=` handlers. Behaviour comes from one same-origin file, `static/js/ui.js`.
  - All text props are escaped by templ. Never use `templ.Raw` or `templ.SafeURL` on a caller-supplied string: pass `href` as a plain string so templ sanitises `javascript:` URLs.
  - Do not edit `layout.templ`, `pages.go` or `middleware.go`. The shell (UI-03) wires `ui.js` into the signed-in layout; until then only the dev page loads it. Existing pages and their tests are untouched (`runs_test.go:744` allows only the htmx `<script`).
  - Class names are prefixed `ui-` so nothing collides with `legacy.css`.
  - Existing Go names in `templates` that must not be reused: `Action`, `TimelineStep`, `Layout`, `Home`, `Run`, `Finding`, `Audit`, `Metrics`, `Approvals`, `Runs`, `Login`, `Base`.
- Accessibility baseline for every component: semantic element first (`button`, `a`, `table`, `dialog`, `ol`), visible focus from `:focus-visible` (UI-01), names for icon-only controls, `aria-live` where content updates, no information by colour alone, motion honours `prefers-reduced-motion`.

## Components

Props are structs in `internal/web/templates/ui.go`. Zero values must render something sensible. `Attrs templ.Attributes` on a component is the escape hatch for `id`, `data-*`, `hx-*`; it is merged last and never used for `class`, `href` or `on*` (a test checks that an `onclick` key is dropped).

| Component | Signature | Notes |
| --- | --- | --- |
| `Icon` | `Icon(name, label string)` | `<svg class="ui-icon"><use href="/static/icons.svg#icon-NAME"/></svg>`; empty `label` gives `aria-hidden="true"`, else `role="img"` and `aria-label`. Unknown names render nothing. |
| `Button` | `Button(p ButtonProps)` | `ButtonProps{Label, Variant, Size, Type, Icon string; Href string; Disabled, Loading, IconOnly bool; Attrs}`. Variants `primary`, `secondary`, `danger`, `ghost`; sizes `sm`, `md`. `Href` set renders an `<a>` styled as a button. `Loading` sets `aria-busy`, disables, shows a spinner (CSS only). `IconOnly` needs `Label` as `aria-label`. `Type` defaults to `button` (never an accidental submit). |
| `StatusChip` | `StatusChip(status string)` | Maps run, finding and proposal states (`queued running done failed open accepted dismissed proposed approved rejected posted`) to a variant, an icon and a readable label; unknown values render neutral with the raw text. |
| `SeverityBadge` | `SeverityBadge(sev string)` | `high`, `medium`, `low`; text plus icon, never colour alone. |
| `VerifiedBadge` | `VerifiedBadge(verified bool)` | verified (check icon) or unverified (dashed outline). |
| `Card` | `Card(p CardProps)` with children | `CardProps{ID, Title, Subtitle string; Actions templ.Component; Tone string}`; renders `<section>` with a heading level fixed at `h2`. `Tone` `default|danger|warn|info`. |
| `StatTile` | `StatTile(p StatProps)` | `StatProps{Label, Value, Hint, Href, Tone string}`; value uses tabular figures; with `Href` the tile is one link. |
| `DataTable` | `DataTable(p TableProps)` | `TableProps{Caption string; Columns []Column; Rows []Row; EmptyTitle, EmptyBody string; Dense bool}`; `Column{Label, Align string; SortHref string; Sorted string}` (`Sorted` is `asc`, `desc` or empty; sets `aria-sort`); `Row{Cells []Cell; Attrs}`; `Cell{Text, Href string; Num bool; Content templ.Component}`. Numeric cells right-aligned with tabular figures. Wrapped in a focusable scroll container with a visible caption (or `aria-label`). No rows renders `EmptyState` in the body. |
| `Tabs` | `Tabs(p TabsProps)` | `TabsProps{Label string; Items []Tab}`, `Tab{Label, Href string; Count int; Current bool}`. A `<nav>` of links with `aria-current="page"`; server-driven (works with htmx boost), not an ARIA tablist. |
| `Stepper` | `Stepper(steps []Step)` | `Step{Label, Detail, State string}`, states `done active pending failed`. An `<ol>`; the active step has `aria-current="step"`; state is also printed as visually hidden text. |
| `Timeline` | `Timeline(items []TimelineEntry)` | `TimelineEntry{Title, Actor, Time, Detail, State string}`; `<ol>` with `<time>` text supplied by the caller (formatting is the caller's). |
| `ToastRegion`, `Toast` | `ToastRegion()`, `Toast(kind, message string)` | The region is `<div id="ui-toasts" role="status" aria-live="polite">`. `Toast` renders one dismissible message (`success|error|info`); it can be swapped in with htmx `hx-swap-oob="beforeend:#ui-toasts"` by passing that in `Attrs`-like prop `OOB bool`. `ui.js` removes a toast on its dismiss button and after 6 s (errors stay until dismissed). |
| `ConfirmModal` | `ConfirmModal(p ConfirmProps)` | `ConfirmProps{ID, Title, Body, Method, Action, CSRFToken string; Confirm ButtonProps; Fields map[string]string}`. A native `<dialog>` with a `<form method=post>`: hidden `csrf_token`, the `Fields` as hidden inputs (sorted by key for stable output), Cancel and Confirm buttons. Opened by `OpenDialogButton`; no inline script. The confirm button defaults to `danger` when `Confirm.Variant` is empty and the caller sets nothing else (callers restate amounts and accounts in `Body`). |
| `OpenDialogButton` | `OpenDialogButton(p ButtonProps, dialogID string)` | a `Button` with `data-dialog-open="<id>"` and `aria-haspopup="dialog"`. |
| `Field`, `SelectField`, `TextareaField` | `Field(p FieldProps)` etc. | `FieldProps{ID, Name, Label, Type, Value, Hint, Error, Placeholder string; Required bool; Options []Option; Attrs}`. Label bound by `for`/`id`; hint and error linked by `aria-describedby`; error sets `aria-invalid="true"` and is announced (`role="alert"`). |
| `EmptyState` | `EmptyState(p EmptyProps)` | `EmptyProps{Icon, Title, Body string; Action *ButtonProps}`. |
| `Skeleton` | `Skeleton(lines int)`, `SkeletonTable(rows, cols int)` | shimmer by CSS only (off under reduced motion); `aria-hidden` with a visually hidden "Loading". |

## Acceptance (human-readable)

- A person opens `/dev/components` on a server started with the option on, sees every component in light and dark, tabs to every control with a visible focus ring, and opens and cancels the modal with the keyboard and the mouse.
- All existing web tests pass unchanged except the one deliberate `design_test.go` extension.
- `layout.templ`, `pages.go` and `middleware.go` are untouched.

## Out of scope

- Using the components on real pages (UI-03 onward), the app shell, theme toggle, command palette, Indian money formatting, charts.
- Enabling the dev page from `cmd/agent`, config or an env var.
- ARIA tablist behaviour and client-side sorting (the table and tabs are server-driven).

## Notes

- No new dependencies; templ is already the generator (`go tool templ`).
- `<dialog>` with `showModal()` gives focus trapping, Esc to close and a backdrop for free in current browsers; do not rebuild them by hand.
- Keep `components.css` readable: one section per component with a comment header; later tickets only add to it.
