# CC-703 · Close workflow orchestrator

## Goal

`RunClose(ctx, company, month)` drives one run through a fixed sequence of states, records each state as `run_steps` (CC-709), keeps within time and token budgets, and leaves a readable report. A killed run resumes and finishes with no duplicate steps (Gate B).

## Context

- **Ticket:** `docs/implementation-tickets.md`, section `CC-703`.
  - It is a workflow, not an agent: the steps are fixed, and only "explain" and "investigate" call a model.
  - States: `queued → preflight → checking → retrieving → explaining → verifying → investigating → synthesizing → done | partial | failed`.
  - Phase 1 runs preflight, checking (bank reconciliation only), explaining, verifying and synthesizing. Retrieving arrives with CC-806 and investigating with CC-706. Record those as `skipped` steps.
- **Explainer and verifier don't exist yet** (CC-704 and CC-705 come after this ticket).
  - Define `Explainer` and `Verifier` interfaces in `workflow.go`, sized for what CC-704 and CC-705 need: a finding plus its evidence artifact hashes in, an explanation or verdict as an artifact hash out. Every model call goes through `RecordingProvider`.
  - With no explainer configured, the explain and verify steps are recorded as `skipped`, and the run ends `partial` (findings saved, explanations missing). The CLI's default stays like that until CC-704 lands.
  - Tests use fakes and expect `done`.
  - Explaining runs four findings in parallel. A finding that fails verification is retried inside the explainer, then marked `needs_review`; with fakes, just keep the hook.
- **Steps and resume (CC-709 API, merged):**
  - Each state is one or more steps. `kind` is from the shared spec (`router`, `check.<name>`, `retrieve`, `explain`, `verify`, `investigate`, `synthesize`); `subject` is the check name or the finding ID.
  - Wrap each step in `store.Begin`. `done=true` means skip it. Finish with `store.Finish(ctx, step, ...)` or, for check steps, `store.FinishWithFindings(ctx, step, outputRefs, findings)` after `Snapshots.Annotate`.
  - Treat `ErrStaleAttempt` as "another attempt owns this step": stop this run with an error, and never retry in a loop.
  - Workers return `StepResult{StepID, Status, OutputRefs}`. The workflow passes artifact hashes around and never decodes artifact content.
  - **Finding IDs must be stable across a resume.** Steps after `checking` take subjects from the stored findings (`ListFindingsByRun`), never from a re-run of the checks.
  - `ResumeClose(ctx, runID)` loads the run, re-runs every step that isn't `done`, and finishes the run. It refuses a run in `done`.
  - Never use `artifacts.run_id` or `artifacts.produced_by` for provenance (they keep the first writer). Use `run_steps.output_refs`.
- **Preflight** (the router step for close runs). It refuses with a reason, before any check, when:
  1. evidence for the month isn't loaded: `MCPEvidence` returns no bank lines for the month;
  2. books are unreachable: one cheap books tool call for the month, such as `TrialBalance`, through MCP;
  3. the daily LLM budget is exhausted: `store.LLMBudgetExhausted(ctx, cfg, now)`.
  - The agent reaches ERPNext only through the MCP readers (CC-702). `internal/agent` must not import `internal/frappe`, transitively; `noerpimport` covers tests too.
- **Budgets:**
  - The run ctx gets a 10-minute deadline; `--timeout` may shorten it, never lengthen it.
  - A per-run token cap comes from the new `LLM_RUN_TOKEN_CAP` (int, default 200000, must be > 0). It is checked before each model call from the run's recorded `llm_calls`; over the cap, the remaining explain steps become `skipped` and the run ends `partial`.
  - Add the variable to `internal/config` and `.env.example`. This adds a stricter limit; never touch `LLM_DAILY_BUDGET_USD`.
- **No floats in `internal/agent`** (the `nofloat` analyzer).
  - Cost and token rollups happen in SQL in the new `internal/store/runprogress.go`, which is not under `nofloat`:
    - `SetRunState(ctx, runID, status, errText)`;
    - `RollupRunUsage(ctx, runID)` sums `llm_calls` (through `run_steps`) into `close_runs` tokens and cost;
    - `RunTokensUsed(ctx, runID) (int64, error)`;
    - `LLMBudgetExhausted(ctx, cfg config.Config, now time.Time) (bool, error)` compares today's UTC `sum(cost_usd)` with `cfg.LLMDailyBudgetUSD` in SQL, passing the budget as a decimal string.
  - Update `close_runs` after each state: status, timings, tokens and cost.
  - Don't edit `runs.go`.
- **Report:**
  - `report.go` renders `results/runs/<run_id>.md` (the dir is set by `--results-dir`; `results/` is git-ignored).
  - A templated Synthesizer in plain Go, with no model call. It lists the run, its state, each finding with its amount in rupees (use `money` formatting) and evidence IDs, and explanations when present.
  - Store the report as a `report` artifact. A golden-file test sits under `internal/agent/testdata/report/`.
- **CLI (`cmd/agent`):**
  - `agent close --company sharma --month 2026-09 [--results-dir results] [--timeout 10m]` and `agent resume <run_id>`. Keep the existing config check.
  - Ctrl-C (SIGINT or SIGTERM) cancels the ctx. The run is marked `failed` with reason `cancelled` (use a fresh short ctx for that final write), and the command exits non-zero.
  - A `kill -9` leaves the run `running`, and `resume` finishes it.
  - Production `cmd/agent` must not import `internal/frappe`, `internal/books` or `internal/seed`. Add a `go list -deps` test in `cmd/agent` (without `-test`), as CC-601a's `TestNoERPClientDependency` does.
- **Shared fake ERPNext:**
  - Move `fakeLedgerERP` and its synthetic-month builder out of `internal/checks/direct/parity_test.go` into the non-test package `internal/testsupport/fakeerp`, along with a helper that seeds the matching bank lines into a `*store.Store`.
  - Make both parity tests use it; their assertions don't change.
  - It may import frappe and books (it serves the books MCP server over the fake). Only tests import it: add a check that no non-test package imports `internal/testsupport/...`.
  - Synthetic data only, including the three planted bank charges.
- **Gate B tests (integration tag):**
  - `internal/agent/workflow_integration_test.go`, `TestWorkflow*`:
    - Postgres via testcontainers.
    - In-process books and evidence MCP servers over `fakeerp`, run outside `internal/agent`: start them in a helper from `fakeerp`, and have the agent test receive only URLs and a token, so it doesn't import books.
    - A skeleton month with fake explainer and verifier ends `done`, with three bank-charge findings, a report file and a `report` artifact.
    - With no explainer it ends `partial`.
    - An exhausted budget is refused at preflight.
    - A month with no evidence is refused at preflight.
    - The token cap leads to `partial`.
  - `cmd/agent` tests:
    - **`TestKillResume`:** build the binary with `go build` in the test and start `agent close` against the in-process servers and Postgres (env vars set in the test). Kill it with SIGKILL once `run_steps` shows at least two `done` steps, then run `agent resume <run_id>`. Assert the run ends with the expected status, every `(run_id, kind, subject)` appears once, and findings and the report equal an uninterrupted run once IDs are ignored.
    - **`TestCloseCLI`:** SIGINT leads to `failed` with reason `cancelled`.
  - Without an explainer the expected end state is `partial`. Wire the fake explainer through a test-only build of the binary, or accept `partial` and assert the explain steps are `skipped`. Choose one and say which.
- **Notes carried from `tasks/hardening.md`:**
  - Put a run-level deadline on the ctx (`GLEntries` can page up to 1000 times).
  - A NUL or U+FFFD in source text stops a snapshot with `ErrUnstorableContent`. In this ticket, mark the run `failed` with that reason; the sanitising policy is a later ticket.
  - `cost_usd` rounding and range: reject negative or ≥10000 costs in Go before the insert. That is a small change in `runprogress.go`'s callers, or note it if it belongs in `artifacts.go`, which is not declared here.
- No new dependencies.

## Acceptance (human-readable)

- A seeded skeleton month ends `done` (with fakes) or `partial` (no explainer yet), with findings and a report file.
- Ctrl-C leaves the run `failed` with a reason.
- `kill -9` mid-run, then `resume`, finishes with no duplicate steps (Gate B).

## Out of scope

- The real explainer and verifier (CC-704, CC-705), retrieval (CC-806), the investigator (CC-706) and the web UI (CC-1001).
