# CC-902 · Scoring and the results report

## Goal

`cmd/eval score <results-dir>` compares a suite run's findings with the seeder's ground truth and writes precision, recall and the other metrics as `score.json` and a README-ready `score.md`, with count-based `--require` checks, an item-by-item `--compare` against a baseline, and a noise calculator.

## Context

- **Ticket:** `docs/implementation-tickets.md`, section `CC-902`. Plan: `docs/orchestrated-implementation-plan.md`, "RAG evaluation design" → Metrics, Baseline storage, Regression tolerance (regressions are judged **item by item**, not by percentage).
- **Independence (why this ticket is regulated):** the scorer is the measuring stick. It must not import or reuse the code it grades: no import of `internal/checks`, `internal/agent` (except what `cmd/eval run` already uses), `internal/seed`, `internal/frappe`, `internal/books`. It decodes ground truth with its **own** types in `internal/evals/truth.go`, matching `evals/schema/ground_truth.schema.json` (`scenario, company, month, clean, planted[{id,type,keys,amount_paise}], expected[{type,keys}], investigations[{id,keys,expected_resolution}]`), with `DisallowUnknownFields` and `json.Number`/`UseNumber` for `amount_paise`.
- **Inputs, as CC-901 wrote them** (read `internal/evals/result.go`, `runner.go`, `testdata/*.json`):
  - `<results-dir>/manifest.json` (`evals.Manifest`: `suite.name`, `results[]{company, month, control, file, run_id, status, failed}`, `commit`, `config.llm_model_fast/strong`, `agent`).
  - one `evals.Result` per month: `findings` are `store.Finding` (`type`, `keys map[string]string`, `verified`, `status`, `amount_paise`), plus `duration_ms`, `cost_usd` (exact decimal **string**), `tokens`, `models`.
  - Ground truth: default `--truth-dir evals/scenarios/<manifest.suite.name>/ground_truth`, file `<company>-<month>.json` (written by `cmd/seed` via CC-306). **Read only.** A month in the manifest with no truth file is an **error** (never treated as clean).
- **Finding types and matching keys** (tickets doc, "Finding types"):

  | Type | Keys |
  | --- | --- |
  | `unrecorded_bank_charge`, `unmatched_bank_line` | `bank_txn_id` |
  | `unmatched_ledger_entry` | `gl_entry` (reported, not scored) |
  | `duplicate_vendor_payment`, `prepaid_not_spread`, `misclassified_expense`, `wrong_period_posting` | `invoice` |
  | `gstr2b_missing_in_2b`, `gstr2b_amount_mismatch`, `gstr2b_missing_in_books`, `gstr2b_wrong_period`, `gstr2b_not_eligible` | `supplier_gstin` + `invoice_no_norm` |
  | `missing_accrual` | `supplier` + `month` |
  | `variance` | `account` + `month` (reported, not scored) |
  | `suspicious_instruction_text` | `invoice` or `bank_txn_id`; planted as `prompt_injection` |

- Protected, never edit: `evals/golden/**`, `evals/scenarios/**`, `evals/baseline.json`. The first real baseline is committed **by the owner** in its own `baseline-update` commit; this ticket only produces a candidate file.
- Unit tests use files under `internal/evals/testdata/score/` only: no Postgres, ERPNext, Docker or model.

## Subtasks

- [ ] **`truth.go`:** `LoadGroundTruth(path)` with strict decoding; rejects a company/month that differs from the file name, a planted ID that isn't `E\d{2,}`, duplicate planted IDs, an investigation ID that isn't `X\d{2,}`.
- [ ] **Matching (`score.go`):**
  - Type mapping: `prompt_injection` → `suspicious_instruction_text`; every other planted type maps to itself.
  - A finding matches a truth item when the mapped types are equal and **every key in the truth item** is present in the finding with an equal value (compare after `strings.TrimSpace`; extra finding keys are ignored). A truth item with empty `keys` can never match: report it as `unmatchable` and count it missed.
  - **Each truth item matches at most one finding, and each finding at most one item.** Order is deterministic: truth items by ID (expected items by type then canonical keys), findings by type, canonical keys, then finding ID. A second finding for an already-matched item is a false alarm with reason `duplicate`.
  - Correct but unplanted: findings matching an `expected` item count as correct. `unmatched_bank_line` findings matching an `investigations` item count as correct (the investigation case was surfaced).
  - Not scored: `variance`, `unmatched_ledger_entry`. Listed in the report, excluded from precision and false alarms.
  - A month whose run `failed` has its planted items counted missed and is listed under `failed_runs`.
- [ ] **Metrics (`score.json`)**, all counts as integers, ratios as `{"num": n, "den": d}` plus an integer-arithmetic percentage string; **no `float64` anywhere in the scoring code**:
  - per planted type: `planted`, `caught`, `missed`, `recall`;
  - overall: `recall`, `precision` = scored findings matching a planted, expected or investigation item ÷ all scored findings;
  - `clean.false_alarms` = scored findings in `control: true` months (target 0);
  - `verified_rate` = findings with `verified: true` and status ≠ `needs_review` ÷ all findings;
  - `investigation_accuracy`: `{"measured": false, "reason": "no investigator (CC-706)"}` until findings carry a resolution;
  - `unauthorized_writes`: `{"checked": false, "reason": "audit decorator (CC-504a) and ERPNext external-ID check not built"}`. A `--require` on it **fails** while unchecked; it never passes by default;
  - cost and time per close run: mean and p95 (nearest rank) of `duration_ms`; total, mean and p95 of `cost_usd` as exact decimal strings (`math/big`, like `sumDecimals`); token totals;
  - `items`: every planted item's outcome (`{"id":"E01","outcome":"caught","finding_id":...}` or `missed`/`unmatchable`), every false alarm with company, month, type, keys and reason (`no_match`, `duplicate`, `clean_month`), and the unscored findings.
- [ ] **`report.go`:** `score.md`, a Markdown table per metric plus the missed and false-alarm lists, deterministic (golden-file test).
- [ ] **`require.go`:** `ParseRequire(expr)` for `<subject>.<metric><op><value>`:
  - subjects: a scored finding type from the table, `overall`, `clean`, `unauthorized_writes`, `verified_rate`;
  - metrics: `recall`, `precision`, `caught`, `missed`, `false_alarms`; `unauthorized_writes` takes no metric (`unauthorized_writes==0`);
  - ops: `>=`, `<=`, `==`, `>`, `<`; values: an integer for counts, `N/M` for `recall`, `precision`, `verified_rate`;
  - for `N/M`, the actual denominator **must equal M** or the requirement fails with "denominator is X, not M" (a shrunken truth set can't pass silently); then compare numerators;
  - malformed input (unknown type or metric, `recall>=3` without `/M`, `M == 0`, `N > M`, a negative, spaces inside the number, an empty string, a trailing op) is a parse error, reported before any scoring, non-zero exit.
- [ ] **`baseline.go`:**
  - `--baseline-out <path>` writes a candidate baseline: every item's outcome keyed `<company>-<month>/<id>`, the aggregates, `noise` (from `--noise`, else empty), the commit and model IDs from the manifest, and the sha256 of `config/pricing.yaml` as the pricing version. It **refuses** any path that resolves to `evals/baseline.json`, so only the owner's `baseline-update` commit writes that file.
  - `--compare <baseline.json>` lists every item caught in the baseline and now missed, and any clean-month false alarm, then exits non-zero if the list isn't empty. A missing or malformed baseline file is an error, never a pass. Items new since the baseline are listed as `new`, not as failures.
  - `cmd/eval noise <score.json>...` (two or more) writes the spread (max − min, in items) per metric: per-type `caught`, `verified`, `clean.false_alarms`. Fewer than two inputs or mismatched suites is an error.
- [ ] **CLI (`cmd/eval`):** `eval score <results-dir> [--truth-dir D] [--out D (default: results-dir)] [--require EXPR]... [--compare FILE] [--baseline-out FILE] [--noise FILE] [--pricing config/pricing.yaml]` and `eval noise <score.json>... --out FILE`.
  - `score` and `noise` need **no environment variables** (no `DATABASE_URL`): only `run` checks `required`. Restructure `main`/`args.go` so the env check depends on the subcommand.
  - Writes are atomic with sorted keys (reuse `writeJSON`).
  - Exits 0 when every requirement and the comparison pass; non-zero (with each failure on stderr) otherwise.
  - Keep `deps_test.go` passing; add `internal/checks` and `internal/seed` to its forbidden list for the binary if not already covered.
- [ ] **`TestScoreCLI` (in `cmd/eval`, calls the binary's run path with an empty environment, no `DATABASE_URL`)** must cover, at minimum:
  - `score testdata/score/run-pass --truth-dir testdata/score/truth --out <tmp> --require 'unrecorded_bank_charge.recall>=3/3' --require 'clean.false_alarms==0'` exits 0 and writes non-empty `score.json` and `score.md`;
  - the same on `run-miss` (2 of 3 caught) exits non-zero and names the requirement;
  - `--require 'unrecorded_bank_charge.recall>=3'` (no denominator) exits non-zero before scoring;
  - `--require 'unauthorized_writes==0'` exits non-zero while unchecked.
  `TestNoiseCLI` covers `noise` with two inputs and with one.
- [ ] **Testdata (`internal/evals/testdata/score/`):** a hand-written `truth/` (sharma 2026-09 with three `unrecorded_bank_charge` items E01–E03 keyed by `bank_txn_id`, one `expected`, one investigation; sharma 2026-08 `clean: true`) and result folders `run-pass` (3/3, clean month empty), `run-miss` (2/3), plus fixtures for the edge cases below. Use `bank_txn_id` keys, as `internal/checks/bankrec.go` emits.
- [ ] **Unit tests (edge cases required):** zero findings; zero planted items (recall `0/0` is reported as `n/a`, and `recall>=1/1` fails on denominator); two findings matching one planted item (one caught, one `duplicate` false alarm); one finding that could match two items (matches exactly one); truth item with empty keys; extra keys on the finding; a key value differing only by surrounding spaces; a `prompt_injection` item caught by `suspicious_instruction_text`; `variance` and `unmatched_ledger_entry` excluded from precision; a finding in the clean month; a failed run; a missing truth file; a truth file with an unknown field; a manifest whose result file is missing; `--require` boundaries `3/3` passes at 3 caught, fails at 2, fails when the denominator is 2; every malformed-expression case above; `--baseline-out evals/baseline.json` (and `./evals/../evals/baseline.json`) refused; `--compare` regression, no change, new item, missing baseline; `noise` with one input; p95 of one run and of 20 runs; cost sums with differing decimal scales.

## Acceptance (human-readable)

- **Manual, owner-run (spends budget / needs the seeded ERPNext; not a gate):**

## Notes

- No new dependencies.
- **Risk: wrong matching inflates scores.** That's why matching requires every truth key, a one-to-one assignment, and a denominator check in `--require`.
- **Risk: silent pass.** Missing truth, a missing baseline, an unchecked unauthorized-writes count and a zero denominator all fail closed.
- `unmatched_bank_line` is counted correct only when it hits an investigation item; on the skeleton suite any other unmatched bank line is a false alarm, which is useful signal, not a scorer bug.
- The existing CC-901 testdata uses `bank_ref` keys; leave it alone and write new score testdata with `bank_txn_id`.
- Percentages in `score.md` use integer math (`num*100/den`, with one decimal via `num*1000/den`) so output is byte-stable.
