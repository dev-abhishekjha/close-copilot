# CC-1201 · Deployment on a VM

## Goal

A demo at a public HTTPS address, plus a one-command local setup for reviewers.

## Context

- Ticket: docs/implementation-tickets.md, section `CC-1201` (line ~2440). Plan row: phase 5, INT, data-sensitive, check "HTTPS demo; fresh clone reproduces locally".
- Ticket description (quoted): "a 16 GB VM fits the stack if traces go to Langfuse Cloud and docling runs only when ingesting. Protect your wallet: the public demo serves pre-computed runs for viewers, and only the maker and checker accounts (whose passwords you share privately with interviewers) can start live runs, under the daily budget cap."
- Plan risk row: "16 GB of RAM isn't enough → Swapping, Docker restarts. Langfuse Cloud; docling only during ingest; `bge-small` for embeddings; run TEI on the VM; stop ERPNext's scheduler container."
- Env vars (from `.env.example`; production needs fresh values for every secret): `ERP_BASE_URL`, `ERP_SITE`, `ERP_API_KEY/SECRET`, `ERP_POST_API_KEY/SECRET` (only the mcp-books process), `DATABASE_URL`, `BOOKS_MCP_URL` (`…:7001/mcp`), `EVIDENCE_MCP_URL` (`…:7002/mcp`), `MCP_TOKEN_AGENT`, `MCP_TOKEN_ADMIN`, `MCP_SCOPE_KEY`, `LLM_PROVIDER=anthropic`, `ANTHROPIC_API_KEY`, `LLM_MODEL_FAST/STRONG` (full model IDs), `LLM_DAILY_BUDGET_USD` (low, e.g. 2.00), `LLM_RUN_TOKEN_CAP`, `PSEUDONYM_KEY`, `TEI_EMBED_URL`, `TEI_RERANK_URL`, `OTEL_EXPORTER_OTLP_ENDPOINT/HEADERS` (Langfuse Cloud), `TRACE_PROMPTS=false`, `APP_ADDR=:8000`, `APP_SESSION_KEY` (>= 32 bytes). Never set `COPILOT_FAULT` or `FAULTS`.
- Binaries: `cmd/agent serve` (web UI and API on `APP_ADDR`), `cmd/mcp-books --transport http --addr :7001 --companies <ids>` (refuses to start if ERP_POST_* is unset or equals the bot's keys), `cmd/mcp-evidence` (`:7002`). Migrations: `goose -dir migrations postgres "$DATABASE_URL" up`.
- Existing compose files: `deploy/docker-compose.yml` (project `close-copilot`: postgres pgvector:pg17, tei-embed, tei-rerank, docling under profile `ingest`) and `deploy/erpnext/docker-compose.yaml` (project `close-copilot-erpnext`, generated; its `frontend` publishes 8080). Prod must not publish any of these ports.
- Web users live in `config/users.yaml` (protected): `asha` maker, `ravi` checker, `demo` viewer. Roles are enforced by `internal/web/routes.go` `routeTable`: `POST /runs` is `makerOnly`, approve/reject are `checkerOnly`, a viewer can only read. `docs/deploy.md` documents rotating the bcrypt hashes before going public; the owner does that edit.
- `DEMO_MODE`: **no code reads it and this ticket may not edit `internal/`**. The "demo viewer can't start runs or approve" requirement is already met by the role matrix (`internal/web/routes_test.go`). Document `demo` as the shared viewer login and say the read-only behaviour comes from its role; do not add a `DEMO_MODE` variable to the prod env file.

## Code map

- `deploy/docker-compose.yml:1`: pattern for postgres/TEI services, healthchecks, volumes; copy images and TEI model ids (`BAAI/bge-small-en-v1.5`, `BAAI/bge-reranker-base`), drop the `ports:` entries.
- `deploy/erpnext/docker-compose.yaml:1`: ERPNext stack (`frontend` at line ~85 publishes 8080 at ~108). Reuse it via compose `include:` or a documented second `-f`; do not edit it (it is generated, `deploy/erpnext/generate-compose.sh`). On the VM stop the `scheduler` service.
- `deploy/erpnext/build-image.sh`, `deploy/erpnext/new-site.sh`, `deploy/erpnext/api-users.sh`: how the ERPNext image, site and API users are made; the docs reference them, do not change them.
- `Makefile:81-150`: targets `up`, `erp-reset`, `seed`, `load`, `ingest`, `run-agent`, `migrate`; the local path in docs/deploy.md uses these exactly.
- `cmd/agent/args.go:28`: usage text for `agent serve`; `cmd/mcp-books/main.go:42`: flags `--transport`, `--addr`, `--companies`.
- `docs/setup.md`: local setup doc to mirror in tone and structure. Do not read `docs/implementation-tickets.md` or `docs/orchestrated-implementation-plan.md`.
- Style to copy: `deploy/erpnext/wait-healthy.sh` for shell scripts (`set -euo pipefail`).

## Subtasks

- [ ] `deploy/prod/docker-compose.yml`: services `caddy` (only service with published ports: 80 and 443), `agent` (serve on 8000), `mcp-books`, `mcp-evidence`, `postgres`, `tei-embed`, `tei-rerank`, plus ERPNext attached on the same internal network. Everything except caddy is on an `internal: true` network (egress services such as the agent need a second, non-internal network only for Anthropic and Langfuse; document why). Docling only under profile `ingest`.
- [ ] `deploy/prod/Dockerfile`: multi-stage Go build of `agent`, `mcp-books`, `mcp-evidence` and goose into one small non-root image (Go 1.26). No `.env` copied in.
- [ ] `deploy/prod/Caddyfile`: automatic HTTPS for `{$DEMO_DOMAIN}`, reverse proxy to `agent:8000`, security headers; the MCP ports are never proxied.
- [ ] `deploy/prod/.env.prod.example`: every variable above with placeholders only (`CHANGE_ME`, `openssl rand -hex 32` comments), `LLM_PROVIDER=anthropic`, low `LLM_DAILY_BUDGET_USD`, `DEMO_DOMAIN`.
- [ ] `docs/deploy.md`: VM spec (4 vCPU, 16 GB RAM), firewall allowing 22, 80, 443 only, Docker install, fresh secrets, Anthropic console spend limit, Langfuse Cloud keys, bring-up order, seed/load/ingest on the VM and one close run per month so viewers see results, rotating `config/users.yaml` hashes (owner step), logins (`demo` for viewers; `asha`/`ravi` shared privately), backups, teardown, and a "Reviewer path" section: `git clone --recurse-submodules`, `cp .env.example .env`, `make up erp-reset seed load ingest`, then `make run-agent`.

## Acceptance (human-readable)

- The compose file validates and only caddy publishes ports. Anything else on a published port fails G5.
- No real secret, domain-specific credential or real IP in the repo.
- Owner steps (not run by the worker): provision the VM, set DNS, put real secrets in the VM's `.env`, rotate user hashes, run the closes, and confirm the demo URL loads over HTTPS with the demo login and that a fresh clone reaches the same state by following `docs/deploy.md` alone.

- Provisioning the actual VM, DNS, the Anthropic console limit.
- README (CC-1202).
