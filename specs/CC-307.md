# CC-307 · Suite CLI and reset

## Goal

Provide `make erp-reset seed SUITE=suite-v1` to rebuild everything from scratch, identically every time.

## Context

- Ticket: `docs/implementation-tickets.md`, section `CC-307`.
- Reset restores the clean database backup taken in CC-303 (`clean-bootstrap-database.sql.gz`).
- Phase 1 builds against `suite-skeleton` (1 company `sharma`, evaluated month `2026-09`, clean control `2026-08`, 3 planted `unrecorded_bank_charge` errors, `--small`).
- Phase 2 expands to `suite-v1` with 40 errors across two companies.
- Regulated: domain data engineer builds the CLI and reset; owner approves the spec and diff.

## Subtasks

- [ ] **Scenario definition files (`evals/scenarios/`):**
  - `evals/scenarios/suite-skeleton.yaml`: Phase 1 scenario config.
  - `evals/scenarios/suite-v1.yaml`: Phase 2 scenario config.
- [ ] **CLI Subcommands (`cmd/seed/`):**
  - Implement `seed plant`: runs error planter on a company-month and writes ground truth JSON.
  - Implement `seed all`: runs bootstrap, books, evidence, and ground truth for all evaluated and clean months in the suite.
  - Support `--small` flag across subcommands.
- [ ] **Reset target (`Makefile`):**
  - `make erp-reset` restores `sites/erp.localhost/private/backups/clean-bootstrap-database.sql.gz`.
- [ ] **Tests (`cmd/seed/main_test.go`):**
  - Tests for `seed plant` and `seed all`.
  - Idempotent and reproducible runs.

## Acceptance (human-readable)

- Two consecutive reset-and-seed runs produce byte-identical bank CSVs, GSTR-2B files, and ground truth (`diff -r` is empty).
- `cmd/seed plant` and `cmd/seed all` exit with code 0.
- All gates G1-G3, G5-G6 pass.
