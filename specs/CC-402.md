# CC-402 · Bank statement loader

## Goal

`go run ./cmd/load bank --company sharma --month 2026-09` loads that month's CSV into `bank_lines`.

## Context

- Ticket: `docs/implementation-tickets.md`, section `CC-402`.
- Shared specs: `Bank statement` CSV format and `bank_lines` Postgres table.
- Plan row: Phase 1, implementer, risk data-sensitive, gates G1-G3, G5.
- Handles untrusted CSV input from bank statements: validates headers, line numbers on parse errors, parses dates and signed paise amounts.
- Derives `txn_id` if empty from transaction date and row order.
- Performs balance continuity verification with the previous month's closing balance.

## Subtasks

- [ ] **Bank Statement Parser (`internal/evidence/bank.go`):**
  - Parse CSV using `encoding/csv` with the exact shared-spec header (`txn_id,date,value_date,narration,ref,withdrawal,deposit,balance`).
  - Validate each row: date in `2006-01-02`, optional value_date, non-empty narration, optional ref.
  - Require exactly one of withdrawal and deposit set, parsed via `money.ParseRupees`.
  - Derive `txn_id` if empty as `TXN-<YYYYMMDD>-<seq>`.
  - Return detailed row-level errors with line numbers.
- [ ] **Database Loader & Continuity Check (`internal/evidence/bank.go`):**
  - In a transaction, upsert parsed rows to `bank_lines` via `store.Store`.
  - Track count of inserted, updated, and rejected rows.
  - Check that the first transaction's opening balance (`balance - amount`) matches the previous month's closing balance if present, warning if there is a mismatch.
- [ ] **CLI (`cmd/load/`):**
  - Implement `bank` subcommand accepting `--company`, `--month`, optional `--file` and `--data-dir`.
  - Connect to database via `store.Open(ctx, cfg.DatabaseURL.Reveal())`.
  - Print JSON summary of load results (inserted, updated, rejected, warnings).
- [ ] **Unit & Integration Tests (`internal/evidence/bank_test.go`, `cmd/load/main_test.go`):**
  - Test valid CSV parsing and derived txn IDs.
  - Test malformed rows: missing header, both withdrawal and deposit set, neither set, invalid amounts.
  - Test idempotent reload: loading the same file twice produces 0 inserts and leaves table unchanged.
  - Test sum of amounts equals closing balance minus opening balance.

## Acceptance (human-readable)

- Loading the same file twice leaves the table unchanged.
- The sum of amounts equals the closing balance minus the opening balance for every seeded month.
