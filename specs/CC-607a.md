# CC-607a · Variance cites only purchase invoices it read

## Goal

A variance finding may cite `list_purchase_invoices` evidence only if the variance step itself read those invoices, so the workflow can annotate the finding with a stored snapshot.

## Context

- Found 2026-10-12 recording `suite-v1` with all detectors (first run of the Phase 2 checks on real seeded data). All 7 months ended `failed` in step `check.variance`: `agent: annotate finding <id> (variance) evidence 2 (books__list_purchase_invoices): agent: no snapshot for evidence ref`. The other detectors ran and produced findings (5 to 26 per month).
- Why: `varianceEvidence` (`internal/checks/variance.go:164-197`) adds a ref `list_purchase_invoices {company, month}` naming the `VoucherNo` of every Purchase Invoice GL entry on the account. But the variance step only calls `TrialBalance`, `AccountHistory` and the GL entries reader; it never calls `PurchaseInvoices`. Each check step snapshots only its own tool calls, so there is no `list_purchase_invoices` snapshot for the ref. `suite-skeleton` has no purchase-invoice vouchers on variance accounts, so CC-607's tests and Gate B never exercised it.
- How refs are matched (`internal/agent/snapshot.go`, `snapshotCall.supports`): every ref arg must be a recorded call arg, an indexed result key, a month that the call's `from_date..to_date` window covers, or a descriptive arg; and **every ID in the ref must be a record in that call's result**.
- Do not change the `internal/agent` snapshot rules or the workflow. The one allowed edit there is the test `TestSnapshotAnnotateVarianceInvoiceRef` in `internal/agent/snapshot_test.go` (~line 729): it asserted the old bug (Annotate returns `ErrNoSnapshot` for a variance-only step citing invoices). After this fix the variance step reads the invoices itself, so update it to expect `Annotate` to succeed on the first call, with the artifact set; keep the rest of its intent.

- [ ] Cite an invoice ref only for `VoucherNo` values that appear in that result, with the same `{company, month}` args (the `month` rule accepts it because the call window covers the month). If none of the account's invoice vouchers are in the result, add no invoice ref.
- [ ] Keep the existing limits (`varianceMaxInvoices`, sorted IDs) and the evidence order.
- [ ] Do not read invoices when no account is flagged, so a month with no variance findings makes no extra call. Read once per run, not per account.
- [ ] Tests: a finding whose vouchers are in the result keeps its ref; a voucher absent from the result is dropped; no flagged account means `PurchaseInvoices` is never called; a `PurchaseInvoices` error fails the check. Update the fake reader where a test now needs the call.
