# CC-401 · Postgres migrations and store package

## Goal

The database schema from the shared specs, applied by versioned migrations, with a small typed query layer and connection pool on top.

## Context

- Ticket: `docs/implementation-tickets.md`, section `CC-401`.
- Shared specs: Postgres schema (`companies`, `bank_lines`, `gstr2b_entries`, `close_runs`, `findings`, `journal_proposals`, `audit_log`, `doc_chunks`).
- Plan row: Phase 1, implementer, risk data-sensitive, gates G1-G3, G5.
- Uses Goose for SQL-based migrations and pgx v5 with `pgxpool`.
- Vector embeddings use `pgvector` with 384 dimensions (for `bge-small-en-v1.5`).

## Subtasks

- [ ] **Migrations (`migrations/`):**
  - `0001_evidence.sql`: `companies`, `bank_lines`, `gstr2b_entries` tables with foreign keys and composite primary keys.
  - `0002_runs.sql`: `close_runs`, `findings`, `journal_proposals`, `audit_log` tables.
  - `0003_docs.sql`: `vector` extension, `doc_chunks` table with `hnsw` cosine index and `gin` tsvector index.
- [ ] **Makefile:**
  - `make migrate` runs `goose -dir migrations postgres "$DATABASE_URL" up`.
- [ ] **Typed Query Layer (`internal/store/`):**
  - `store.go`: `Store` wrapping `*pgxpool.Pool`, `Open(ctx, url)`, `Close()`, `WithTx(ctx, fn)`, `Migrate(ctx, dir)`.
  - `companies.go`: `Company` model, upsert, list, and profile seeding (`SeedCompaniesFromProfiles`, `SeedCompaniesFromDir`).
  - `evidence.go`: `BankLine` and `GSTR2BEntry` models and batch insert / query functions with exact `money.Paise`.
  - `runs.go`: `CloseRun`, `Finding`, `JournalProposal`, `AuditLogEntry` models and queries.
  - `docs.go`: `DocChunk` model, insert, chunk deletion, and vector similarity search using `pgvector-go`.
- [ ] **Integration Tests (`internal/store/store_integration_test.go`):**
  - Tagged `//go:build integration`.
  - Runs against `pgvector/pgvector:pg17` (via testcontainers or existing DATABASE_URL).
  - Verifies migration execution and idempotent re-runs.
  - Round-trips rows across every table group.
  - Verifies company seeding from shipped profiles in `config/companies`.

## Acceptance (human-readable)

- `make migrate` on an empty database creates every table and index; running it again is a no-op.
- Integration tests pass locally and in CI.
