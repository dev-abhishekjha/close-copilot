# CC-709 · Runtime data plane: steps, artifacts, LLM calls and resume

## Goal

Every workflow step, tool-result snapshot, prompt and response is stored, so a crashed run resumes without repeating work and any finding can be rebuilt for audit (invariant CC-709 in CLAUDE.md).

## Context

- **Ticket:** `docs/implementation-tickets.md`, section `CC-709`. Shared spec: "Runtime data plane (CC-709)". The three tables there are the contract; copy them exactly into a goose migration (`-- +goose Up` / `-- +goose Down`, like `migrations/0002_runs.sql`).
- **Scope split with CC-703.** The close workflow (CC-703) depends on this ticket, so it doesn't exist yet.
  - **In this ticket:** the store primitives and the reader and provider decorators, plus a resume test driven by a small test-only workflow, in `resume_integration_test.go`.
  - **CC-703:** `cmd/agent resume <run_id>` and the real `kill -9` Gate B check. The orchestrator has noted this for CC-703's spec.
- **Steps (`internal/store/steps.go`):**
  - `Begin(ctx, runID, kind, subject) (Step, bool, error)` uses the ticket's `INSERT ... ON CONFLICT (run_id, kind, subject) DO UPDATE ... WHERE status <> 'done' RETURNING id, attempt`. No row back means the step is done: return `done=true` and the existing step.
  - `Finish(ctx, stepID, status, outputRefs, errText)` sets `finished_at`. `FinishWithFindings(ctx, stepID, outputRefs, findings)` inserts the findings and marks the step `done` **in one transaction**, so a resume can't duplicate them.
  - Reuse the insert logic behind `CreateFindings` (`internal/store/runs.go`) through an unexported helper that takes a `pgx.Tx`. Put that helper in `steps.go`; don't edit `runs.go`.
  - The `kind` values come from the shared spec. Validate them, along with the `status` enum.
- **Artifacts (`internal/store/artifacts.go`, `canonical.go`):**
  - `Canonical(v any) ([]byte, error)`:
    1. marshal;
    2. decode with `UseNumber` into `any`;
    3. re-marshal, which sorts map keys and leaves no whitespace.
    - Numbers stay exact, with no float path (`nofloat` applies).
  - `PutArtifact(ctx, kind, runID, stepID, v) (sha string, err)` hashes the canonical bytes (lowercase hex sha256) and inserts with `ON CONFLICT (sha256) DO NOTHING`.
  - `GetArtifact(ctx, sha)` re-canonicalises the stored jsonb and checks that it hashes back to `sha`. A mismatch is an error, so tampering or drift is caught.
  - Validate `kind` against the shared enum.
- **Snapshot readers (`internal/agent/snapshot.go`):**
  - Decorators over `checks.BooksReader` and `checks.EvidenceReader`. They work with any reader: MCP (CC-702) or a fake.
  - Each reader call stores its result as a `tool_result` artifact. The content is `{server, tool, args, result}`, where `tool` is the MCP tool name and `args` the arguments as the check's `EvidenceRef` records them. The decorator records the hash.
  - After a check step, `Annotate(findings)` fills every `EvidenceRef.Artifact` from the recorded calls, matching on server, tool and canonical args.
  - **Fail closed:** a ref with no matching snapshot is an error, never an empty `Artifact`. Look at how `internal/checks/bankrec.go` builds its refs, and make the matching fit them without changing `internal/checks`.
  - The agent only stores hashes and passes them on; it never decodes `content` (shared spec).
  - Keep `internal/agent` free of `internal/frappe`, transitively (the `noerpimport` analyzer).
- **Recording provider (`internal/agent/llmrecord.go`):**
  - Wraps `llm.Provider`. Per `Complete`, it stores a `prompt` artifact (the full `llm.Request`, canonical) and a `response` artifact, then inserts one `llm_calls` row with model, tokens, cost and latency.
  - The model call itself is never repeated or retried by the wrapper.
  - If the provider returns an error with a usable `Response` (for example `ErrUnpricedModel`), still record it, then return the error.
  - Give `store` an `InsertLLMCall` in `artifacts.go`.
- **Privacy:**
  - Prompts and responses are stored verbatim. Pseudonymisation happens before the call (CC-710, later), so this layer stores what the model saw.
  - Never log artifact content.
  - Retention is an open question in the plan. Don't add deletion.
- **Tests:**
  - Integration tests use testcontainers Postgres with the migrations, as `internal/store/store_integration_test.go` does.
  - Unit tests in `internal/agent` use fakes for the store, behind small interfaces declared in `snapshot.go` and `llmrecord.go` and satisfied by `*store.Store`.
  - Synthetic data only.
- No new dependencies.

## Subtasks

- [ ] `migrations/0004_steps.sql`: the three tables from the shared spec, plus a Down migration.
- [ ] `store/steps.go`: `Begin`, `Finish`, `FinishWithFindings`, `GetStep`, `ListSteps(runID)`.
- [ ] `store/canonical.go` and `store/artifacts.go`: `Canonical`, `PutArtifact`, `GetArtifact` with hash verification, `InsertLLMCall`.
- [ ] `agent/snapshot.go`: `SnapshotBooks`, `SnapshotEvidence` and `Annotate`.
- [ ] `agent/llmrecord.go`: `RecordingProvider`.
- [ ] Tests:
  - **canonical:** key order, nested maps, big integers beyond 2^53 exact, and the same value giving the same hash.
  - **steps:** a second `Begin` on a done step returns `done`; a failed step is re-begun with `attempt` + 1; two concurrent `Begin` calls give exactly one running row; `FinishWithFindings` rolls back the findings when marking the step fails.
  - **artifacts:** a duplicate `Put` gives one row; `Get` of tampered content fails.
  - **snapshot:** every finding ref gets an existing artifact; an unmatched ref errors.
  - **recording:** one `llm_calls` row per call, with both artifacts present, including on the unpriced-model error.
  - **`TestResume`:** a test workflow of N steps (checks over fake readers through the snapshot decorators). Cancel after k steps, then re-run. Assert no duplicate `run_steps` or findings, `attempt` counts as expected, and findings identical to an uninterrupted run once IDs are ignored.

## Acceptance (human-readable)

- A resumed run finishes with no duplicate steps or findings (the test-workflow version; the real `kill -9` check is in CC-703).
- Every finding's `EvidenceRef.Artifact` exists and verifies, and every LLM call has prompt and response artifacts plus an `llm_calls` row.
- G6 (the orchestrator's full-diff review during the build phase): the migration matches the shared spec, and nothing logs artifact content.
