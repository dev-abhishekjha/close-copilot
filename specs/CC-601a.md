# CC-601a · Decouple checks and store from the ERPNext client

## Goal

`internal/checks` and `internal/store` no longer depend, directly or transitively, on `internal/frappe`, `internal/books` or `internal/seed`. The agent (CC-702 onwards) can then use checks and the store without breaking the invariant "`internal/agent` never imports `internal/frappe`". The `noerpimport` analyzer enforces that invariant transitively since CC-005.

## Context

- **Why now:** `go list -deps ./internal/checks` includes `internal/frappe`, `internal/books` and `internal/seed`; `./internal/store` includes `internal/seed`, which imports `internal/frappe`.
  - CC-702 puts MCP-backed readers in `internal/agent`, implementing `checks.BooksReader`.
  - CC-703 runs the checks from `internal/agent/workflow.go`.
  - CC-709 puts `internal/agent/snapshot.go` on the store.
  - All of these would fail `noerpimport` today. This ticket was added on 2026-10-10 by the orchestrator under the owner's build-phase delegation.
- **A pure refactor. No behaviour changes.**
  - Move types and pure functions. The old packages keep **type aliases** (`type GLEntry = ledger.GLEntry`) and thin forwarding functions or vars, so existing callers compile unchanged.
  - Every existing test passes, with at most import-path edits in the declared test files.
- **New `internal/ledger`** (imports only `internal/money` and the standard library):
  - From `internal/frappe/models.go`, the **domain** structs: `Account`, `GLEntry`, `Supplier`, `Customer`, `PurchaseInvoice`, `PurchaseInvoiceItem`, `PurchaseTaxesAndCharges`, `SalesInvoice`, `SalesInvoiceItem`, `SalesTaxesAndCharges`, `PaymentEntry`, `PaymentEntryReference`, `JournalEntry`, `JournalEntryAccount`, plus any constants they need.
  - The `*Raw` types, their `Domain()` conversions and everything that talks HTTP stay in `internal/frappe`. `Domain()` returns the ledger types (via the aliases).
  - From `internal/books`: `TB`, `TBRow`, `TBTotals`, `MonthTotal`, `RecurringSupplier`, and the pure `RecurringSuppliers` function (CC-502 moved it into books).
  - `books` keeps aliases and a forwarding `RecurringSuppliers`. `TrialBalance`, `AccountHistory`, the ledger interface and the tools stay in `books`.
- **New `internal/company`** (no import of frappe, books or seed):
  - From `internal/seed/profile.go`: `Profile` and its nested types, `Rules` and its nested types, `Range`, `Day`, `BasisPoints`, `Share`, `LoadProfile`, `LoadProfiles`, `LoadRules` and the profile validation.
  - Also the GSTIN/PAN helpers those need (from `internal/seed/gstin.go`, or wherever `GSTIN`, `PAN`, `ValidGSTIN` and the entity constants live; move only what the profile code needs).
  - `seed` keeps aliases and forwarding functions, so the seeder and its tests are untouched.
  - If a helper is also used by the seeder's generators, leave a forwarding func in `seed`.
- **`internal/store/companies.go`:** `SeedCompaniesFromProfiles` takes `[]company.Profile` (identical type through the alias) and `SeedCompaniesFromDir` uses `company.LoadProfiles`. `store` must not import `seed`.
- **`internal/checks`:**
  - `BooksReader` and `EvidenceReader` use `ledger` types (and `store` types for evidence).
  - `checks.Rules` aliases `company.Rules`, and `BankAccountsFor` takes `company.Profile`.
  - Move `DirectBooks` and `CompanyDirectory` into a new subpackage, `internal/checks/direct` (`direct.Books`), which may import frappe and books.
  - `DirectEvidence` stays in `checks`, since the store becomes frappe-free.
  - Update the checks tests' imports; their assertions don't change.
- **Graph:** add this ticket to `tasks/graph.yaml` (phase 1, integration-engineer, standard, `depends_on: [CC-601, CC-502]`, these files, check "checks and store have no ERPNext client dependency") and add `CC-601a` to `CC-702`'s `depends_on`. `go run ./gates/cmd/graph check` must pass.
- `nofloat` covers these packages; move code as it is.
- No new dependencies.

## Subtasks

- [ ] Create `internal/ledger` and `internal/company` with the moved code and doc comments (`// Built in CC-601a.` in each package doc).
- [ ] Aliases and forwarding functions in `frappe`, `books` and `seed`. No caller outside the declared files needs editing. If one does, stop and report it.
- [ ] `store` imports `company`, not `seed`.
- [ ] `checks` imports only `ledger`, `company`, `store`, `money`, `config` and the standard library (plus `x/sync`); `DirectBooks` moves to `internal/checks/direct`.
- [ ] **`TestNoERPClientDependency`** in `internal/checks`, `internal/store`, `internal/ledger` and `internal/company`:
  - run `go list -deps <pkg>` through `os/exec`, using the test's own `go` from `runtime.GOROOT()/bin/go`;
  - fail if any of `internal/frappe`, `internal/books` or `internal/seed` appears;
  - one shared helper is fine, a small `_test.go` per package.
- [ ] The graph entry for CC-601a and CC-702's new dependency: deferred to the owner (the permission classifier denied the edit). The orchestrator orders CC-702 after CC-601a by hand.
