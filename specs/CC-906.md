# CC-906 · Benchmarks: the trade-off write-up

## Goal

Measured answers to the design questions interviewers ask, written up in `docs/benchmarks.md`: four tables with real numbers and a decision under each.

## Context

- Ticket: docs/implementation-tickets.md, section `CC-906` (you need not open it; the subtasks are below).
- Plan row: phase 3, EVL, standard, depends on CC-905, CC-804, CC-907. Check: "Four tables with a decision under each".
- Ticket description: each benchmark is a small variation of the eval run, so the cost is mostly compute time and a few dollars of tokens.
- The four benchmarks (ticket subtasks, verbatim):
  1. Workflow only (`--no-agent`) against workflow plus investigator: investigation accuracy, cost and time.
  2. RAG against putting the whole policy manual and the company's contracts in the prompt: citation accuracy, faithfulness, tokens and cost per finding.
  3. Retrieval modes from CC-804: recall@5 for vector only, hybrid, hybrid plus rerank.
  4. Fast model against strong model for explanations: faithfulness and cost.
  Then: one table per benchmark, then a short "what I chose and why" paragraph.
- Env: `LLM_MODEL_FAST=haiku`, `LLM_MODEL_STRONG=sonnet`, `LLM_PROVIDER=claude-cli` is the default (no API key). `eval run --model-fast X` overrides the fast model for one run. Pricing comes from `config/pricing.yaml` (`eval score --pricing`).
- Eval CLI (cmd/eval/main.go header): `eval run --suite S [--only company:month] [--model-fast X] [--no-llm|--no-agent] [--record|--replay] [--fixtures-dir D] [--results-dir D]`; `eval score <results-dir> [--citations evals/golden/citations.yaml] [--fixtures-dir D] [--out D]`; `eval refusal ...`. Replay needs `DATABASE_URL` only; with the agent on it also needs `PSEUDONYM_KEY` (64 hex digits). `make eval-replay` is the no-model path.
- Golden retrieval set (CC-907, committed): `evals/golden/retrieval.yaml`, 60 queries; items look like `{id: R07, query, company, expect: [{doc_id, section}]}` and `expect: []` marks a tenant-boundary query (correct result: no hit from another company). Read it, never edit it.
- Token budget rule (CLAUDE.md): while building, run evals without the model unless a benchmark needs one. Benchmarks 1, 2 and 4 need the model; limit each to the smallest run that gives a stable number (suite-skeleton or one `--only` month), note the run count, and respect `LLM_DAILY_BUDGET_USD` (do not raise it). Tier-2 verified_rate is unstable (0/8 to 3/8 on identical code): run each model benchmark at least twice and report the range, not one number.

## Acceptance (human-readable)

- The file has four `## Benchmark N` sections, each with a table of real numbers (measured on this machine, with the run count and date) and a `**Decision:**` line.
- Every number can be traced to a command and run directory recorded in the section; nothing is estimated or copied from a plan.
- Model-run benchmarks show a range over at least two runs.
- No change outside `docs/benchmarks.md` is committed (the last acceptance command checks the protected and code paths against `main`).

- Changing code, golden sets, scenarios or the baseline; a `baseline-update` commit; new CLI flags or a benchmark command.
- Tuning anything (that is CC-1104, which depends on this ticket's numbers).
