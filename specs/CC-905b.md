# CC-905b · Eval runs the Phase 2 detectors on suite-v1

## Goal

`cmd/eval run` runs every detector (`agent.DefaultChecks()`) on `suite-v1`, so the score measures them, while `suite-skeleton` keeps running bank reconciliation only.

## Context

- Found at the first Gate C replay (2026-10-12): `suite-v1` scored recall 6/40. Only `check.bankrec` ran. `cmd/eval/main.go` builds `agent.Workflow` without `Checks`, and a nil `Checks` means bank reconciliation only (`internal/agent/workflow.go:285-288`).
- That default is deliberate (CC-608, owner decision 2026-10-11): the recorded `suite-skeleton` fixtures cover only bankrec, and a wider default breaks `--replay` on them. `cmd/agent/main.go:148` sets `Checks: agent.DefaultChecks()` explicitly. Do not change the `Workflow.Checks == nil` meaning or `internal/agent`.
- `suite-v1` has 7 evaluated months (sharma 06 to 09, mehta 07 to 09). Its recorded fixtures must contain what every detector reads. The current `evals/fixtures/suite-v1/` is bankrec-only and is **not committed**; the owner re-records after this merges.
- Replay never falls through to a live reader. A check that reads something unrecorded fails with `ErrFixtureMissing` naming the tool and arguments. That is the intended signal; don't weaken it.
- Checks run in `DefaultChecks()`'s fixed order (variance last, because it links to findings stored earlier). Don't reorder.

## Code map

- `cmd/eval/main.go:~150-200`: builds `agent.Workflow{Store, Profiles, Rules, Config, ResultsDir, Log}`; add `Checks` here.
- `cmd/eval/args.go:149-150`: flag registration (`--no-agent`/`--no-llm`); add `--checks` next to it.
- `internal/evals/result.go:91`: `Flags` (recorded in the manifest); add the field here.
- `internal/agent/workflow.go:365`: `DefaultChecks()`.
- Tests to copy: `cmd/eval/args_test.go` (`TestRunArgs`), `cmd/eval/replay_test.go`.
- Do not open `docs/` or the rest of `internal/agent`.

## Subtasks

- [ ] `--checks bankrec|all` on `eval run`. Default: `all`, except for the suite named `suite-skeleton`, whose default is `bankrec`. Put the choice in one small tested function `checksFor(suite, flag)`; an unknown value is a usage error. No other suite name is special-cased.
- [ ] `all` sets `Workflow.Checks = agent.DefaultChecks()`; `bankrec` leaves it nil.
- [ ] Record the resolved value in the manifest as `flags.checks` (`evals.Flags`, `json:"checks,omitempty"`), and print it in the run's start log line. `--record` and `--replay` use the same resolution, so a recording and its replay agree by default.
- [ ] `--replay` with `--checks` different from what the fixtures index recorded is allowed (the missing-fixture error already protects it), but the index's recorded checks, if the index has such a field, must not be required to exist; do **not** change the index format.
- [ ] Tests: `TestChecksFor` (suite-skeleton defaults to bankrec, any other suite to all, explicit flag wins, bad value errors); `TestRunArgs` rows for `--checks`; a manifest test that `flags.checks` round-trips; a replay test showing `suite-skeleton` still replays with its committed fixtures under the default.

## Acceptance (human-readable)

- The unit tests above pass, and `suite-skeleton` replay (existing CI job) still passes unchanged.
- Owner step after merge (live, needs the stack up): re-record `suite-v1` (`make record-fixtures SUITE=suite-v1`), then `make eval-replay SUITE=suite-v1`. The per-type score now has findings for the Phase 2 types. Misses are expected and become detector tickets; this ticket does not fix detectors.
