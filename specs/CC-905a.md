# CC-905a · Recorder: prime the month's trial balance inside the run scope

## Goal

`make record-fixtures` must work against the real, scoped MCP servers: the `After` hook that primes each month's trial balance has to make its call inside a run scope, not outside one.

## Context

- Found 2026-10-12 recording `suite-v1`. Every month's close passes, then `ScopedCloser` (`internal/evals/fixtures.go:175`) calls `After` (`rb.PrimeMonth`, wired in `cmd/eval/main.go:182`) with the caller's original `ctx`. That context carries no run scope, so the request goes out with the discovery scope, and the books server refuses it: `books tool: call outside the run scope refused  tool=get_trial_balance`. The recorder treats any live error as fatal (`Recorder.err`), so all later months fail and no fixtures are written.
- CC-905's integration test (`fixtures_integration_test.go`) uses unscoped test servers, so it never hit this.
- Scope rules (CC-506, `internal/mcpkit/scope.go`): `Window(company, runID, month, exp)` gives company + `month-12 months .. month-end+1 month`. `Mint(key, scope)` signs it. `agent.WithRunScope(ctx, header)` (`internal/agent/registry.go:626`) puts it on a context. The workflow does exactly this per run in `scopeRun` (`internal/agent/workflow.go:508`). With an empty `MCP_SCOPE_KEY` it leaves the context unchanged (unscoped test servers); keep that behaviour.
- `PrimeMonth` (`fixtures.go:515`) calls `TrialBalance(company, monthStart, monthStart+1month-1day)`, the same range the workflow's preflight reads, so on a good run it normally records nothing new. It exists so a no-model recording still serves a Tier 2 replay.
- Never loosen the servers: no change under `internal/mcpkit`, `internal/books` or `cmd/mcp-*`. The scope must be minted by the caller.

## Code map

- `internal/evals/fixtures.go:165-184`: `ScopedCloser` and its `After func(ctx, company, month) error`.
- `internal/evals/fixtures.go:515`: `PrimeMonth`.
- `cmd/eval/main.go:182`: where `After: rb.PrimeMonth` is set; `cfg.MCPScopeKey` is available there.
- `internal/agent/workflow.go:499-521`: `scopeRun`, the pattern to copy (mint a `Window` scope, `WithRunScope`).
- `internal/mcpkit/scope.go:101,159`: `Window`, `Mint`. Run IDs must match `^[A-Za-z0-9._:-]{1,64}$`.
- Tests to copy: `internal/evals/fixtures_test.go:611` (`TestScopedCloser`), `cmd/eval` tests.
- Do not open `docs/` or the rest of `internal/agent`.

## Subtasks

- [ ] In `cmd/eval`, wrap `rb.PrimeMonth` so it runs under a freshly minted run scope for that company and month: run ID like `eval-prime-<uuid>`, short expiry (a few minutes), `mcpkit.Window` + `mcpkit.Mint` with `cfg.MCPScopeKey`, `agent.WithRunScope`. With an empty key, pass `ctx` through unchanged. Put the wrapper in a small tested function.
- [ ] A scope error must still abort the recording; only a successful call may be recorded. No silent skip.
- [ ] Skip the live call when the month's trial balance is already recorded by the close (idempotent `PrimeMonth`), if the recorder can tell cheaply. Optional; do it only if it stays simple and tested.
- [ ] Unit tests: `TestPrimeScope` (the wrapper mints a scope whose company and window match the month, the scope reaches the callee's context, an empty key passes `ctx` through, a bad month or key returns an error) and a `TestPrimeMonth` row showing a refusal still aborts the recording.
- [ ] Extend the integration test to run against a scoped fake server if the fake supports it; otherwise note that in the PR summary.
