# CC-017 · Loader that replaces a period's evidence, and `make load` that works

## Goal

`make load SUITE=suite-v1` loads every company-month the suite seeded, and loading a month leaves exactly the rows its file holds.

## Context

- Found 2026-10-12 re-recording `suite-v1` (full write-up: `tasks/cc-013-diagnosis.md`, symptom 2).
- **Bug 1.** `Makefile:109-115` runs `go run ./cmd/load --suite $(SUITE)`, but `cmd/load` has only the subcommands `bank` and `gstr2b` (`cmd/load/main.go:30-41`), each with `--company --month [--file] [--data-dir]`. The target fails with `flag provided but not defined: -suite`.
- **Bug 2.** `store.UpsertGSTR2BEntries` (`internal/store/evidence.go:200`) and `store.UpsertBankLines` (`:52`) only insert or update. Rows of the same period that the new file lacks stay. A `--small` load left 16 sharma 2026-08 GSTR-2B rows; the later full load added its own 20 on top; the recording held 36 and the check raised 15 false `gstr2b_missing_in_books` findings. Stale bank rows likely caused another false alarm (`BNK-20260904-001`): it vanished once the table was cleared.
- Tables: `bank_lines(company_id, txn_id, txn_date, value_date, narration, ref, amount_paise, balance_paise, source_file)` primary key `(company_id, txn_id)`; `gstr2b_entries(company_id, period, supplier_gstin, supplier_name, invoice_no, invoice_no_norm, invoice_date, ...)` primary key `(company_id, period, supplier_gstin, invoice_no_norm)`. `period` is `YYYY-MM`.
- Suite file (`evals/scenarios/<suite>.yaml`): `history_months`, `evaluated: [{company, months}]`, `clean_control`. The seeder seeds, per company in `evaluated`, `history_months` plus that company's evaluated months (suite-v1: 6 months for each of sharma and mehta; data files at `data/external/<company>/<YYYY-MM>/{bank.csv,gstr2b.json}`).

## Code map

- `cmd/load/main.go:25-41`: `newRun` dispatches `bank` and `gstr2b`; `runBank` (`:45`) and `runGSTR2B` (`:116`) parse flags, open the store with `store.Open`, call `evidence.LoadBankFile` / `evidence.LoadGSTR2BFile`, print a JSON summary. Copy this style for `all`.
- `internal/evidence/bank.go:185-226` (`LoadBank`, inside it the balance-continuity check and the upsert at line 219) and `:229` `LoadBankFile`.
- `internal/evidence/gstr2b.go:154-185` (`LoadGSTR2B`, upsert at line 178) and `:187` `LoadGSTR2BFile`.
- `internal/store/evidence.go:52` `UpsertBankLines`, `:200` `UpsertGSTR2BEntries`; both run in `s.WithTx`. Existing integration tests: `internal/store/store_integration_test.go`.
- `internal/evals/suite.go:42-60` `suiteFile`, `:83` `LoadSuite`, `Suite` (`:34`) holds only the evaluated `Months`. `evals.SuitePath(dir, name)` (`:72`) maps a name to a file and rejects anything that isn't a plain suite name.

## Subtasks

- [ ] **Replace semantics (store).** Add `ReplaceGSTR2BEntries(ctx, companyID, period string, entries []GSTR2BEntry) error`: in one transaction, `DELETE FROM gstr2b_entries WHERE company_id=$1 AND period=$2`, then insert the entries (same SQL as the upsert, without the conflict clause or keeping it). Add `ReplaceBankLines(ctx, companyID, month string, lines []BankLine) error`: delete `WHERE company_id=$1 AND txn_date >= first day of month AND txn_date < first day of next month`, then insert. Both scope the delete to exactly one company and one period, with parameters, never a table-wide delete. A line dated outside the month makes `ReplaceBankLines` return an error before any delete. An empty list still deletes the period (a reloaded empty file leaves nothing) and the loader reports it as a warning.
- [ ] **Loaders use it.** `LoadBank` and `LoadGSTR2B` call the Replace functions. `inserted` and `updated` in the summary stay (counted before the replace, as now); add `removed` (rows that were present and are not in the file). Keep the balance-continuity warning.
- [ ] **`cmd/load all --suite <name> [--data-dir D] [--suites-dir evals/scenarios]`.** Resolve the suite with `evals.SuitePath` and `evals.LoadSuite`; for each company in the suite and each month in `Suite.SeededMonths(company)` (history months plus that company's evaluated months, sorted, no duplicates), run the bank load and the GSTR-2B load, in month order so the continuity check sees the previous month. A missing file for a month is an error naming company and month, after the months already loaded are reported; do not skip silently. Print one JSON summary per company-month and a final total. Add `Suite.SeededMonths(company string) []string` in `internal/evals/suite.go` (the suite parser keeps `HistoryMonths` and the per-company evaluated months it already reads; extend `Suite` or add a field, and test it).
- [ ] **Makefile.** `load` runs `go run ./cmd/load all --suite $(SUITE)`.
- [ ] **README note.** In `evals/fixtures/README.md` "Bootstrap order": load is `make load` and now replaces each month's rows; `index.json` also pins each ground-truth file's sha256, so a change to any suite's truth makes that suite's fixtures stale; the committed suites (`suite-skeleton`, `suite-v1`) are re-recorded when their truth changes. Keep it to a few lines.
- [ ] **Tests.** Unit: `SeededMonths` (history plus evaluated, per company, no duplicates); argument errors for `all` (no `--suite`, unknown suite, a missing data file names company and month). Integration (`//go:build integration`, testcontainers Postgres like the existing ones): load a 3-row GSTR-2B then a 2-row one for the same period and see 2 rows; another company's and another period's rows are untouched; same for bank lines; a bank line outside the month errors and deletes nothing; reloading the same file twice is idempotent; the replace is atomic (a failing insert leaves the old rows).

## Acceptance (human-readable)

- The three acceptance commands pass.
- Owner check after merge: with Postgres up and a seeded `suite-v1`, `make load SUITE=suite-v1` prints 12 company-months, and `SELECT company_id, period, count(*) FROM gstr2b_entries GROUP BY 1,2` shows sharma 2026-08 as 20.
- The security review confirms every delete is parameterised and limited to one company and period.

## Out of scope

- Anything under `evals/fixtures/<suite>/`, the seeder, the checks, `docs/` (protected; `docs/mcp.md` already says `make load`), and a CLI flag to wipe tables.

## Notes

- No new dependencies. A tester must not run the loader against the owner's dev Postgres; use the integration containers.
- The replace changes behaviour for a re-run of `load bank` / `load gstr2b` too: it now removes rows the file lacks. That is the intended fix.
