# CC-001 · Build harness: specs, task graph and merge gates

## Goal

Any later ticket can be handed to a coding agent as a spec, and the gates reject a change that strays outside that spec or touches a protected path without the owner's approval.

## Context

- Ticket: `docs/implementation-tickets.md`, section `CC-001`. Plan: `docs/orchestrated-implementation-plan.md`, "Gate ladder" (G0, G1) and "Failure report".
- These programs are the measuring stick for every later PR. The owner reads every line (G6), so keep them small, plain and well tested.
- Already in the repo (CC-101): `specs/_template.md`, `tasks/graph.yaml`, `.github/workflows/ci.yml`, `.claude/hooks/guard-edit.sh` (a shell version of the declared-files rule applied at edit time; read it, but don't edit it).
- Module path `github.com/abhishekjha/close-copilot`. YAML: `go.yaml.in/yaml/v3` (already in `go.mod`). **No new dependencies.** Don't edit `internal/deps/deps.go`; CC-002 is editing it in parallel.
- There is no git remote yet. Every git comparison takes `--base <ref>` (default `main`); CI passes `origin/<base_ref>`.

## Subtasks

### Shared package `gates` (`gates/*.go`)

- [ ] `Spec`: parse the YAML front matter of `specs/<ID>.md` (between the first two `---` lines) into a struct with the template's fields: `id, title, phase, owner_role, risk, approved_by, depends_on, needs_erpnext, files, consumes, produces, acceptance, gates, budget{max_attempts,max_wall_minutes}`.
- [ ] `Graph`: parse `tasks/graph.yaml` (`tasks: [{id,title,phase,owner,risk,human_review,depends_on,needs_erpnext,phase_2_pass,files,check}]`).
- [ ] `Done(ctx, base)`: the set of ticket IDs that have a commit on `base` whose subject starts with `CC-xxx:` (`git log <base> --format=%s`).
- [ ] `InFlight(ctx, base)`: tickets in progress, from `tmp/current-task` and from local branches named `cc-<n>-*` that are not merged into `base`. For a branch, read its spec with `git show <branch>:specs/CC-<n>.md`. Skip a branch that has no spec.
- [ ] Glob matching, with one documented semantics used by every gate:
  - Patterns are slash-separated and relative to the repo root.
  - `*` and `?` match within one path segment; `**` matches zero or more whole segments.
  - A pattern ending in `/` matches everything under that directory.
  - Braces are not supported: `{` in a pattern is an error.
  - Write a small matcher; don't add a dependency.
- [ ] `Overlaps(a, b []string) bool`: true when some path could match a pattern in both sets. Be conservative: report "might overlap" as overlap. Required cases are in Acceptance.
- [ ] `Report`: the failure report `{gate, task, commit, attempt, max_attempts, verdict, blocking: [{check, message, repro, evidence}]}`.
  - Writing a blocking entry with an empty `repro` or `evidence` is a programming error: return an error and test it.
  - `verdict` is `pass` or `fail`.
- [ ] Every command:
  - Prints a one-line summary.
  - On failure, prints the report JSON to stdout and writes it to `--report <path>` when given.
  - Exits 1 on a gate failure and 2 on bad usage or I/O errors.
  - Uses `context.Context`, wraps errors with `%w` and logs with `log/slog` JSON to stderr.

### `gates/cmd/graph`

- [ ] `graph ready [--base main] [--json]` prints the tickets whose dependencies are all done and that are neither done nor in flight: ID, title, owner, risk, needs_erpnext, sorted by phase then ID.
- [ ] `graph check <path>` validates the graph:
  - IDs are unique.
  - Every `depends_on` ID exists.
  - There are no cycles.
  - `owner` is a known role or `human`/`orchestrator`, and `risk` is one of the three classes.
  - Every regulated ticket has `human_review: true`.

### `gates/cmd/ready` (G0)

`ready <spec> [--base main]` fails, with one blocking entry per problem, when any of these holds:

- [ ] The front matter doesn't parse, `id` doesn't match the file name, or a required field is empty. Required: `title, phase, owner_role, risk, files, acceptance, gates, budget`. `depends_on` may be an empty list.
- [ ] `gates` doesn't contain G1, G2 and G3, or misses G5 for data-sensitive or regulated tickets, or misses G6 for regulated tickets.
- [ ] A `files` entry uses braces.
- [ ] A `depends_on` ticket is not done on `--base`.
- [ ] The declared `files` overlap the spec of any in-flight ticket other than this spec's own ID.
- [ ] An acceptance line is not a runnable command. Strip a leading `!` and any leading `VAR=value` assignments, then the first word must resolve with `exec.LookPath`, be a path to an existing script or to a script the spec's own `files` declares (it may not exist until the ticket is built), or be a shell builtin (`test`, `[`, `cd`). Prose such as `Debits equal credits` fails.
- [ ] `risk: regulated` and `approved_by` is empty.

### `gates/cmd/declared` (G1)

`declared --spec <spec> [--base main]`:

- [ ] Collect the changed files: `git diff --name-only <base>...HEAD`, plus uncommitted and untracked files (`git status --porcelain`), excluding `tmp/`.
- [ ] Fail on any file that matches no `files` glob. Always allow `go.mod`, `go.sum` and the spec itself.
- [ ] Each blocking entry names the file. Its `repro` is the command line used; its `evidence` is the file path.

### `gates/cmd/protected` (G1)

`protected [--base main] [--labels a,b]`:

- [ ] Use the same changed-file set as `declared`.
- [ ] The protected list is a Go variable in the `gates` package:
  - `evals/golden/**`, `evals/scenarios/**`, `evals/baseline.json`
  - `gates/**`, `.github/**`, `.claude/**`, `docs/**`, `CLAUDE.md`
  - `internal/books/admin.go`, `internal/approvals/**`, `internal/mcpkit/auth*.go`
  - `config/users.yaml`
- [ ] Fail when a protected path changed and the label `approved` is absent.
- [ ] Labels come from `--labels` locally, or in CI from the GitHub event payload at `$GITHUB_EVENT_PATH` (`pull_request.labels[].name`).

## Acceptance (human-readable)

`go test ./gates/...` covers:

- **G0:** a valid spec passes. Each of these fails with the right blocking entry: an unmerged dependency, overlapping file sets with an in-flight branch, a prose acceptance line, a regulated spec without `approved_by`, braces in `files`, and an ID that doesn't match the file name.
- **G1 declared:** run against a temporary git repo (`git init` in `t.TempDir()`). A branch touching an undeclared file fails; `go.mod` and the spec are allowed.
- **G1 protected:** a branch editing `evals/baseline.json` fails without the label and passes with `--labels approved`.
- **Overlaps:**
  - `gates/*.go` vs `gates/analyzers/**` → no overlap
  - `internal/checks/**` vs `internal/checks/bankrec.go` → overlap
  - `tasks/**` vs `tasks/graph.yaml` → overlap
  - `internal/mcpkit/auth*.go` vs `internal/mcpkit/server.go` → no overlap
  - `deploy/**` vs `docs/setup.md` → no overlap
- **Report:** a blocking entry without `repro` or `evidence` is rejected.

The last two acceptance commands run on this ticket's own branch, which changes `gates/**` and `.github/**`: `protected` passes with the label and fails without it.

Owner checks (G6): read every line under `gates/` and the CI change.
