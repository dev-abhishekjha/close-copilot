# CC-903 · Faithfulness judge

## Goal

An LLM judge scores whether each finding's explanation is supported by its evidence, and the judge's agreement with the owner's hand labels is computed and reported.

## Context

- Ticket: `docs/implementation-tickets.md`, section `CC-903` (quoted below; do not open `docs/`).
- Quoted: "the verifier catches wrong numbers and citations; the judge catches subtler problems, such as a claim the evidence doesn't support or a wrong suggested action. A judge is only useful once you know its accuracy, so hand-label 20 explanations first and report agreement." Subtasks: judge prompt with a rubric: `supported` (every claim backed by evidence), `partially` (minor unsupported detail), `unsupported`; output via a forced `emit_judgement` tool with a one-line reason; use the strong model, run on all findings with explanations; labels in `evals/judge/labels.yaml`; report the faithfulness rate and the judge's agreement with the labels in `score.md`. Acceptance: `score.md` shows faithfulness and judge agreement; if agreement is under 80%, refine the rubric before trusting it.
- **The 20 labels are the owner's.** `evals/judge/labels.yaml` is protected and is written by the owner, so this ticket does not create it. Build the loader, schema and agreement calculation against a small synthetic labels file in `internal/evals/testdata/judge/`. The agreement figure on real data is produced later, once the owner commits the labels.
- Runtime rule: the judge is an LLM call and may be given retrieved or evidence text only if it has no tools beyond `emit_judgement`. Its allowlist is exactly that one tool.
- Pseudonymisation (CC-710) runs before any model call; the judge reads the stored, already pseudonymised explanation and evidence. Do not de-pseudonymise.
- While building, do not call a real model: use `llm.Fake`. No G4-tier2 run is needed; a live baseline run is the owner's.

## Subtasks

- [ ] `evals/judge/rubric.txt`: the rubric and the judge's system prompt text (embed it).
- [ ] `Judge` that, for a finding with an explanation, calls the provider with a forced `emit_judgement` tool (fields: `verdict` one of `supported|partially|unsupported`, `reason` one line) and returns a `Judgement`. Malformed output is retried once, then recorded as an error, never a guess.
- [ ] Load labels from YAML against `evals/judge/labels.schema.json`; agreement = labelled items where the judge's verdict equals the label, over labelled items; also report per-verdict counts and a confusion table.
- [ ] Render the faithfulness rate (share `supported`) and agreement in `score.md`; when agreement is under 80%, print a visible "refine the rubric" warning line.
- [ ] Tests: schema rejects a bad verdict; agreement on a synthetic labelled set; malformed judge output retried once; the judge's tool list is exactly `emit_judgement`; no network or real model.

## Acceptance (human-readable)

- `score.md` shows faithfulness and, when labels are present, judge agreement.
- Needs the owner: 20 hand labels in `evals/judge/labels.yaml` (include a few deliberately broken explanations), then a live judge run to get the real agreement figure.
