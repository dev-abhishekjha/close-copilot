# CC-202 · Frappe REST client

## Goal

`internal/frappe` gives typed, paginated and retried access to any ERPNext DocType and whitelisted method. Every later ERPNext caller (seeder, books MCP server, reports) builds on it.

## Context

- Ticket: `docs/implementation-tickets.md`, section `CC-202`. It has a worked `List[T]` and the `Query` shape; follow them.
- **The CC-201 work to reuse and improve:**
  - `cmd/probe/client.go` is a private helper this package replaces. Read it for the header format, error-body parsing and redaction.
  - `docs/erpnext-schema/` holds the real field names.
  - Keys are in `tmp/erp-keys.env` (mode 600): the bot key `ERP_API_KEY`/`ERP_API_SECRET` (Accounts User) and the seeder key `ERP_SEED_*` (Administrator). Never read `.env`; never print a secret.
- **Outbound HTTP only through `internal/httpx.New(cfg, httpx.WithTimeout(15*time.Second))`.** The CC-002 `egress` analyzer fails anything else.
- **Money:** decode JSON with `UseNumber()` so amounts arrive as `json.Number`. CC-203 converts them to paise. No floats for amounts.
- Site: `erp.localhost`, frappe and erpnext 15.122.0 with India Compliance 15.32.0, company Sharma Traders Pvt Ltd (abbr STPL). The audit trail is off, so cancelled documents can be deleted.
- This ticket holds the ERPNext lock (`needs_erpnext: true`) because the integration test writes.

## Subtasks

- [ ] **`Client`**:
  - `New(cfg config.Config, key string, secret Secret) (*Client, error)`.
  - Holds base URL, site, key, secret and the `httpx` client.
  - Every request sends `Authorization: token <key>:<secret>`, `Accept: application/json` and `Host: <ERP_SITE>`.
  - Response bodies are capped (e.g. 32 MiB).
- [ ] **`Secret` type**: `type Secret string`, with **value-receiver** `String`, `GoString`, `Format`, `LogValue` and `MarshalJSON` that all return `[redacted]`. The raw value is reachable only through one unexported accessor used to build the header. `Client` holds a `Secret`, so `%v`, `%+v`, `%#v`, `fmt.Sprint(*c)`, `json.Marshal` and slog never show it. This closes CC-201's G5 finding 1.
- [ ] **Redirects**: set `CheckRedirect` to refuse any redirect that changes scheme, host or port, returning an error. Go keeps `Authorization` across a same-host, different-port redirect, and those ports are on the httpx allowlist.
- [ ] **Generic calls**:
  - `List[T](ctx, c, doctype, Query)`: auto-paginates with `limit_start`/`limit_page_length`, page size 500. `Query.Limit` 0 means all pages. A server that ignores `limit_start` must not loop forever: stop and return an error after 10,000 pages, or when a page repeats the previous one.
  - `Get[T](ctx, c, doctype, name)`.
  - `GetMany[T](ctx, c, doctype, names)`: fetches child tables per document, at most 4 in flight. Use a semaphore and `sync.WaitGroup`, not `errgroup` (no new dependency). Results come back in input order, and the first error cancels the rest.
  - `Insert(ctx, c, doctype, doc any) (map[string]any, error)` (POST), `Update` (PUT).
  - `Submit` and `Cancel` through the whitelisted `frappe.client.submit` and `frappe.client.cancel`. The integration test proves which path works on v15; document it.
  - `Delete` (DELETE `/api/resource/<doctype>/<name>`).
  - `Call[T](ctx, c, dottedPath, params)` for `/api/method/<dotted.path>`, GET or POST as the caller chooses.
- [ ] **`errors.go`**:
  - `*APIError{Method, Path, Status, ExcType, Message}`, built from Frappe error bodies (`exc_type`, `exception`, `_server_messages`, which is JSON inside a string).
  - Drop tracebacks. Redact the secret from any text before truncating it.
  - `IsPermission(err)` is true **only** for `ExcType == "PermissionError"`, so a bare 403 from a proxy doesn't count (CC-201 G5 finding 3).
  - Also `IsNotFound` (`DoesNotExistError` or 404), `IsValidation` (`ValidationError` and its subclasses as Frappe reports them) and `IsAuth` (401/`AuthenticationError`).
- [ ] **Retries**:
  - Only idempotent calls (GET), on 429, 502, 503 and 504 and on transport errors before any response.
  - Exponential backoff with jitter (`math/rand/v2`), honouring `Retry-After` up to a cap. At most 4 attempts. Context-aware.
  - **Never retry POST, PUT or DELETE.**
- [ ] **Unit tests** against `httptest.Server`, never ERPNext:
  - `TestListPagination`: three pages, filters/fields/order_by encoding, `Limit`, and the runaway-pagination guard.
  - `TestAPIError`: a validation error, a permission error, a bare 403 without `exc_type` (not `IsPermission`), `_server_messages` parsing, traceback dropped.
  - `TestRetry`: a 503 retried then OK, `Retry-After`, giving up after 4 attempts, a cancelled context stopping retries.
  - `TestNoRetryOnWrite`: a 503 on POST and PUT is not retried.
  - `TestSecretRedacted`: the secret never appears in `%v`/`%+v`/`%#v`, `fmt.Sprint(*c)`, JSON, slog output or any error.
  - `TestRedirect`: a redirect to another port or host is refused, and the `Authorization` header is never sent there.
  - `TestGetMany`: concurrency never exceeds 4, results keep input order, and an error cancels the rest.
  - `TestIntegrationSkips`: shows the integration test's skip guard works when the env vars are missing. Or document that `-tags=integration` without the keys skips.
- [ ] **Integration test** (`//go:build integration`, file `client_integration_test.go`):
  - `t.Skip` unless `ERP_BASE_URL`, `ERP_SITE`, `ERP_API_KEY`, `ERP_API_SECRET`, `ERP_SEED_API_KEY` and `ERP_SEED_API_SECRET` are all set. CI's integration job has no ERPNext.
  - With the **bot** key: `List` at least one Account of Sharma Traders Pvt Ltd.
  - Insert a minimal balanced Journal Entry (₹1.00 between two existing STPL accounts, `user_remark: "CC-202 integration test"`), submit it, read it back with docstatus 1, cancel it, and read docstatus 2.
  - Then delete the cancelled entry. Use the **seeder** key only if the bot lacks delete rights, and say so in a comment.
  - **Cleanup runs in `t.Cleanup`**, so a failed run doesn't leave a draft or submitted entry behind. A leftover draft is deleted; a leftover submitted one is cancelled and then deleted.
  - After cleanup, assert that no Journal Entry with that remark remains.

## Acceptance (human-readable)

- The unit tests cover multi-page results, a Frappe validation error, a retried 503 and every G5 carry-over item: the secret type, redirects, `PermissionError` only, and no retry on writes.
- The integration test lists an Account and completes insert → submit → cancel → delete on the real site, leaving no Journal Entry behind.
- `go run ./gates/cmd/lint ./...` stays clean.
