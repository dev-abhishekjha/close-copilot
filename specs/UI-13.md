# UI-13 · Command palette, keyboard shortcuts, toasts

## Goal

Let a keyboard user jump anywhere in two keystrokes and let every page raise a toast or a screen-reader announcement, with one same-origin script, no inline script or style, and no CSP change.

## Context

- Ticket: `tasks/frontend-plan.md` section 6 row UI-13 (S): "Command palette (Ctrl+K), keyboard shortcuts, toasts and live-region announcements; vanilla JS file in /static". Check (`tasks/graph.yaml`): "Ctrl+K opens the palette; only same-origin script, CSP unchanged". Frontend plan section 3 puts "search / command palette (Ctrl+K)" in the top bar and section 5 requires "`aria-live` for progress and toasts, keyboard reachable everywhere, visible focus".
- **CSP is fixed** (`middleware.go:20`): `default-src 'self'; script-src 'self'; style-src 'self'; ... connect-src 'self'`. Do not edit `middleware.go`. No inline `<script>`, no `style=` attribute, no `on*=` handler, no `javascript:` URL, no `eval`, no `new Function`, no string `setTimeout`.
- **One script tag.** `layout.templ` loads `/static/js/ui.js` (defer) for signed-in pages, after htmx. Many tests pin exactly two `<script` tags on a page (`finding_test.go:662`, `:907`, `shell_test.go` `uiJSTag`). Keep that true: **extend `ui.js`; do not add a second script file or tag, and do not edit `layout.templ`.** `ui.js` is an IIFE with `"use strict"`, delegated listeners from `document`, and `TestUIScript` (`devcomponents_test.go:68`) fails the file if it contains `eval(`, `new Function`, `innerHTML`, `document.write` or `outerHTML`. Build every node with `createElement`, `textContent`, `setAttribute`; never insert HTML strings.
- **Role filtering stays on the server.** `navFor(role, path)` (`shell.go:54`) already returns only the links the route table lets the role GET (`s.allows`); the shell draws exactly those. The palette is **rendered by the server from `sd.Nav`** as a list of real links, so a link the role may not follow is never in the page, and the script only shows, hides and activates what is there. There is no JSON endpoint and no new route.
- Current shell data (`templates/shell.go`):

```go
type NavItem struct { Label, Href, Icon string; Current bool }
type NavGroup struct { Title string; Items []NavItem }
type ShellData struct {
    User, Role, CSRFToken string
    Nav []NavGroup; Companies []string; Company, Month, Path string; Health string

```

- Current nav table (`shell.go:28`): `Work`: Dashboard `/`, Close runs `/runs`, Findings `/findings`, Ask `/ask`; `Review`: Approvals `/approvals`, Proposals `/proposals`; `Reference`: Documents `/documents`, Audit log `/audit`, System `/system`. `type navEntry struct{ group, label, icon, path string }`; `navFor` builds `NavItem{Label, Href, Icon, Current}` from it.
- Existing toast pieces (UI-02): `ToastRegion()` is `<div id="ui-toasts" class="ui-toasts" role="status" aria-live="polite">`; a toast is `<div class="ui-toast ui-toast-<kind>" data-toast data-kind="<kind>">` with an icon, `<span class="ui-toast-message">`, and a `<button data-toast-dismiss>`. `ui.js` auto-dismisses non-error toasts after 6 s (a `MutationObserver` arms any `[data-toast]` added to the body) and removes one on a dismiss click. `ToastRegion` is rendered **only** on the dev components page today (`dev_components.templ:143`), so no real page has a place for toasts yet. Dialogs: `[data-dialog-open="<id>"]` calls `showModal()`, `[data-dialog-close]` closes, and a click on the `<dialog>` backdrop closes it (all in `ui.js`); styles are `.ui-dialog` and friends in `components.css` (do not edit it; put new rules in `shell.css`).
- Icons in the sprite (`static/icons.svg`): `search`, `x`, `info`, `check`, `alert`, `menu`, among others. Use `search` for the trigger. Do not edit the sprite.
- `.visually-hidden` and `.skip-link` exist (`base.css`, `shell.css`); `design_test.go` fails any template class that no stylesheet styles, and any raw colour or `style=`: use tokens from `tokens.css` only, and add every class you use to `shell.css`.

## Design

**Markup (all in `shell.templ`, inside `shellBody`, signed-in pages only; the plain frame is unchanged):**

1. In the top bar, before the context form: a trigger `<button type="button" class="shell-palette-btn" data-dialog-open="ui-palette" aria-haspopup="dialog" aria-keyshortcuts="Control+K Meta+K">` with the `search` icon, the visible text "Search or jump to…" and a `<kbd>` hint "Ctrl K". The existing delegated `data-dialog-open` handler opens it; add no extra click code for the button.
2. `<dialog id="ui-palette" class="ui-dialog ui-palette" aria-label="Command palette">` holding: an `<input type="search" id="ui-palette-input" class="ui-palette-input" role="combobox" aria-expanded="true" aria-controls="ui-palette-list" aria-autocomplete="list" autocomplete="off" spellcheck="false" placeholder="Type a page name" aria-label="Search pages and commands" autofocus>`, then `<ul id="ui-palette-list" class="ui-palette-list" role="listbox" aria-label="Pages">` with one `<li role="presentation">` per nav item containing `<a role="option" class="ui-palette-item" href="…" id="ui-palette-opt-N" data-palette-item data-group="Work|Review|Reference" [data-shortcut="g r"]>` (icon, label, the group name in a muted span, and the shortcut as `<kbd>` pairs when present), and an empty-state `<p id="ui-palette-empty" class="ui-palette-empty" hidden>No matching page.</p>`. Include a close button (`data-dialog-close`, `aria-label="Close"`). Hrefs come from the same `NavItem.Href` the sidebar uses.
3. `<dialog id="ui-shortcuts" class="ui-dialog ui-shortcuts" aria-labelledby="ui-shortcuts-title">`: a title "Keyboard shortcuts" and a definition list: Ctrl or Cmd + K "Open the command palette", `?` "Show this help", `g` then a key "Go to a page" followed by one row per nav item that has a key (Label, then its keys), `Esc` "Close a dialog". A close button with `data-dialog-close`. Opened by the `?` key and by a "Shortcuts" `<button data-dialog-open="ui-shortcuts">` at the bottom of the sidebar (`shell-side`).
4. Once per signed-in page, at the end of `<body>` content inside `.shell` (after `<main>`): `@ToastRegion()` and `<div id="ui-announce" class="visually-hidden" role="status" aria-live="polite" aria-atomic="true"></div>`. Remove `@ToastRegion()` from `dev_components.templ` (the dev page renders inside the shell now, so keeping it would duplicate `id="ui-toasts"`); the dev page keeps its static `@Toast(...)` samples, which are appended after the region, and `devcomponents_test.go` still finds `id="ui-toasts"` through the shell.

**Server side (`shell.go`, `templates/shell.go`):**

- `navEntry` gains `key string`, `NavItem` gains `Key string` (keys as a space-separated sequence, e.g. `"g d"`), copied through `navFor`. Keys (unique, lowercase letters): Dashboard `g d`, Close runs `g r`, Findings `g f`, Ask `g a`, Approvals `g p`, Proposals `g o`, Documents `g c`, Audit log `g l`, System `g s`. A role that cannot GET a route never gets its item, so never gets its key. Add a test that no two entries share a key and every key is `g` plus one letter.
- Nothing else in `ShellData` changes. Do not add a field the palette does not need.

**Script (`ui.js`, new sections inside the existing IIFE; keep the file readable, no frameworks):**

- *Palette.* Ctrl+K or Cmd+K (`ev.key.toLowerCase() === "k"` with `ctrlKey` or `metaKey`, no shift or alt), from anywhere including inputs: `preventDefault()`, then toggle `#ui-palette` (`showModal()` if closed, `close()` if open). `/` opens it too when focus is not in an editable element. On open (listen for the dialog `toggle` or the opener, whichever works in `<dialog>` without a polyfill; a `MutationObserver` on the `open` attribute is acceptable): clear the input, show every item, mark the first visible item active, focus the input. On `input`: case-insensitive substring match against the item's label, group and href path words; set `hidden` on non-matches, show `#ui-palette-empty` when none match, re-mark the first visible item active, and announce "N results" (or "No results") through `cc:announce`, throttled so a burst of keystrokes sends one announcement. Arrow Down/Up move the active item among visible items (wrapping), set `aria-activedescendant` on the input to its id and `aria-selected="true"` on it (clear the old one), and `scrollIntoView({block: "nearest"})`. Enter navigates: `window.location.assign(activeItem.href)`; a click on an item is a normal link click. Esc closes (native `<dialog>` behaviour; add nothing). Never navigate to anything that is not one of the rendered `[data-palette-item]` anchors, and read `href` with `getAttribute`, never build a URL from the input text.
- *Go-to shortcuts.* On `keydown` with no ctrl, meta or alt key, focus not in an editable element (`input`, `textarea`, `select`, `[contenteditable]`, or inside an open dialog) and no dialog open: `g` arms a 1.5 s chord; the next key looks up `[data-shortcut="g <key>"]` in the palette list and navigates to that anchor's `href`; any other key, or the timeout, disarms. `?` (shift+`/` on most layouts, test `ev.key === "?"`) opens `#ui-shortcuts`. Use `window.setTimeout` with a function, never a string. Do not `preventDefault` on keys while typing in a field, and never act on `ev.repeat` or `ev.isComposing`.
- *Toasts.* A `cc:toast` event on `document` with `detail: {kind, message}` appends a toast to `#ui-toasts` built with DOM methods in the same structure as `toastBody` (class `ui-toast ui-toast-<kind>`, `data-toast`, `data-kind`, icon via `<svg><use href="/static/icons.svg#icon-…"/></svg>` created with `createElementNS`, message in `textContent`, dismiss button with `data-toast-dismiss` and `aria-label="Dismiss"`). `kind` is checked against `info|success|error`, anything else becomes `info`; `message` is coerced to a string and cut at 300 characters. The existing `MutationObserver` arms the auto-dismiss, so do not add a second timer. Cap the region at 4 toasts: remove the oldest when a fifth is added. If `#ui-toasts` is missing, do nothing.
- *htmx errors.* On `htmx:responseError` raise an error toast "That request failed (HTTP <status>). Try again." using only the numeric `detail.xhr.status`; on `htmx:sendError` or `htmx:timeout` raise "Could not reach the server. Check your connection." Never put the response body, the URL or a header into the toast.
- *Announcements.* A `cc:announce` event with `detail: {message}` sets `#ui-announce` textContent to the message (first to the empty string, then the message on the next animation frame, so a repeated message is read again). Also announce when htmx swaps in an element carrying `data-announce="<text>"`: on `htmx:afterSwap`, find `[data-announce]` in the swapped target and announce its attribute value (no page uses it yet; UI-14's walkthroughs and later tickets can). Do not edit other pages' templates.
- `ui.js` must still work if loaded late and must do nothing when an element it needs is absent (the plain login frame never loads the script anyway).

**Styles (`shell.css` only, tokens only, light and dark come from the tokens):** `.shell-palette-btn` (outlined button that looks like a search field, `<kbd>` hint right-aligned, hidden label text below the 640px breakpoint but the button and icon stay, min target 2.5rem), `.ui-palette` (wider dialog, `max-width` about 36rem, `padding: 0`, top-anchored), `.ui-palette-input` (full width, no border radius clash, visible focus ring from the existing focus token), `.ui-palette-list` (scrollable `max-height`, no bullets), `.ui-palette-item` (flex row, icon, label, muted group), `.ui-palette-item[aria-selected="true"]` (background from a surface token plus a left border so selection is not colour alone), `.ui-palette-empty`, `.ui-shortcuts` and its list, `kbd` look. Reduce motion is respected (no new animation).

## Acceptance (human-readable)

- Press Ctrl+K (or Cmd+K) on any signed-in page: the palette opens with focus in the input; typing "aud" leaves only Audit log; arrow keys move the highlighted row; Enter goes there; Esc closes and focus returns to where it was.
- A viewer's palette lacks Approvals and Proposals if the viewer's sidebar does; it is never larger than the sidebar.
- `g` then `r` goes to Close runs; `?` opens the shortcuts list; typing `g` or `?` inside a form field does nothing special.
- Stop the server and click an htmx action: an error toast appears, stays until dismissed, and a screen reader announces it.
- Browser console on every page: no CSP violations and no script errors. Check light, dark and 420px (the trigger shows only its icon on a phone). Tab order reaches the trigger, and the dialog traps focus natively.
