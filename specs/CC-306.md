# CC-306 · Error planter and ground truth

## Goal

Apply planted errors to the right views of the true world, and write `ground_truth.json` with keys that detectors and findings match against.

## Context

- Ticket: `docs/implementation-tickets.md`, section `CC-306`.
- Shared specs: `Ground truth` schema and `Finding types` table.
- Phase 1 builds against `suite-skeleton` (1 company `sharma`, evaluated month `2026-09`, clean control `2026-08`, 3 planted `unrecorded_bank_charge` errors).
- Phase 2 expands to `suite-v1` with 40 errors across two companies (`sharma`, `mehta`).
- Regulated: domain data engineer writes the planter and truth; owner approves the spec and diff.

## Subtasks (Phase 1: suite-skeleton)

- [ ] **JSON Schema (`evals/schema/ground_truth.schema.json`):**
  - Defines the shared-specs structure: `scenario`, `company`, `month`, `clean` (boolean), `planted` (array of finding items), `expected` (array of items), and `investigations` (array of items).
  - Each planted item has `id` (`E01`, `E02`, ...), `type`, `keys` (object), and `amount_paise`.
- [ ] **Planter (`internal/seed/plant.go`):**
  - Takes a company-month `World` and scenario config.
  - Generates mutation targets reproducibly using the seeded RNG.
  - Implements `unrecorded_bank_charge`: removes the bank-charge journal from the books view so it exists in bank statement CSV but not in ERPNext ledger.
  - Never places two errors on the same event.
  - Leaves the clean control month (`2026-08`) completely unmutated (`clean: true`).
- [ ] **Ground Truth Writer (`internal/seed/truth.go`):**
  - Resolves `ExtID`s to ERPNext names using `erp_map.json` (from CC-304).
  - Emits `evals/scenarios/<suite>/ground_truth/<company>-<YYYY-MM>.json` conforming to `ground_truth.schema.json`.
  - Records gateway settlement batches under `investigations` with `expected_resolution: "gateway_settlement"`.
  - Records genuine late-filed cross-month invoices under `expected`.
- [ ] **Tests (`internal/seed/plant_test.go`, `internal/seed/truth_test.go`):**
  - `TestPlantBankCharge`: verifies the bank charge is dropped from books but preserved in bank lines.
  - `TestGroundTruthSchema`: validates generated ground truth JSON files against `ground_truth.schema.json`.
  - `TestCleanControlMonth`: verifies that a clean month has 0 planted errors and `"clean": true`.
  - `TestReproducibility`: identical seed produces byte-identical mutated world and ground truth.

## Acceptance (human-readable)

- For `suite-skeleton`: `sharma-2026-09` has exactly 3 planted `unrecorded_bank_charge` errors, and `sharma-2026-08` has 0 errors with `"clean": true`.
- Every ground-truth key points at a record that exists in ERPNext, the bank CSV, or GSTR-2B.
- The ground truth JSON strictly validates against `evals/schema/ground_truth.schema.json`.
