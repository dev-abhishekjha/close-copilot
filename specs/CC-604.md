# CC-604 · GSTR-2B matcher

## Goal

Compare the month's purchase invoices with GSTR-2B and put every invoice into one bucket; every bucket except "matched" becomes a finding whose amount is the input tax credit (ITC) at risk.

## Context

- Ticket: `docs/implementation-tickets.md`, section `CC-604` (quoted below; you need not open it).
- Plan row: Phase 2 only (the graph has no Phase 1 pass and no `phase_2_pass`; Phase 1 is bank rec on `suite-skeleton`, so nothing in this ticket belongs to the Phase 1 slice). Standard risk, implementer, depends on CC-601 and CC-403 (both merged). Gate-run acceptance from `tasks/graph.yaml`: "All six planted GSTR-2B errors in the right bucket".
- Description (ticket): build two sets keyed on supplier GSTIN plus normalised invoice number: the books' purchase invoices whose `bill_date` falls in the month (input tax per type summed from the tax rows, mapped through the GST Settings account heads), and the GSTR-2B entries for that period.
- Buckets (ticket table):

| Bucket | Rule | Finding type |
| --- | --- | --- |
| Matched | Both sides, tax within `amount_tolerance_paise` | none |
| Amount mismatch | Both sides, tax differs beyond tolerance | `gstr2b_amount_mismatch` |
| Missing in 2B | Books only, and not in the next period's 2B | `gstr2b_missing_in_2b` |
| Wrong period | Books in month M, 2B in M-1 or M+1 | `gstr2b_wrong_period` |
| Missing in books | 2B only | `gstr2b_missing_in_books` |
| Not eligible | 2B marks `itc_available` false | `gstr2b_not_eligible` |

- Finding keys (shared spec "Finding types"): `supplier_gstin` + `invoice_no_norm` for all five types. `invoice_no_norm` is `evidence.NormInvoiceNo(invoice number)`, the same function the loader used to fill `gstr2b_entries.invoice_no_norm` and the seeder used for ground truth. Ground-truth shape: `{"type": "gstr2b_missing_in_2b", "keys": {"supplier_gstin": "27AABCX1111E1ZX", "invoice_no_norm": "XYZ778"}, "amount_paise": 1800000}`. The six planted GSTR-2B errors are 2 `missing_in_2b` + 2 `amount_mismatch` + 2 `missing_in_books`. `not_eligible` is never planted. Genuine `gstr2b_wrong_period` findings from late-filed supplier invoices are listed under `expected` in ground truth (they count as correct, not false alarms); the seeder defers about 5% of registered-supplier invoices dated in M to the 2B of M+1.
- How the planter makes each error (CC-306, tickets doc): missing_in_2b = "Drop the invoice from GSTR-2B"; amount_mismatch = "Reduce the tax in GSTR-2B by 10%"; missing_in_books = "Add a GSTR-2B invoice that was never booked". The planter does not implement these yet (`internal/seed/plant.go` has only `unrecorded_bank_charge`), so the "six planted" criterion is proven here by a unit test on synthetic data shaped like the planter's output.
- Rules: `Inputs.Rules.GSTR2B.AmountTolerancePaise` (`internal/company/profile.go:180`, `int64`, `config/rules.yaml` default `100`, validated non-negative). Compare against it as `money.Paise`.
- GSTR-2B row, `store.GSTR2BEntry` (`internal/store/evidence.go:36`): `CompanyID, Period (YYYY-MM), SupplierGSTIN, SupplierName *string, InvoiceNo, InvoiceNoNorm, InvoiceDate time.Time, TaxablePaise, IGSTPaise, CGSTPaise, SGSTPaise money.Paise, ITCAvailable bool`. Primary key is `(company, period, supplier_gstin, invoice_no_norm)`. `EvidenceReader.GSTR2BEntries(ctx, company, period)` returns an empty slice with no error for a period that was never loaded.
- Books row, `ledger.PurchaseInvoice` (`internal/ledger/models.go:83`): `Name, Supplier, SupplierName, BillNo, BillDate (zero when unset), PostingDate, SupplierGSTIN, CompanyGSTIN, IsReturn, GrandTotal, Taxes []PurchaseTaxesAndCharges`. A tax row (`models.go:115`) has `AccountHead, TaxAmount money.Paise, AddDeductTax ("Add" or "Deduct"), GSTTaxType`.
- Input tax per type: mirror `gstKind`/`gstSplit` in `internal/books/tools.go:953-990` (do NOT import `internal/books`; copy the logic into an unexported helper in `gstr2b.go`). A row's GST head is its `GSTTaxType` when that is `igst`, `cgst` or `sgst` (case-insensitive; India Compliance sets it from GST Settings); when `GSTTaxType` is empty, the word `IGST`, `CGST` or `SGST` in `AccountHead` (the seeded heads are `Input Tax CGST - STPL` etc., the GST Settings input heads). Anything else (cess, RCM, TDS, freight) is ignored. A `Deduct` row counts negative. There is no GST Settings reader on `BooksReader`, so this mapping is the "GST Settings account heads" step.
- Readers return **submitted documents only and filter by `posting_date`** (`internal/checks/direct/books.go:112-125`, `submittedFilters`), not `bill_date`. ERPNext requires `bill_date <= posting_date`, so an invoice with `bill_date` in month M has `posting_date` on or after the first of M, and may be posted later. Read purchase invoices with `posting_date` from the first day of M-1 to the last day of M+1, then filter by `bill_date` yourself (fall back to `PostingDate` when `BillDate` is zero).
- Invoice-number normalisation: `evidence.NormInvoiceNo` (CC-403, merged) is the shared function; import it (`github.com/abhishekjha/close-copilot/internal/evidence`). `internal/evidence` depends only on config, company, money, store and mcpkit, none of which reach `internal/frappe`, `internal/books` or `internal/seed`, so `TestNoERPClientDependency` still passes; run it to confirm. If it does fail, stop and report instead of copying the function (a copy needs a parity test and the owner's say).

## Subtasks

- [ ] `GSTR2BCheck` (`Name()` returns `"gstr2b"`), `var _ Check = (*GSTR2BCheck)(nil)`, in `internal/checks/gstr2b.go`.
- [ ] Books set for month M: purchase invoices with `bill_date` in M (fallback `PostingDate`), not `IsReturn`, and a non-empty `SupplierGSTIN` (skip unregistered suppliers). Key = `SupplierGSTIN` + `evidence.NormInvoiceNo(BillNo)`. Tax per type (igst, cgst, sgst) from the tax rows as described in Context. If two invoices share a key, keep the first by `Name` and put all names in evidence (cover with a test).
- [ ] 2B sets: load periods M-1, M and M+1 with three `GSTR2BEntries` calls (wrap each error with `%w`). Key = `SupplierGSTIN` + `InvoiceNoNorm` (already normalised by the loader; do not renormalise).
- [ ] Also build a prior-month books set (invoices with `bill_date` in M-1, same filters) used only to suppress false "missing in books" for late filers already reported in M-1's close.
- [ ] Classify, for each key (precedence in this order):
  1. In books(M) and in 2B(M): `itc_available` false gives `gstr2b_not_eligible`; else any of IGST, CGST, SGST differing by more than `Rules.GSTR2B.AmountTolerancePaise` gives `gstr2b_amount_mismatch`; else matched (no finding).
  2. In books(M), not in 2B(M), but in 2B(M-1) or 2B(M+1): `gstr2b_wrong_period` (evidence names the 2B period it was found in). If `itc_available` is false there, still `gstr2b_wrong_period`.
  3. In books(M) and in no 2B period read: `gstr2b_missing_in_2b`.
  4. In 2B(M) only: if the key is in books(M-1) or books(M+1), it is a timing difference already reported in that month's close: no finding. If `itc_available` is false: no finding (no credit is claimable or claimed). Otherwise `gstr2b_missing_in_books`.
- [ ] Amounts (ITC at risk, `*money.Paise`, positive): `missing_in_2b`: the books' total input tax (IGST+CGST+SGST). `amount_mismatch`: the absolute difference of the two totals. `wrong_period`: the books' total input tax. `missing_in_books`: the 2B total tax. `not_eligible`: the books' total input tax. Both sides' amounts go in evidence (see below) so the explainer can quote them.
- [ ] Finding: `Keys{"supplier_gstin", "invoice_no_norm"}`; `Title` names supplier, invoice number as written and the amount (`money.Paise.Format()`); `Severity`: high for `missing_in_2b`, `amount_mismatch`, `missing_in_books` and `not_eligible`, medium for `wrong_period`; `Action`: `ActionFollowUpSupplier` for `missing_in_2b`, `amount_mismatch`, `wrong_period`, `ActionInvestigate` for `missing_in_books` and `not_eligible`; `Status: StatusOpen`. Evidence refs: books side `BooksEvidence("list_purchase_invoices", {company, from, to}, invoiceNames...)`, 2B side `EvidenceEvidence("list_gstr2b_entries", {company, period, supplier_gstin}, invoiceNoNorm)`. Put each side's tax totals in the evidence args (`books_tax_paise`, `gstr2b_tax_paise`, and the per-type values) so both amounts are in the ref, not only in the title.
- [ ] Output order deterministic: sort by finding type, then `supplier_gstin`, then `invoice_no_norm`.
- [ ] Table-driven tests (`gstr2b_test.go`, fake readers keyed by period), one row per bucket: matched (no finding); mismatch beyond tolerance; difference exactly at tolerance (matched) and one paisa above (mismatch); missing in 2B; wrong period via M+1; wrong period via M-1; missing in books; 2B-only but present in prior-month books (no finding); 2B-only with `itc_available` false (no finding); not eligible; unregistered supplier skipped; return invoice skipped; `bill_date` outside the month skipped, `bill_date` in the month with a later `posting_date` included; normalisation ("CLD/2026/0912" in books against "CLD-2026-912" in 2B is matched; `invoice_no_norm` in the finding is `CLD2026912`); tax from `GSTTaxType` and from account-head words, a cess row ignored, a `Deduct` row negative; duplicate key; each reader error wrapped with `%w` (books, and each of the three periods); a clean month returns no findings; `TestGSTR2BSixPlanted`: a month shaped like the planter's output (2 invoices dropped from 2B, 2 with tax cut by 10% in 2B, 2 2B-only rows, plus 10 matched, plus one late filer in M+1) gives exactly six findings in the right buckets with the right keys, plus the one genuine `gstr2b_wrong_period`.

## Acceptance (human-readable)

- All six planted GSTR-2B errors in a synthetic month shaped like the planter's output land in the right bucket with the right `supplier_gstin` and `invoice_no_norm` keys; a clean month gives zero findings.
- A timing difference (invoice in the next period's 2B) is `gstr2b_wrong_period`, never `gstr2b_missing_in_2b`; a late filer's invoice does not appear again as `gstr2b_missing_in_books` in the following month.
- Both sides' tax amounts are readable from each finding's evidence.
- Tests pass under the race detector and `make check` passes.

## Notes

- No new dependencies. New import inside the module: `internal/evidence` (see Context; guarded by `TestNoERPClientDependency`).
- `gates` stays at G1-G3: G4-tier1 would not exercise this check (not registered, nothing planted), so a pass would be empty. Add it once the check is registered and the suite plants the GSTR-2B errors.
- Risk: if the next period's 2B (M+1) is not loaded yet, a late filer looks like `gstr2b_missing_in_2b`. This is inherent to the data; the ticket says to look at neighbouring periods "when they are loaded". The check does not error on an empty period.
- Risk: real ERPNext data may leave `SupplierGSTIN` empty on a registered supplier's invoice; it is skipped like an unregistered one (the ticket's rule).
- The mismatch comparison is per tax type (IGST, CGST, SGST each within tolerance), so a CGST/SGST versus IGST split difference is a mismatch even when the totals agree.
