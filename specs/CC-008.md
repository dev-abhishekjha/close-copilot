# CC-008 · Create the Mehta company in ERPNext and fix seed key handling

## Goal

`make erp-reset` leaves an ERPNext that holds both suite companies, so `cmd/seed all --suite suite-v1` bootstraps both, and `make seed` gets its keys from `tmp/erp-keys.env` without touching `.env`.

## Context

- Ticket text: `tasks/hardening.md`, section `CC-008` (this ticket is not in `docs/implementation-tickets.md`).
- Found in the first Gate C attempt (2026-10-12):
  - After `make erp-reset`, `go run ./cmd/seed all --suite suite-v1` bootstrapped sharma and stopped at mehta with `company "Mehta Tech Services Pvt Ltd" does not exist in ERPNext; create it first` (`internal/seed/bootstrap.go:453`). Nothing in the repo creates a second company: `setup-wizard.sh` makes only Sharma (`STPL`) and `clean-bootstrap-database.sql.gz` is a snapshot of that.
  - `make seed` failed with `missing required environment variables: ERP_SEED_API_KEY, ERP_SEED_API_SECRET` although the keys were exported from `tmp/erp-keys.env` in a subshell. Running `go run ./cmd/seed all ...` in the same subshell worked. The Makefile has `-include .env` and `export` at lines 3-4, so a make variable from `.env` (probably a blank line) probably overrides the environment. **Do not read or edit `.env`**; find the cause from the Makefile's behaviour and fix it so the subshell's values win.
- The company the seeder expects (from `config/companies/mehta.yaml`): `erp_company: Mehta Tech Services Pvt Ltd`, `abbr: MTSPL`, Maharashtra. The seeder checks the abbreviation and the fiscal year (`bootstrap.go:445-470`), then sets the GST fields itself, so the script only creates the company.
- The first company's settings (from `setup-wizard.sh`): country India, currency INR, chart `India - Chart of Accounts`, fiscal year April to March of the current Indian fiscal year, no GSTIN.
- `tmp/erp-keys.env` holds `ERP_BASE_URL`, `ERP_SITE`, `ERP_API_KEY`, `ERP_API_SECRET`, `ERP_SEED_API_KEY`, `ERP_SEED_API_SECRET`. Never print or commit the values. Use it only by sourcing in a subshell: `(set -a; . tmp/erp-keys.env; set +a; <command>)`.
- The scripts refuse to run under xtrace (`lib.sh`). Keep that.
- `docs/setup.md` and `docs/**` are protected: don't edit them; list the doc change the owner should make under Notes in your report.

- [ ] `deploy/erpnext/add-company.sh <company name> <abbr>`: idempotent. If the company exists with that abbreviation, log `no change` and exit 0. If the abbreviation belongs to another company, or the company exists with a different abbreviation, `die`. Otherwise create it (India chart, INR, India, same fiscal year as the first company, `bench execute` with a Company insert) and read back abbr, country and currency like `run_wizard` does.
- [ ] Say in the script header that `deploy/erpnext/backup-clean.sh` must be re-run after the company is added (under `tmp/erpnext.lock`) so `make erp-reset` restores both companies. `backup-clean.sh` itself keeps its behaviour; change its header comment only.
- [ ] Fix the key handling so that `(set -a; . tmp/erp-keys.env; set +a; make seed SUITE=suite-v1)` reaches `cmd/seed` with `ERP_SEED_*` set, whatever `.env` contains. Apply it to every target that reaches ERPNext as seeder or bot (`seed`, `load`, `eval`, `record-fixtures`, `eval-replay` if they need it; leave the rest).

- [ ] Under the ERPNext lock: run `add-company.sh` for Mehta, re-run `backup-clean.sh`, then `make erp-reset`, then the bootstrap acceptance line; a second bootstrap run reports zero changes.
