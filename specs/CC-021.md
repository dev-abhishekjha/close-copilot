# CC-021 · Harness: accept UI-nn ticket IDs

## Goal

The guard hook, the gates code, `/next` and the two CI workflows accept the ticket ID forms `CC-<n>[a-z]` and `UI-<n>[a-z]` identically, so the UI series runs through the normal `/spec` and `/build` path, with `CC-nnn` behaviour unchanged.

## Context

- Ticket: `tasks/frontend-plan.md`, section 9 (not in `docs/implementation-tickets.md`). Owner decision 2026-10-16: the frontend work is a separate `UI-01` to `UI-14` series. The owner approved edits to the protected `gates/**`, `.claude/**` and `.github/**` paths for this ticket.
- Naming rules after this ticket:
  - ID: `^(CC|UI)-[0-9]+[a-z]?$`. Examples: `CC-602`, `CC-504a`, `UI-01`, `UI-09`.
  - Branch: lower-case ID plus slug: `ui-01-design-tokens`. `TicketFromBranch("ui-01-design-tokens")` returns `UI-01`; `cc-602-bank-rec` still returns `CC-602`; anything else returns `""`.
  - Commit subject that marks a ticket done: `UI-01: ...`, as `CC-602: ...` today.
  - Spec: `specs/UI-01.md`.
  - Ordering (`CompareIDs`): by number, then suffix, as now. IDs of different series compare by series first (`CC` before `UI`) and when series, number and suffix are all equal (`UI-1` and `UI-01`) fall back to `strings.Compare`, so the order is total; `CC-1001 < UI-01`.
- Invariants that must not weaken: another ticket's spec is never allowed on a branch (the `specs/cc-*.md` rule must also cover `specs/ui-*.md`, in any case); an ID that doesn't match the spec's file name still fails G0; a `tmp/current-task` value that is not a valid ID still blocks every edit.
