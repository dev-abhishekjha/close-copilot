# CC-104 · Redact secrets in config

## Goal

Logging, printing or JSON-encoding a `config.Config` never shows a secret.

## Context

- Ticket text: `tasks/hardening.md`, section `CC-104` (from CC-002's G5 finding N3). `internal/config/config.go` holds every token and key as a plain `string`, so `slog.Info("cfg", "cfg", cfg)` leaks them all.
- CC-701 and CC-904 will read secrets only through this `config.Secret`.
- `internal/frappe` already has its own `frappe.Secret` (a string type) for the client. Leave `internal/frappe` non-test code alone; callers pass `frappe.Secret(cfg.X.Reveal())`.
- **Owner role:** the graph says implementer, but the callers include `internal/seed` integration tests, which the implementer role may not edit (guard hook). The integration engineer owns frappe and books and can edit every caller listed here.
- **Secrets:** never read `.env`, and never print real key values. Tests use made-up values like `sk-test-123`.
- No new dependencies.

## Subtasks

- [ ] **`internal/config`: `type Secret struct{ v string }`** (unexported field, so `string(s)` doesn't compile):
  - `NewSecret(string) Secret`, `Reveal() string`, `IsZero() bool`;
  - `String`, `GoString`, `Format` (all verbs, including `%#v` and `%+v`), `LogValue` (slog), `MarshalJSON` and `MarshalText` all give `[redacted]`, or `""` when empty;
  - no `UnmarshalJSON`/`UnmarshalText`: secrets come only from the environment.
- [ ] **Change these `Config` fields to `Secret`:**
  - `ERPAPIKey`, `ERPAPISecret`, `ERPSeedAPIKey`, `ERPSeedAPISecret`;
  - `DatabaseURL` (it carries a password);
  - `MCPTokenAgent`, `MCPTokenAdmin`, `MCPScopeKey`;
  - `AnthropicAPIKey`, `PseudonymKey`;
  - `OTLPHeaders` (it carries auth);
  - `AppSessionKey`.

  `FromEnv` fills them, and required-variable checks still work (use `IsZero`). Keep the field names: the CC-002 `admintoken` analyzer tracks `Config.MCPTokenAdmin` by object, and must keep flagging it outside its allowed places.
- [ ] **`Config.LogValue()`:** a group that lists the non-secret fields (URLs, site, provider, models, addresses, data dir and budget) and shows each secret as set or unset (`"[redacted]"` or `""`).
- [ ] **Update callers** to `.Reveal()`, one line per call site. Today they are in `cmd/probe` (main.go, schema.go and the fake and command tests), `cmd/seed/main.go` and its test, and the integration tests in `internal/frappe`, `internal/books` and `internal/seed`. Compile with **and without** `-tags=integration` to find them all. Test fixtures build `Config` with `config.NewSecret("…")`.
- [ ] **Tests** (`internal/config/config_test.go`):
  - `TestSecret`: every formatting path, plus an empty secret.
  - `TestConfigRedacted`: a `Config` with every secret set to a distinct marker (`marker-erp-key`, …) is formatted with `%v`, `%+v`, `%#v`, `fmt.Sprint`, `slog` JSON (`slog.Any("cfg", cfg)` and `slog.Any("cfg", &cfg)`) and `json.Marshal` (value and pointer). No marker may appear in any output, and the non-secret fields do appear.
  - `FromEnv` still loads every secret (`Reveal` returns the env value).

## Acceptance (human-readable)

- No secret appears in `%v`, `%#v`, slog or JSON output of a populated `Config`.
- Everything builds, vets and tests with and without the integration tag, and the analyzers stay green.

## Out of scope

- `frappe.Secret`'s own hardening (CC-205).
- Moving secrets out of environment variables.
