# CC-802 · TEI and docling-serve clients

## Goal

Small Go clients for embedding, reranking and PDF-to-Markdown conversion over plain HTTP.

## Context

- Ticket: `docs/implementation-tickets.md`, section `CC-802`. Plan row: Phase 3, integration-engineer, standard; graph check "384-dim embeddings; rerank puts the relevant text first".
- Both services are plain HTTP. Batch embedding requests, set a generous timeout for document conversion, and retry transient failures.
- Quoted from the ticket:
  - `Embed(ctx, texts []string) ([][]float32, error)`: `POST /embed` with `{"inputs": [...]}`, batches of 32.
  - `Rerank(ctx, query string, texts []string) ([]Scored, error)`: `POST /rerank` with `{"query": "...", "texts": [...]}`, returning `[{"index": 0, "score": 0.98}, ...]`.
  - `ConvertPDF(ctx, path string) (markdown string, error)`: multipart `POST /v1/convert/file` with field `files` and `to_formats=md`; read `document.md_content`; 120 s timeout; fail when `status` is `failure`.

```bash
curl -X POST http://localhost:5001/v1/convert/file \
  -H 'accept: application/json' \
  -F 'files=@POL-001-accounting-policy.pdf;type=application/pdf' \
  -F 'to_formats=md'
```

- Env vars (`.env.example`; fields on `config.Config`): `TEI_EMBED_URL` (default `http://localhost:8081`, model `BAAI/bge-small-en-v1.5`, 384 dimensions), `TEI_RERANK_URL` (`http://localhost:8082`, `BAAI/bge-reranker-base`), `DOCLING_URL` (`http://localhost:5001`, compose profile `ingest`, started by `make up-ingest`).
- Shared spec: `doc_chunks.embedding vector(384)`, so a vector of any other length is an error the caller must not store.
- Egress rule (CC-002 analyzer, `docs` "egress"): no `http.Get`, `http.Post`, `http.DefaultClient` or `&http.Client{}` outside `internal/httpx`. Build the client with `httpx.New`, which only reaches the configured TEI and docling hosts.
- Phase 3 consumers: CC-803 (ingest: `ConvertPDF`, `Embed`) and CC-804 (search: `Embed` for the query, `Rerank` for the top 20). Expose small interfaces (`Embedder`, `Reranker`) so those tickets can fake them.

## Code map

- `internal/httpx/httpx.go:55` `func New(cfg config.Config, opts ...Option) (*http.Client, error)` and `:41` `func WithTimeout(d time.Duration) Option`: the only way to build the HTTP client. The default timeout is 30 s; docling needs `WithTimeout(120*time.Second)`.
- `internal/config/config.go:101-103`: `TEIEmbedURL`, `TEIRerankURL`, `DoclingURL` string fields. A client constructor returns an error when its URL is empty.
- `internal/frappe/client.go:299` `do`/`:314` `request`: the retry model to copy. Retry on 429, 502, 503, 504 and on transport errors before a response, with jittered exponential backoff (`backoffBase` `:44`, injectable `sleep` `:92`), honour `Retry-After`, and never wait past the context deadline. Unlike Frappe, **retry POSTs here too**: embed, rerank and convert have no side effects.
- Style to copy: `internal/frappe/client_retry_test.go:12` (`TestRetry`, an `httptest` handler failing n times then 200, with a fake `sleep` that records waits) and `internal/frappe/client_test.go:34` (`newTestClient`). Integration style and env-skip: `internal/frappe/client_integration_test.go` (build tag `integration`, skips without its env).
- `internal/retrieval/doc.go`: the package comment only. Do not open `internal/frappe` beyond the entries above.

## Subtasks

- [ ] `tei.go`: `type Scored struct{ Index int; Score float32 }`; `NewTEI(cfg config.Config) (*TEI, error)` with `Embed` and `Rerank`. `Embed` sends batches of 32 in order and returns vectors in input order; it fails when a response has a different count than its batch, and returns nil, nil for no texts without a call. `Rerank` returns the scores as TEI gives them and nil, nil for no texts.
- [ ] `docling.go`: `NewDocling(cfg config.Config) (*Docling, error)` and `ConvertPDF(ctx, path)`: opens the file, sends multipart (`files` part with content type `application/pdf`, plus `to_formats=md`), 120 s timeout, decodes `status` and `document.md_content`, and fails with a clear error when `status` is `failure` (include docling's `errors` text, truncated) or the Markdown is empty. Read the response through a size cap (64 MiB).
- [ ] Shared retry helper used by both files (put it in `tei.go` or a small unexported function; no new file outside the list). Errors wrap with `%w`, name the operation and status, and never include request text (document content may be large and is not for logs).
- [ ] Unit tests with `httptest`: batching (70 texts → 3 requests of 32, 32, 6, order kept); count mismatch; retry on 503 then success; no retry on 400 or 413; context cancel during a wait; rerank decode; docling success, `status: failure`, empty Markdown, multipart shape (field `files`, `to_formats=md`), missing file; an empty URL is a constructor error; a host outside the allowlist is refused.
- [ ] Integration tests (`//go:build integration`, names start `TestIntegration`): two texts embed to 384 dimensions each; reranking three texts (one about a bank charge, two unrelated) puts the relevant one first; a sample PDF converts and its Markdown contains a known phrase. Read the URLs from `TEI_EMBED_URL`, `TEI_RERANK_URL` and `DOCLING_URL` and **skip** a test whose URL is unset or unreachable, so the suite is not red without Docker.
- [ ] `testdata/sample.pdf`: a tiny text PDF with one heading and one paragraph (write the bytes by hand or with a few lines of Go in a test helper; no new dependency) and the phrase the integration test checks.

## Acceptance (human-readable)

- Integration tests pass with `make up` and the `ingest` profile running (`make up-ingest`); the orchestrator runs them with the services up and reports skips as skips, not passes.
- Embeddings are 384 floats each; rerank puts the relevant text first; a sample PDF converts to Markdown.
- Nothing in the package builds its own `http.Client` or reaches a host outside the configured URLs.

## Out of scope

- Chunking, ingestion and storage (CC-803); hybrid search, RRF and the `doc_chunks` SQL (CC-804); the Makefile and compose files (CC-102 owns them; the services already exist).
- Pseudonymisation: embeddings run on local TEI, so no text leaves the machine.
- Streaming, async docling jobs, and OCR options.

## Notes

- No new dependency expected (standard library plus `httpx` and `config`). If you need one, name it in the spec notes and the PR summary.
- `internal/retrieval` is not under the `nofloat` analyzer, so `float32` scores and vectors are fine; keep money out of this package.
- TEI answers 413 when an input is too long and 429 when its queue is full. Retry 429 only; surface 413 as an error naming the batch index, since the chunker (CC-803) keeps chunks short.
- G4-tier2 is listed because the ladder runs it when `retrieval` changes. Nothing consumes these clients yet, so expect no change.
