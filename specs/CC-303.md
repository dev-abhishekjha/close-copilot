# CC-303 · ERPNext master data bootstrap

## Goal

An idempotent command that creates everything the books need before the first invoice: accounts, GST setup, addresses, suppliers, customers, items and the external-ID field. A second run changes nothing.

## Context

- Ticket: `docs/implementation-tickets.md`, section `CC-303`. Shared spec: "Money, dates and IDs". The custom field is `copilot_ext_id`.
- Stack: `erp.localhost` at `ERP_BASE_URL`. frappe/erpnext 15.122.0 with India Compliance 15.32.0. Company **Sharma Traders Pvt Ltd** (abbr `STPL`) already exists with fiscal year 2026-2027 (April to March). The books are empty.
- **Keys:**
  - Use the **seeder key** (`ERP_SEED_API_KEY`/`ERP_SEED_API_SECRET`, Administrator) through `frappe.New(cfg, key, secret)`.
  - Acceptance loads `tmp/erp-keys.env` with `set -a; . file`. Never print a key or secret, and never read `.env`.
- **Field names:** `docs/erpnext-schema/*.json` and its README list the fields of Company, Account, Address, Supplier, Customer and Item, with India Compliance's `gstin`, `gst_category`, `gst_state` and `gst_hsn_code`. Use those names. For GST Settings (`gst_accounts` table) and Custom Field, read the live meta with the seeder key if you need it.
- **The generator (CC-302)** decides what the books need:
  - `seed.Accounts` and the `Account*` constants: base names with no abbreviation;
  - `profile.Bank.Account` (`HDFC Current 0001`);
  - customers are `CUST-001` … `CUST-<profile.customers>`, all in the company's state;
  - supplier names come from the profile;
  - bank charges carry CGST and SGST.
- ERPNext appends the abbreviation (`Rent - STPL`). Always resolve accounts by `account_name` **plus company**; never guess `name`.
- Unit tests use `httptest` fakes or a small in-memory fake of the frappe calls, never ERPNext. Live checks are the integration test and the acceptance commands.
- No new dependencies.

## Subtasks (Phase 1: company `sharma` only)

- [ ] **`internal/seed/bootstrap.go`**: `Bootstrap(ctx, c *frappe.Client, p Profile) (BootstrapReport, error)`. Every step looks the record up first and creates it only if it's missing; otherwise it counts it as unchanged. It updates only fields the bootstrap owns that differ, and counts each such update as a change. The report lists created, updated and unchanged counts per DocType, plus the names it created.
  1. **Company:** check the company exists and that a Fiscal Year covering 2026-04-01 to 2027-03-31 applies to it (its `companies` table is empty or names it). Fail clearly if not. Set the company's `gstin` (from `p.GSTIN()`), `gst_category` (`Registered Regular`) and `pan` if India Compliance has those fields and they're empty.
  2. **Company address:**
     - `Address`, `address_type: Billing`, `is_your_company_address: 1`, linked to the Company;
     - `gstin` set to the company GSTIN; a state and a pincode that match the state code (keep a small state code → state name and pincode map in bootstrap.go for every state code the profiles use).
  3. **Accounts:** every name in `seed.Accounts` plus the bank account, for the company. Create missing ones under a parent group that already exists in the chart. Put a table in a comment in bootstrap.go:
     - **bank:** `account_type: Bank`, under the `Bank Accounts` group;
     - **Payment Gateway Clearing** and **Prepaid Expenses:** Asset, under `Current Assets` or a subgroup;
     - **Office Equipment:** Asset, `account_type: Fixed Asset`, under `Fixed Assets`;
     - **expense accounts:** under `Indirect Expenses`, except Cost of Goods Sold, which normally exists already;
     - **Interest Income:** under `Indirect Income`;
     - **Sales, Debtors and Creditors:** these must already exist. Fail if they don't.

     Export `ERPAccount(base, abbr string) string` only if the naming rule is reliable; otherwise export a resolved map in the report.
  4. **GST Settings:**
     - check `gst_accounts` has an **Input** row and an **Output** row for the company, with CGST, SGST and IGST accounts that exist;
     - if a row or an account is missing, create the accounts (India Compliance's default names, e.g. `Input Tax CGST - STPL`) and add the rows;
     - report the resolved input and output account names; CC-304 needs them.
  5. **Custom field:**
     - one `Custom Field` each on Sales Invoice, Purchase Invoice, Payment Entry and Journal Entry: `fieldname: copilot_ext_id`, `label: Copilot Ext ID`, `fieldtype: Data`, `no_copy: 1`, `read_only: 1`, `search_index: 1`;
     - read back the stored fieldname. `const ExtIDField = "copilot_ext_id"` must equal it; if Frappe stored something else (e.g. `custom_copilot_ext_id`), fail with the stored name rather than guess.
  6. **Suppliers:**
     - one per profile supplier: `supplier_name` set to the profile name, a supplier group that exists, `country: India`;
     - **registered:** `gstin` (from `SupplierGSTIN`), `gst_category: Registered Regular`, `pan`, and a linked `Address` (Billing) with that GSTIN and the matching state and pincode;
     - **unregistered:** `gst_category: Unregistered` and no GSTIN.

     India Compliance validating these GSTINs is the real proof of CC-301's generator. If it rejects one, stop and report the exact message.
  7. **Customers:** `CUST-001` … `CUST-NNN` as `customer_name`, `customer_type: Company`, a group and territory that exist, `gst_category: Unregistered`. Check the resulting `name` equals the customer name, because the generator's `Party` is that string.
  8. **Items:**
     - non-stock (`is_stock_item: 0`, `stock_uom: Nos`, an item group that exists), each with a valid `gst_hsn_code` that exists as a `GST HSN Code` record;
     - one sales item, one per supplier kind (rent, utility, subscription, goods, services) and a laptop;
     - export `ItemFor(eventKind, supplierKind string, isAsset bool) string`, so CC-304 picks the item for a line.
- [ ] **`cmd/seed/main.go`:**
  - `seed bootstrap --company sharma [--config config/companies] [--expect-no-changes]`;
  - it needs the four ERP seed variables (the existing per-subcommand list);
  - it prints the report as JSON on stdout;
  - `--expect-no-changes` exits non-zero if anything was created or updated;
  - keep `world` working exactly as it is.
- [ ] **`deploy/erpnext/backup-clean.sh`:**
  - runs `bench --site erp.localhost backup` in the backend container (see `lib.sh`; use `</dev/null` on `docker compose exec` inside loops);
  - copies the newest database dump inside the container to the stable name `sites/erp.localhost/private/backups/clean-bootstrap-database.sql.gz`, overwriting it;
  - prints that path;
  - `set -euo pipefail`; idempotent. CC-307 restores from it.
- [ ] **Unit tests** (`bootstrap_test.go`), against a fake Frappe (`httptest`) that keeps records in memory:
  - an empty fake gets everything created;
  - a second run reports zero changes;
  - an existing account with the same `account_name` in another company is not mistaken for ours;
  - a stored custom fieldname other than `copilot_ext_id` fails loudly;
  - a missing Sales, Debtors or Creditors account fails;
  - `ItemFor` covers every event kind that has lines.
- [ ] **Integration test** (`bootstrap_integration_test.go`, `//go:build integration`; skip unless the ERP variables and the seed key are set):
  - `TestIntegrationBootstrapIdempotent`: run `Bootstrap` twice; the second report has zero created and updated.
  - `TestIntegrationBootstrapPurchaseInvoice`:
    - as the seeder, insert a Purchase Invoice for one **out-of-state** registered supplier (IGST) and one **in-state** one (CGST + SGST);
    - each has one item line (`expense_account` set to the base account resolved for the company), explicit tax rows (`charge_type: Actual`, the GST Settings accounts) and `bill_no`/`bill_date` in 2026-09;
    - **submit** each one, then **cancel** and **delete** it, so the books stay empty (the dev site has `delete_linked_ledger_entries=1`);
    - on failure, still try to cancel and delete in `t.Cleanup`.

    This test runs before `backup-clean.sh`, so the backup has no invoices.

## Acceptance (human-readable)

- The first run creates the masters. The second, with `--expect-no-changes`, exits 0.
- India Compliance accepts every generated supplier GSTIN, and a GST Purchase Invoice for a generated-GSTIN supplier submits (IGST and CGST + SGST cases).
- After the run there are no Purchase Invoices, Journal Entries or GL Entries in the books, and the clean backup exists.
