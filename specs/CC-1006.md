# CC-1006 · agent serve: wire the web server, the run starter and /api/ask

## Goal

One binary serves the web UI: `agent serve` starts the CC-1001 server with the CC-1002 runs pages, the CC-1003 finding pages and a real `POST /api/ask`.

## Context

- Ticket: `tasks/hardening.md`, section `CC-1006` (not in `docs/implementation-tickets.md`). Plan row: `tasks/graph.yaml`, phase 4, implementer, data-sensitive, no ERPNext lock.
- Finding: no `cmd/` package imports `internal/web`; `cmd/agent` has `close`, `resume`, `mint-scope`; `internal/web/routes.go:64` maps `POST /api/ask` to `notImplemented` (501). `RunsBackend.Execute` and `FindingsStore` have no caller outside tests.
- **Owner decisions (2026-10-14), binding:**
  - `/api/ask` is API only. Add no "ask a question" page and no template.
  - The handler validates the submitted `company` against `ListCompanies` (as `runsService.start` does at `internal/web/runs.go:108-114`) and refuses an unknown one. Do not edit `config/users.yaml`. Per-user company lists are a later decision (before CC-1201); say in a code comment that until then any signed-in user can ask about any listed company.
  - The close runs inside the server process (`RunsBackend.Execute` = `Workflow.ResumeClose`). A separate worker is a Phase 5 option.
- Quoted rules:
  - `AskRequest.Company` is "the authenticated session's company id, never a value from the question"; here it is the validated `company` field, never text from `question`.
  - Treat any error from the Asker as "do not answer": no answer text in the response.
  - `ErrQuestionTooLong` (`MaxQuestionRunes = 500`) maps to 400; `ErrAskReroutes` maps to 429; every other error to 500 with the fixed body `{"error":"internal error"}`, logged with `serverError`-style slog (no question text in logs).
  - `AskResult` JSON (what the handler returns for a routed answer, a refusal or a clarification): `run_id, action, refusal?, answer?, citations, evidence_ids, verified, needs_review, violations?, step_refs`.
  - Invariants: `internal/web` does not import `internal/frappe`; the agent binary does not link the ERPNext client; `LLM_DAILY_BUDGET_USD` and tool allowlists are not changed; secrets come only from env; synthetic data only.
- Request body: one JSON object `{"company","month","question"}`, `DisallowUnknownFields`, trailing data refused (copy `handleAPIStartRun`, `internal/web/runs.go:517-536`). Month must match `monthRE` (`YYYY-MM`). Empty or whitespace-only `question` is 400. Role: `anyRole`; CSRF and auth come from `wrap`.
- `serve` environment: `cli.Main` requires `DATABASE_URL`, `BOOKS_MCP_URL`, `EVIDENCE_MCP_URL`, `MCP_TOKEN_AGENT`. `serve` additionally requires `APP_SESSION_KEY` (at least 32 bytes, checked by `web.NewServer`), `MCP_SCOPE_KEY`, and, unless `--no-explain`, `PSEUDONYM_KEY` and `cfg.CheckLLM()`. `APP_ADDR` is optional (default `:8000`). Listen address comes only from `APP_ADDR`.

## Acceptance (human-readable)

- `agent serve` starts on `APP_ADDR` using `APP_SESSION_KEY` and `config/users.yaml`.
- A viewer can log in and see the runs list and one finding.
- `POST /api/ask` returns a routed answer or the router's fixed refusal, and nothing answers when the router or Asker errors.
- Invariants hold: `internal/web` does not import `internal/frappe`; the `agent` binary does not link the ERPNext client.
- A person can follow the browser steps in the final report; the live walkthrough needs the seeded ERPNext, so it is not part of the gate.

## Out of scope

- An "ask a question" page or any template (separate follow-up).
- Per-user company lists in `config/users.yaml` (owner decision before CC-1201).
- A separate run worker (Phase 5 option).
- Maker-checker routes (CC-1004), audit pages (CC-1005), login rate limits (CC-1102), TLS or HSTS (CC-1201).
- Any change to `internal/agent`, `internal/approvals`, `config/users.yaml`, `evals/**`, `docs/**`.

## Notes

- No new dependencies expected.
- `serve` wires `Workflow` as `close` does; the explain and verify steps need `PSEUDONYM_KEY`, so `serve` without it runs with `--no-explain` only.
- The per-question Asker run is rate-limited by the Asker itself (reroute cap); a per-IP or per-user limit is CC-1102.
- `AskRedactorFunc` rejects a person name with `& < >`; surface that as a startup error naming only the index.
- The Asker's `Tools` is the same `*agent.Registry` the close uses; every call is scoped by `newScope(company, month)` inside `Ask`, so no extra scope code is needed in the handler.
- Risks: `RunsBackend.Execute` ties up the server for the length of a close; accepted for the demo (owner decision).
