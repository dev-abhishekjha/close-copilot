# UI-14 · Accessibility, responsive pass and end-to-end tests

## Goal

Close the UI series: fix what an automated accessibility scan and a tablet/phone viewport find on every page, and add a Playwright suite (viewer, maker and checker walkthroughs, no CSP violations, one screenshot per page) that runs against a Go fixture server with in-memory backends.

## Context

- Ticket: `tasks/frontend-plan.md` row UI-14 ("Accessibility and responsive pass, plus a visual and e2e test suite (Playwright against a seeded `agent serve`), screenshots stored per page"). The owner chose, for this spec (2026-10-17): the suite runs against an **in-memory fixture server** (no Docker, no Postgres, no ERPNext), and **Node lives only under `e2e/`** (dev only).
- Gate G (plan section 5/6): every API row reachable by a button for the role that may call it; viewer, maker and checker walkthroughs pass; no CSP violations in the browser console.
- Plan rules for this ticket: accessibility = keyboard reachable everywhere, visible focus, `aria-live` for progress and toasts, contrast AA, skip link, labelled forms. Responsive = down to tablet; phone is read-only friendly (no side-by-side). Synthetic data only in fixtures and screenshots. No CI wiring (`.github/**` is protected; do not touch it).
- Decision 1 of the plan stays: no Node in the Go build, `make check` and `make gates` never need Node. Only `make e2e` does.
- Server pieces (all in `internal/web/server.go`): `NewServer(opts Options, users Users, log *slog.Logger) (*Server, error)`; `*Server` is an `http.Handler`. `Options` fields the fixture sets: `SessionKey config.Secret` (>= 32 bytes), `InsecureCookies true` (plain http on localhost), `Now func() time.Time`, `Runs *RunsBackend{Store RunsStore, Execute RunExecutor, Findings FindingsStore}`, `Ask AskBackend`, `Approvals ApprovalsBackend`, `Audit AuditStore`, `Documents DocumentsBackend`, `System *SystemOptions{Backend SystemBackend, Info SystemInfo}`, `ERPBaseURL`, and rate limits (`APIRate`, `APIBurst`, `AskRate`, `AskBurst`, `LoginIPFailures`, `LoginUserFailures`; zero = defaults, raise them for the suite so repeated logins and asks never get 429). `DevComponents` stays false.
- Backend interfaces the fixture must implement (copy exact signatures):
  - `RunsStore`: `CreateCloseRun(ctx, store.CloseRun) error`; `GetCloseRun(ctx, uuid.UUID) (store.CloseRun, error)`; `ListCloseRuns(ctx, limit int) ([]store.RunSummary, error)`; `ListFindingsByRun(ctx, uuid.UUID) ([]store.Finding, error)`; `ListCompanies(ctx) ([]store.Company, error)`. `RunExecutor` is `func(ctx, runID uuid.UUID) error` and drives a queued run to a terminal state.
  - `FindingsStore`: `GetFinding`, `GetCloseRun`, `ListSteps(ctx, runID) ([]store.Step, error)`, `GetArtifact(ctx, sha string) (store.Artifact, error)`, `SetFindingStatus(ctx, findingID, status string) error`, `InsertAuditLog(ctx, store.AuditLogEntry) (int64, error)`, `GetProposalByFinding(ctx, findingID) (store.JournalProposal, bool, error)`.
  - `ApprovalsBackend`: `Propose(ctx, actor string, findingID) (store.JournalProposal, error)`; `Approve(ctx, actor, id) (ApproveResult, error)`; `Reject(ctx, actor, id, reason string) error`; `Pending(ctx) ([]store.JournalProposal, error)`; `Get(ctx, id) (store.JournalProposal, error)`. Maker-checker must hold in the fake: the approver may not be the proposer (the real `adaptApprovalErr` in `cmd/agent/serve.go:139` maps the domain errors; mirror what the web layer expects by reading the existing `fakeApprovals` in `approvals_test.go:24`).
  - `AskBackend`: `Ask(ctx, AskInput) (AskOutput, error)`.
  - `AuditStore`: `ListAuditPage(ctx, store.AuditFilter) ([]store.AuditLogEntry, int64, error)`; `ListAuditFacets(ctx) (actors, servers, tools []string, err error)`; `RunMetricsByStep(ctx, runID) ([]store.StepUsage, error)`; `RunsSummaryStats(ctx) (store.LastRunStats, error)`.
  - `DocumentsBackend`: `ListDocuments(ctx, company string, docTypes []string) ([]retrieval.DocSummary, error)`; `GetDocument(ctx, company, docID string) (retrieval.Document, error)`.
  - `SystemBackend`: `Postgres(ctx) error`; `ERPNext(ctx) error`; `SpendToday(ctx) (SpendToday, error)`.
- Users: `NewUsers(list ...User) (Users, error)` with bcrypt password hashes at `MinBcryptCost`. Three roles: viewer, maker, checker (roles are not a ladder; see `anyRole`, `makerOnly`, `checkerOnly` in `routes.go:11`). Build `User` values the way `testFixture` does (`helpers_test.go:60`). Fixture credentials are synthetic, printed in `e2e/README.md`, and never real; the listen address is localhost only.

Page styles live in `static/css/*.css`; put new rules in the stylesheet of the page they affect, or in `shell.css` for shell-wide ones. ## Subtasks

- [ ] **Fixture server** `e2e/fixture/` (package `fixture`, plus `e2e/cmd/e2eserver/main.go` that listens on `E2E_ADDR`, default `127.0.0.1:8099`). In-memory implementations of every backend interface above, seeded with synthetic data: two companies (names from `config/companies`, or invented ones; no real GSTINs), one month, one completed close run with the three planted bank-charge findings (one verified with citations, one "needs review", one with a proposed entry), one failed run, one queued run, a finding with a proposal and one without, a pending proposal for the checker, history (approved, rejected with reason), a few audit rows, documents of each type, system checks ok, and one `Ask` answer with citations plus one refusal. A `RunExecutor` that steps a queued run to completion in a few hundred ms so live progress is visible. `POST /__e2e/reset` is **not** needed; the suite restarts the server per worker instead (Playwright `webServer`). Never read `.env`, never open a network connection, never import `internal/frappe`.
- [ ] **Go tests for the fixture** (`e2e/fixture/fixture_test.go`): the server starts on `httptest`, each role can sign in, every page in `routeTable` that is a GET page answers 200 for the roles that may call it and 403 for the others, and maker-checker holds (proposer cannot approve).
- [ ] **Playwright suite** `e2e/` with `package.json` (dev only, exact pinned versions of `@playwright/test` and `@axe-core/playwright`, `package-lock.json` committed, `node_modules/` git-ignored), `playwright.config.ts` (Chromium only; `webServer` runs `go run ./e2e/cmd/e2eserver` from the repo root and waits on `/login`; viewports `desktop 1280x800`, `tablet 820x1180`, `phone 390x844`), and `tests/`:
  - `walkthrough-viewer.spec.ts`, `walkthrough-maker.spec.ts`, `walkthrough-checker.spec.ts`: sign in, then follow the real path with clicks and the keyboard only (no `page.goto` after login except the first). Viewer: dashboard, runs, run detail, findings, finding detail, ask, documents, system; no write buttons visible. Maker: start a run, watch it finish, open a finding, mark a status, propose an entry, see it pending in Proposals; approve is absent. Checker: approvals queue, approve one (toast shown, audit row appears), reject another with a reason, audit log filters; propose is absent. Palette: Ctrl+K, type, Enter navigates; `?` opens the shortcuts; `g d` goes to the dashboard.
  - `a11y.spec.ts`: for every page and role that can see it, at desktop and tablet, run axe with tags `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa` and assert zero violations. A disabled rule needs a one-line comment saying why; do not disable `color-contrast`.
  - `keyboard.spec.ts`: Tab from the top of each page reaches the skip link first and then every interactive control in a sensible order; focus is visible (outline or ring has non-zero width and contrasts) on a sample of each control type; dialogs trap focus and restore it to the opener on Esc; toasts and run progress sit in `aria-live` regions.
  - `responsive.spec.ts`: at 820 wide and 390 wide no page has horizontal scroll (`document.documentElement.scrollWidth <= clientWidth`), the sidebar becomes a menu button that opens and closes with the keyboard, tables scroll inside their own container or collapse to stacked rows, tap targets are at least 40x40 CSS px, and on phone the finding detail shows no side-by-side layout.
  - `csp.spec.ts` (or a shared fixture in every spec): collect `console` errors and `securitypolicyviolation` events across all walkthroughs and fail on any. Also fail on any request to a non-same-origin host.
  - `screenshots.spec.ts`: one full-page screenshot per page and role-relevant state at desktop, written to `e2e/screenshots/<page>.png` (committed; a README in that folder says they are synthetic and how to refresh with `make e2e-shots`). Fix the clock and disable animations and carets so the images are stable; the test does not diff against them (visual diffing is out of scope), it only writes them.
- [ ] **Accessibility and responsive fixes in `internal/web/**`** for whatever the suite finds: labels, names for icon buttons, heading order, landmarks (one `main`, one `nav` with a label, `header`), table captions or `aria-label`s, `aria-current` on the nav, `aria-live` on progress, visible focus ring tokens, reduced-motion (`prefers-reduced-motion`) honoured in every stylesheet that animates, sidebar collapse under about 900px, table overflow containers, stacked layouts on phone. Each fix gets a Go test in the page's existing `_test.go` that checks the rendered HTML (landmark, label, `aria-*`), so a regression fails `go test` without a browser.
- [ ] **Makefile**: `e2e` (installs with `npm ci --prefix e2e`, ensures the Chromium browser with `npx playwright install chromium` only when it is missing, runs `npx playwright test`; logs to `tmp/reports/e2e.log` and prints the failing lines), and `e2e-shots` (same, runs only `screenshots.spec.ts`). Neither is a prerequisite of `check` or `gates`. Add `make help` descriptions in the file's existing `## ` style.
- [ ] **`e2e/README.md`**: how to run, fixture users and why they are safe, how to add a page to the suite, how to refresh screenshots.
- [ ] **`.gitignore`**: add `e2e/node_modules/`, `e2e/test-results/`, `e2e/playwright-report/`.
