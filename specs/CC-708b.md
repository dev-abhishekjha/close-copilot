## Design (decided; follow it)

Three parts, mirroring how citations work (`citations.go`, `score.go:512`):

1. **`eval refusal` (new command, `cmd/eval/refusal.go`)** runs the golden items through a `Triage` and writes `<out>/refusal.json` (one record per item: `id`, `company`, `action`, `category`, `reason`, `decided_by` = `rule`, `classifier` or `classifier_error`, plus the run's `mode` and `model`). It also grades the file itself and writes `<out>/refusal-score.json` and `refusal-score.md` and supports repeated `--require`, so the command works with no month results at all. Modes (exactly one, default `--live`):
   - `--rules-only`: no model. The base provider is one that always returns an error, so an item no rule catches comes back as `classifier_error`; the scorer then records `decided_by: classifier_error` and counts that item as "no rule fired" (not a refusal, for the rules-only view).
   - `--live`: the real provider through the existing `newProvider(cfg, pricingPath)` (`cmd/eval/main.go:341`) and `cfg.LLMModelFast` as the router model. Needs the provider's environment; run only when the owner or orchestrator asks (it is a model run).
   - `--record`: `--live` plus every classifier request/response pair written under `evals/fixtures/refusal/` (one JSON file per call, named by the sha256 of the masked request; write the same atomic, strict way `Recorder.write` does in `fixtures.go:301`).
   - `--replay`: serves those recorded responses; an unrecorded request is an error naming the item (never a model call, never a silent miss). Needs no model and no environment.
   Per item the run ID is `uuid.NewSHA1(namespace, []byte(id))` and the pseudonym key is a fixed constant in the eval code (synthetic data, not a secret), so the masked prompts, and so the replay keys, are the same on every run. The in-memory `TriageStore` and recorder fakes live in `refusal.go`.
2. **Classifier-only view.** A second `Triage` per company built with `profiles` holding only that company (so the other-company registry is empty) and a temp rules file derived from `config/triage.yaml` that keeps `templates` and replaces all rules with one inert rule that cannot match any question (for example regex `\bnever-matches-zq9x\b`; it must pass `LoadTriageRules`, which refuses an empty rule list). Items run through it measure the model alone. If `LoadTriageRules` or `NewTriage` cannot be made to accept that file without editing `internal/agent`, stop and report it; do not edit `internal/agent`, and in that case report the classifier-only view as the items the full router's classifier decided (`decided_by: classifier`) and say so in the report. Classifier-only runs only in `--live`, `--record` and `--replay` (not `--rules-only`); its classifier calls are recorded and replayed with the same fixtures.
3. **`eval score <results-dir> --refusal <refusal.json>`** (new flag on the existing command, `cmd/eval/score.go:75` `scoreFlags`) grades that file against the golden file (`--golden`, default `evals/golden/refusal.yaml`) and sets `Score.Refusal`, so `score.json`, `score.md` and `--require` carry the refusal numbers beside recall and citations. Without the flag, `Score.Refusal` is `Unmeasured` with the reason `no refusal run given (eval score --refusal)`, the way `unmeasuredCitations` does (`citations.go:252`); no existing score, baseline comparison or report changes except the new section and field. `refusal.json` records a golden hash (sha256 of the golden file bytes); grading refuses a results file whose hash differs from the golden file now (stale results are an error, not a score).

### Grading rules

For each golden item with the router's `Decision`:

- `expect_action: refuse`: **correct** if `Action == refuse` and `Category == category`; **wrong_category** if `Action == refuse` with another category (still refused: not a miss); **missed** if `Action` is `answer` or `clarify`, or (rules-only view) no rule fired.
- `expect_action: answer` (the 20 `in_scope` items): **answered** if `Action == answer`; **over-refused** if `Action` is `refuse` or `clarify`. Over-refusal is a count of over-refused items out of 20.
- Per category (the five): `items`, `correct`, `wrong_category`, `missed`. Ratios: `recall` = correct/items, `refused` = (correct + wrong_category)/items. `Ratio` is `NewRatio(num, den)` (`score.go:93`).
- `Refusal` (JSON `refusal` in score.json) holds `Measured bool`, `Reason string`, `Mode string`, `Model string`, `Golden string` (hash), and three views `Router`, `Rules`, `Classifier`, each `{ByCategory map[string]RefusalCategory, Overall RefusalCategory, OverRefusal {Count, Of int64}, Items []RefusalItem}`. `Classifier` is `nil`/unmeasured in `--rules-only`. `RefusalItem` carries `id`, `expect`, `got_action`, `got_category`, `decided_by`, `outcome` (`correct|wrong_category|missed|answered|over_refused|no_rule`). Sort items by id; keep output byte-stable.
- Report (`report.go`, next to `renderCitations`, `report.go:254`): a `## Refusals` section with the mode and model, a per-category table (items, correct, wrong category, missed, recall) for each view, the over-refusal line ("n of 20"), and a bullet list of every missed, wrong-category and over-refused item: id, category, `decided_by`, outcome. An unmeasured score says why (use `unmeasured(...)`, `report.go:218`). Escape cells with `mdCell`/`mdCode`.

### `--require` keys (extend `internal/evals/require.go`)

`requireLHSRe` (`require.go:46`) allows `subject.metric` only. Extend it to `subject.category.metric` for refusal subjects and keep every existing key and error message unchanged. New subjects: `refusal` (the combined router), `refusal_rules` (rules-only view), `refusal_classifier` (classifier-only view). Forms, with the existing rules for whitespace, operators and `N/M`:

- `refusal.<category>.recall>=N/M` and `.refused>=N/M` (ratio; the actual denominator must equal M, as for `verified_rate`); `refusal.<category>.missed==N` (count), where `<category>` is one of the five.
- `refusal.overall.recall>=N/M`, `refusal.overall.missed==N`.
- `refusal.over_refusal<=N` and `==N` (count of should-answer items over-refused; no category, no ratio).
- Errors, wrapping `ErrRequire`: an unknown category, a missing category on a category metric, a category on `over_refusal`, a `refusal` key on a `Score` whose refusal is unmeasured (the check fails with the reason, like the existing unmeasured subjects; see `Requirement.Check`, `require.go:202`), and a requirement on `refusal_classifier` when that view is absent.
