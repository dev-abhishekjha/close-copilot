# CC-502 · Books server: read-only tools

## Goal

`mcp-books` serves the seven read-only books tools from the shared MCP catalog on `/mcp`, each with typed input and output structs, strict validation and descriptions written for the model.

## Context

- **Ticket:** `docs/implementation-tickets.md`, section `CC-502`.
- **Shared specs:** the "MCP tools" table (books `/mcp` rows: `get_trial_balance`, `list_gl_entries`, `list_purchase_invoices`, `list_sales_invoices`, `list_payments`, `get_account_history`, `list_recurring_suppliers`).
- **Pattern to copy:** `internal/evidence/tools.go` (CC-503), the evidence server: typed structs with `jsonschema` tags, `mcp.AddTool`, `company` as the company **ID**.
- **Company is the company ID** (`sharma`), the same as the evidence tools and `checks.DirectBooks` (CC-601).
  - The ticket's example struct says "ERPNext company name"; the shared tool table and run scoping (CC-506) use the ID, and that wins.
  - The server resolves ID → ERPNext name from the company profiles (`seed.LoadProfiles`, field `ERPCompany`).
  - An unknown ID is a clear error.
  - `mcp-books` gets a `--companies` flag (default `config/companies`). It needs no database.
- **The checks must not change in E7** (CC-702 builds MCP-backed readers over these tools), so the output shapes must carry what `checks.BooksReader` returns:
  - GL entries: name, account, debit, credit, posting date, voucher type and no, party type and party, against, remarks;
  - payments: name, payment type, party, amount, reference no, posting date, invoices;
  - invoices: the fields in the catalog row, plus the line and tax rows.
  - Amounts are `money.Paise` (int64 paise) and dates are `YYYY-MM-DD`.
- **Recurring suppliers:** `checks.computeRecurringSuppliers` (internal/checks/readers.go) already implements the rule.
  - Move the logic into `internal/books` as an exported `RecurringSuppliers(invoices []frappe.PurchaseInvoice, minOccurrences, amountBandPct int) []RecurringSupplier`.
  - The books tool calls it; `checks` delegates to it. Keep `checks.RecurringSupplier` as an alias, so checks code and tests don't change behaviour.
  - `books` must not import `checks` (checks imports books).
- **Hardening note** (`tasks/hardening.md`, "Notes for later specs", CC-502): the books tools validate `fields` and `order_by` against identifier and `asc|desc` allowlists at the tool boundary. CC-205's client check is the second line of defence.
  - No tool here accepts raw `fields` or `order_by`.
  - The `account`, `party` and `supplier` filters go into Frappe **filter values**, never field names.
  - Validate them as printable text up to 140 characters, with no control characters.
  - A test shows a hostile value (`x') or 1=1 --`) reaches Frappe only as a filter value.
- **Read-only:** every tool gets `Annotations: &mcp.ToolAnnotations{ReadOnlyHint: true}`; check the field type in the vendored SDK version. No tool writes. `/mcp-admin` and its tool are CC-504b; leave the admin route as it is.
- **ERPNext:** unit tests use an httptest fake ERPNext. The integration test only **reads** the shared ERPNext, so it takes no lock (`needs_erpnext: false`; only writers lock).
  - It needs a seeded month; the skeleton seeds sharma 2026-08 and 2026-09.
  - If no data is found, fail with a message saying which month to seed. Don't seed from the test.
- **Secrets:** `frappe.New` takes `config.Secret` after CC-205. Use the bot keys `ERP_API_KEY` and `ERP_API_SECRET`, never the seed keys. Never read `.env`.
- No new dependencies.

## Subtasks

- [ ] **`internal/books/tools.go`:** `RegisterTools(s *mcp.Server, deps ToolDeps)`, where `ToolDeps{Client *frappe.Client, Companies CompanyResolver, Now func() time.Time}`.
  - `type CompanyResolver interface { ERPCompany(id string) (string, error) }`.
  - `ProfileCompanies(profiles []seed.Profile) CompanyResolver`.
- [ ] **The seven handlers:** one typed input and one output struct each, with model-facing descriptions that say what the tool returns, when to use it, and that amounts are paise.
  - `get_trial_balance` → `books.TrialBalance`.
  - `list_gl_entries` → `books.FrappeLedger`, with optional `account` and `party` filters, paginated (below).
  - `list_purchase_invoices` (optional `supplier`) fetches each invoice's tax and item rows.
  - `list_sales_invoices`.
  - `list_payments` (optional `party`).
  - `get_account_history` → `books.AccountHistory`.
  - `list_recurring_suppliers` → `books.RecurringSuppliers`, with inputs `before_month`, `lookback_months`, `min_occurrences`; amount band default 20%.
  - All read submitted documents only (`docstatus = 1`), as `checks.DirectBooks` does.
- [ ] **Validation:**
  - a known company ID;
  - dates `YYYY-MM-DD`, from ≤ to, range ≤ 400 days;
  - `months` 1..12;
  - `lookback_months` 1..12 and `min_occurrences` 1..12;
  - months `YYYY-MM`;
  - filter text as above.

  Errors name the field and the rule so the model can retry.
- [ ] **Pagination for `list_gl_entries`:**
  - 500 rows a page, ordered by `name asc`.
  - The cursor is base64 of the last entry's `name`: keyset, stable even if rows are inserted between pages. This is a deliberate change from the ticket's `limit_start` cursor.
  - The next page filters `name > <last>`.
  - Reject a malformed cursor.
  - `next_cursor` is empty on the last page.
- [ ] **`cmd/mcp-books`:**
  - load the profiles, build the frappe client from the bot keys, and register the tools on the `/mcp` server for both the stdio and http transports;
  - keep the env list in `cli.Main` exactly as the admintoken analyzer requires;
  - add `--companies`;
  - a test that the server lists exactly the seven tools, each with a description and the read-only hint.
- [ ] **`internal/checks/readers.go`:** delegate `computeRecurringSuppliers` to `books.RecurringSuppliers`; existing checks tests still pass unchanged.
- [ ] **Tests:**
  - `TestTools*` (unit, fake ERPNext):
    - each tool's happy path;
    - each validation error;
    - an unknown company;
    - pagination across three pages, with a malformed cursor rejected;
    - the hostile filter value only as a filter value;
    - drafts and cancelled documents excluded;
    - output amounts in paise matching the fake's rupee amounts.
  - `TestToolsIntegration` (`//go:build integration`): for sharma 2026-09, each tool's output equals the direct `internal/frappe` / `internal/books` call; for `list_gl_entries`, the concatenated pages equal one direct call.

## Acceptance (human-readable)

- All seven tools are listed with schemas, descriptions and the read-only hint.
- Tool output equals the direct client output for a seeded month (integration).
- Bad input gets a clear, field-named error, and no raw model text ever reaches Frappe as a field name or `order_by`.

## Out of scope

- Phase 2 pass: both companies and the full suite.
