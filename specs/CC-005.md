# CC-005 · Close the static analyzer gaps

## Goal

The analyzers catch the indirect forms of the patterns they already ban.

## Context

- Ticket text: `tasks/hardening.md`, section `CC-005`. It comes from CC-002's G5 review, findings S1, S3 and N2.
- The analyzers are in `gates/analyzers/<name>/`, with `analysistest` testdata under `gates/analyzers/testdata/src/`. The multichecker is `gates/cmd/lint`. Read `specs/CC-002.md` for each rule's scope and the test-file exemptions; they don't change.
- `gates/**` is protected, and this spec's approval covers it. Don't touch `gates/cmd/**` or `gates/*.go`, which belong to CC-004.
- Type information only (`pass.TypesInfo`), never name matching, as in CC-002.
- No new dependencies. `golang.org/x/tools/go/analysis` is already used.

## Subtasks

- [ ] **egress** (`gates/analyzers/egress/egress.go`). Outside `internal/httpx`, and not in `_test.go`, also report:
  - zero-value declarations of `http.Client` or `http.Transport`: `var c http.Client`, and a struct field of that type held by value;
  - `http.Transport{…}` and `&http.Transport{…}` literals, and `new(http.Transport)`;
  - any use of `net/http/httputil.ReverseProxy` or `httputil.NewSingleHostReverseProxy`;
  - a struct that embeds `http.Client` or `http.Transport` (by value or pointer).

  A pointer field `*http.Client` that is only assigned from `httpx.New` stays allowed. Only by-value fields and embedding are reported.
- [ ] **noerpimport** (`gates/analyzers/noerpimport/noerpimport.go`):
  - walk `pass.Pkg.Imports()` transitively, or export a package fact from each package that reaches `internal/frappe`;
  - report on the import line in `internal/agent` (or a subpackage), with the chain, e.g. `internal/agent imports internal/frappe via internal/books`;
  - test files stay covered.
- [ ] **admintoken** (`gates/analyzers/admintoken/admintoken.go`):
  - in `cmd/mcp-books`, accept the name `MCP_TOKEN_ADMIN` (or `config.EnvMCPTokenAdmin`) only as an element of the `[]string` literal passed as the **second argument of a `cli.Main` call**, resolved through `TypesInfo` to `internal/cli.Main`;
  - any other `[]string`, or any other use of the name there, is reported;
  - `Config.MCPTokenAdmin` stays forbidden in `cmd/mcp-books`.
- [ ] **Testdata:** a positive and a negative case for every new rule:
  - **egress:** `var c http.Client` flagged; `var c *http.Client = httpx…` clean; `&http.Transport{}` flagged; `httputil.NewSingleHostReverseProxy` flagged; an embedded `http.Client` flagged; all of these clean inside `internal/httpx`.
  - **noerpimport:** `internal/agent` → `internal/books` → `internal/frappe` flagged, with the chain in the message; `internal/agent` → `internal/money` clean.
  - **admintoken:** `cmd/mcp-books` with the name in the `cli.Main` literal clean; the same name in another `[]string` in `cmd/mcp-books` flagged.
- [ ] `go run ./gates/cmd/lint ./...` must stay clean on the repo. If a new rule fires on real code under `internal/` or `cmd/`, **don't change that code**; report each hit with its file and line, and the orchestrator asks the owner.

## Acceptance (human-readable)

- Every new testdata case is flagged or passes as listed, and every existing CC-002 case still behaves the same.
- The repo stays lint-clean, or every hit is reported for the owner.
- G6, owner checks: the egress allowance for pointer fields assigned from `httpx.New`, and that the noerpimport chain message is readable.

## Out of scope

- The gates, CI and guard hook (CC-004).
- New analyzers, and changes to `nofloat`'s scope.

## Notes

- Today `internal/agent` doesn't exist beyond a stub, and nothing in it imports `internal/books`, so the transitive rule shouldn't fire on the repo. Once CC-502 lands, `internal/books` imports `internal/frappe`, so the agent must reach the books only through MCP; this rule is what enforces it.
