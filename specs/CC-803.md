# CC-803 · Ingestion pipeline

## Goal

`make ingest` converts, chunks, embeds and stores the corpus, and skips documents that haven't changed.

## Context

- Ticket: `docs/implementation-tickets.md`, section `CC-803`. Plan row: Phase 3, implementer, standard; graph check "Second ingest writes zero rows". Do not open `docs/`; everything needed is quoted here.
- Quoted from the ticket:
  - Split on Markdown headings so chunks follow the document's own structure; keep the section path ("§4.2 Spreading annual costs") as metadata for citations; prepend the document title and section path to each chunk **before embedding** so short chunks keep their context.
  - Walk `corpus/`; derive `doc_id`, `doc_type` (policy, contract, close_note) and `company_id` (NULL for shared) from the path.
  - Skip a document when its content hash matches the stored one; otherwise delete its chunks and re-insert.
  - Chunking: split on headings; sections longer than about 350 words split again with about 50 words of overlap; tables stay whole.
  - Embed `title + section path + chunk` in batches; insert into `doc_chunks` in one transaction per document.
  - Stop the docling container afterwards (`docker compose --profile ingest stop`) to free memory.
  - Acceptance: a second `make ingest` with no corpus changes writes zero rows; the ingest log reports documents, chunks and seconds taken.
- Table (migration `migrations/0003_docs.sql`, already applied by `make migrate`):

```sql
CREATE TABLE doc_chunks (
  id bigserial PRIMARY KEY, doc_id text NOT NULL,
  doc_type text NOT NULL,                 -- policy|contract|close_note
  company_id text,                        -- NULL = shared by all companies
  section text, title text, content text NOT NULL, content_hash text NOT NULL,
  embedding vector(384) NOT NULL,         -- bge-small-en-v1.5
  tsv tsvector GENERATED ALWAYS AS (to_tsvector('english', coalesce(title, '') || ' ' || content)) STORED
);
```

- Corpus layout and ids (from CC-801): `corpus/shared/POL-001-accounting-policy.{md,pdf}` (doc_type `policy`, company NULL); `corpus/<company>/contracts/CON-<supplier-id>.{md,pdf}` (`contract`, company = the directory name, `sharma` or `mehta`); `corpus/<company>/notes/NOTE-<company>-<YYYY-MM>.{md,pdf}` (`close_note`, company = directory name). `doc_id` is the **file stem** exactly (`POL-001-accounting-policy`, `CON-bharat-polymers`, `NOTE-sharma-2026-04`); CC-806's citations and the golden set (CC-907) rely on it. Headings: `# Title` once, then `## 1. Scope`, `### 4.2 Spread annual costs monthly` and so on in the policy; `## 1. Parties` in contracts.
- Design decisions for this spec (the ticket leaves them open):
  - **Source is the PDF.** Ingest converts the committed `.pdf` with docling (that is the point of CC-801's PDFs) and chunks docling's Markdown; the `.md` files are never read. Verify against real docling output (see Notes) that headings survive; if docling emits different levels, the chunker must still key on the heading text.
  - **Document hash** = hex sha256 of the PDF bytes plus a constant `pipelineVersion` string (bump it when chunking or the embedding model changes). Every chunk of a document stores that same value in `content_hash`. A document is skipped when `DocHashes` has its `doc_id` with an equal hash, **before** any docling or TEI call, so a second run needs neither service and writes zero rows.
  - **Section strings**: a numbered heading becomes `§<number> <text>` with the trailing dot of the number removed (`## 4. Prepaid expenses` → `§4 Prepaid expenses`; `### 4.2 Spread annual costs monthly` → `§4.2 Spread annual costs monthly`). An unnumbered heading is kept as is. Text before the first heading has a NULL section. `title` is the `# ` heading (fall back to the doc_id). `content` is the chunk body only; the embedding input is `title + "\n" + section + "\n" + content`.
  - **Dimension check**: any embedding whose length is not 384 is an error for that document and nothing is stored for it.
  - **Stale documents** (in the table, no longer in `corpus/`) are left alone and logged as a count; deleting them is out of scope.
- Shared consumer: CC-804 searches with the company filter inside SQL (`company_id IS NULL OR company_id = $2`), so every chunk must carry the right `company_id` (NULL only for the shared policy).
- Config: `DATABASE_URL`, `TEI_EMBED_URL`, `DOCLING_URL` are already required by `cmd/ingest/main.go`. Egress rule: no `http.Get`, `http.Post`, `http.DefaultClient` or `&http.Client{}` outside `internal/httpx`; this ticket makes no HTTP calls itself (it uses the CC-802 clients).

## Subtasks

- [ ] `chunk.go`: `type Chunk struct{ Section, Content string }` and `ChunkMarkdown(md string) (title string, chunks []Chunk)`. Split on `#`..`######` headings (ignore `#` inside fenced code blocks). A section of at most about 350 words is one chunk; a longer one splits on paragraph/word boundaries into pieces of about 350 words with about 50 words of overlap. A Markdown table (consecutive lines starting with `|`) is never split: if it pushes a chunk over the limit it becomes its own chunk. Empty sections produce no chunk. Pure and deterministic.
- [ ] `ingest.go`: `Ingest(ctx, deps, corpusDir string) (IngestStats, error)` where `IngestStats{Documents, Skipped, Converted, Chunks int; Duration time.Duration}`. Walk `corpus/` for `*.pdf` in sorted order; derive `doc_id`, `doc_type`, `company_id` from the path (a PDF that fits none of the three layouts is an error naming the path); load `DocHashes` once; skip unchanged documents; otherwise convert, chunk, embed (`title\nsection\ncontent`), check 384 dimensions, and `ReplaceDocChunks` once per document. A failure on one document is logged and collected; the others still run; the returned error joins them. Never log document text.
- [ ] `store/docs.go`: `DocHashes` and `ReplaceDocChunks` as in the Code map; keep errors wrapped with `%w`.
- [ ] `cmd/ingest`: `--corpus` (default `corpus`), `--keep-docling` (skip the stop). Build `store.Open`, `NewTEI`, `NewDocling` (only create the docling client; it is not called when everything is skipped). Log with `slog` JSON: one line per document (doc_id, status skipped/ingested, chunks) and a final summary with `documents`, `chunks`, `skipped` and `seconds`. After a run that converted at least one document, and unless `--keep-docling`, run the compose stop command through `os/exec` with a timeout; a failure to stop is a warning, not an error. A run that skipped everything does not call docker.
- [ ] Unit tests (fakes, no network, no Docker): chunker (headings and section strings including `§4.2` and `§4`, intro text with NULL section, a 900-word section splits with overlap and no chunk much over 350 words, a table stays whole, `#` in a code fence is not a heading, determinism); path derivation (policy NULL company, contract and note carry the directory company, a stray file errors); `Ingest` with fakes: first run stores chunks with the right `company_id`, the embedder sees `title\nsection\ncontent`, **a second run makes zero converter calls, zero embedder calls and zero store writes**, a changed PDF replaces only that document, a 383-dimension vector fails that document and writes nothing for it while others succeed, an embed error keeps the old chunks.
- [ ] Integration tests (`//go:build integration`): `TestIntegrationDocChunks` (store: `ReplaceDocChunks` replaces atomically, `DocHashes` returns one hash per doc, a failed insert, such as a wrong dimension, rolls the delete back); `TestIntegrationIngest` (real Postgres via `setupTestStore`-style helper, **real TEI and docling** when `TEI_EMBED_URL` and `DOCLING_URL` are set and reachable, else skip: ingest `corpus/` twice, assert the second run reports zero conversions and `count(*)` is unchanged, every chunk's `vector_dims(embedding) = 384`, `company_id IS NULL` only for `POL-001-accounting-policy`, contracts and notes carry `sharma` or `mehta`, and §4.2 exists as a section of the policy).

## Acceptance (human-readable)

- A second `make ingest` on an unchanged corpus writes zero rows, and does not need docling or TEI to be running.
- Every chunk row has a 384-dimension embedding; the shared policy has `company_id` NULL and every contract and note has its company, so CC-804 can filter inside the SQL.
- The ingest log ends with documents, chunks and seconds taken.
- The orchestrator runs the live integration steps (Postgres, TEI, docling up) and reports any skip as a skip, not a pass.

- Changing `corpus/**`, `internal/seed/**`, `migrations/**` or the docling and TEI clients.
