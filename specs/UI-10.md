# UI-10 · Audit and metrics rework with charts and CSV export

## Goal

Rework the checker's audit log (filters as chips, CSV export) and the run metrics page (stat tiles, server-rendered SVG charts for tokens, cost and verified rate) on the UI-02 components, without changing who may see them or any stored data.

## Context

- Ticket: `tasks/frontend-plan.md` (UI-10 row: "filter chips, export CSV, server-rendered SVG charts (cost per run, verified rate, tokens)"; page rows: Audit log `/audit` checker, Run metrics `/runs/{id}/metrics` all roles). Standard risk, no G5, but the CSV export moves customer data out of the browser, so it gets the care below.
- **Both pages and their routes already exist** (`routes.go:80-81`: `GET /audit` `checkerOnly` via `s.auditRoute`, `GET /runs/{id}/metrics` `anyRole` via `s.metricsRoute`, both 501 until their backend is set). Keep those rows, roles and the 501 behaviour. Do **not** edit `routes.go`: the only route this ticket adds is the export, through the `auditRoutes` hook in `routes_audit.go`.
- **Export route (new, `routes_audit.go`):** `{http.MethodGet, "/audit/export.csv", checkerOnly, s.auditRoute(s.handleAuditExport)}`. Same role as the page: a viewer or maker gets 403 from the role wrapper. `TestRouteHooksEmpty` (`routes_hooks_test.go`) expects every hook empty; remove `"audit": s.auditRoutes` from its map and add an assertion that `auditRoutes()` returns exactly that one row. That is the only edit allowed in that test file. The export has no nav entry (`navTable` in `shell.go` lists pages only and is not edited).
- Export is a GET with no body: CSRF does not apply, and it is not under `/api/*` so the API rate limit does not apply either, so **cap it**: at most 5000 rows per download (page the store with `Limit: 200` and the `Before` keyset until the cap or the end), and the response says so in a final comment-free way: if the cap was hit, set the header `X-Export-Truncated: true`. A client disconnect (`r.Context()` done) stops the loop.
- CSV rules: `encoding/csv`; header row `time_utc,actor,server,tool,args,result_count,latency_ms,error`; time as RFC3339 UTC; `args` is the compact JSON from `compactAuditArgs` (full, not truncated). **Neutralise spreadsheet formulas**: any cell that starts with `=`, `+`, `-`, `@`, tab or carriage return gets a leading `'`. Headers: `Content-Type: text/csv; charset=utf-8`, `Content-Disposition: attachment; filename="audit-<YYYYMMDD>.csv"` (fixed pattern, no user input in the name), `Cache-Control: no-store` (check what the existing security middleware already sets before adding), `X-Content-Type-Options: nosniff` comes from middleware. The filter is parsed by the **same function** as the page (extract `parseAuditFilter(r) (store.AuditFilter, string, bool)` from `handleAuditPage`; messages and 400 codes unchanged). Never log args or actors; log only the row count and the user name.
- **Filter chips.** The filter form stays a plain `GET /audit` form (works without JavaScript; CSP forbids inline script and style). Above the table show one removable chip per active filter (`Actor: x ×`), each an `<a>` to the same URL with that parameter dropped (and `before` dropped), plus "Clear all" when any is set. Values are escaped by templ; build the links with `url.Values`. An "Export CSV" `Button` link (`Href` = `/audit/export.csv?` + the same filter, without `before`) sits in the page header. Use `PageHeader`, `Card`, `SelectField`/`Field` (dates keep `YYYY-MM-DD`, `placeholder`, `pattern`), `DataTable` for the rows (args cell: `<code>` plus a `<details>` for the full text when truncated, as today), `EmptyState` when nothing matches, "Older" link kept as `a.older`.
- **Metrics page.** `PageHeader` with run id breadcrumb links as today (`/runs`, run, findings); a `StatTile` row: Status (`StatusChip`), Duration, Cost, Verified rate, Tokens in/out/cache (keep the `.input`/`.output`/`.cache`/`.cost`/`.duration`/`.verified-rate` hook classes the current tests read, or update those tests in `metrics_test.go` and say so). Keep the trace ID line and the "Usage by step" table (`DataTable`, row `data-step`, same numbers). Add charts:
  1. **Tokens by step**: grouped bar chart, one group per step family, series input, output, cache read, from `RunMetricsByStep`.
  2. **Cost by step**: single-series bars from `StepUsage.CostUSD` (decimal text: parse with `strconv.ParseFloat` for the bar height only; the label and table keep the exact text).
  3. **Recent runs** (cost per run and verified rate per run, two line charts or bars, newest on the right) for the last 12 runs of any company from `RecentRunTrend`. Show the chart only when the store offers it (see below) and there are at least 2 points; otherwise omit the card.
- **Charts (`templates/chart.templ` + `chart.go`).** Pure server-side SVG, no JavaScript. Inputs: `ChartProps{Title, Desc string; Unit string; Series []Series; Categories []string}`; `Series{Name string; Values []float64}`. Output: `<figure class="chart"><svg role="img" aria-labelledby=... viewBox="0 0 W H" preserveAspectRatio="xMidYMid meet">` with `<title>`/`<desc>`, gridlines, bars as `<rect>` and lines as `<polyline>`/`<circle>` whose geometry is attributes (`x`, `y`, `width`, `height`, `points`), **never a `style` attribute** (CSP `style-src 'self'`). Colour comes from CSS classes `.chart-s0 .chart-s1 .chart-s2` in `audit.css` using existing tokens from `tokens.css` (read it and reuse tokens; add none), with `fill`/`stroke` set in CSS, so light and dark both work and the contrast test in `design_test.go` is untouched. Below each chart a visually-hidden-safe **data table** (`<details><summary>Data</summary>` with a real `<table>`), so the numbers are available to screen readers and in tests. Axis labels and values come from `Categories`/numbers and are escaped by templ. Rules the code must enforce and tests check: zero or negative max (all values zero) draws an empty-state "No usage recorded" instead of a divide by zero; NaN and Inf become 0; bar height is rounded to one decimal; at most 24 categories and 4 series (extra are dropped, not drawn); labels longer than 14 runes are cut with an ellipsis; the y-axis max is a "nice" number (1, 2, 5 times a power of ten) so ticks read cleanly.
- **Trend data (store, one new read).** `internal/store/runtrend.go`: `type RunTrendPoint struct { RunID uuid.UUID; CompanyID, Month string; StartedAt time.Time; CostUSD float64; InputTokens, OutputTokens int64; Findings, Verified int }` and `func (s *Store) RecentRunTrend(ctx context.Context, limit int) ([]RunTrendPoint, error)`: runs whose status is `done` or `partial`, newest `started_at` first, limit clamped to 1..50, findings and verified counts by a `LEFT JOIN`/`count(...) FILTER (WHERE f.verified)` as `RunsSummaryStats` does (`runmetrics.go:104`), all parameters bound, no string building. The web side does not add the method to `AuditStore` (other fakes would break); `handleRunMetrics` uses `if t, ok := s.audit.(interface{ RecentRunTrend(context.Context, int) ([]store.RunTrendPoint, error) }); ok`. A trend error must not fail the page: log it (no data) and omit the chart card.
- Verified rate keeps its exact current format (`verifiedRate`, "N of M (P%)", "n/a" with no findings) in the text; the chart uses the numeric percent, 0 when there are no findings.
- Output safety: audit `args`, actor, tool, error and company or month strings are untrusted; templ escaping only, no `templ.Raw`, no `SafeURL` on user data except links built in Go from `url.Values` (as `OlderURL` is today). No new JavaScript and no new static asset.
- Shared files are owned by earlier tickets: do not edit `app.css` (it already imports `audit.css`), `design_test.go`, `ui*.templ`, `ui.go`, `layout.templ`, `shell.go`. All new rules go in `static/css/audit.css`, tokens only. If a class the old templates used is no longer used and was listed in `design_test.go`'s `unstyledOK`, that is harmless; if a *new* class is not styled and the legacy-class test complains, style it in `audit.css` rather than editing the test.
- Store row formatting helpers: `formatCost`, `runDuration`, `i64`, `runURL`, `findingsURL` already exist in the web and templates packages; reuse them.

- A checker filters the audit log, sees chips for each filter and removes one with a click, and downloads a CSV that opens cleanly in a spreadsheet with no formula running from log content.

- Check by eye in light, dark and at 420px width; no console CSP errors.
- Roles unchanged: audit and export checker only, metrics any role.
