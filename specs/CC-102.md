# CC-102 · ERPNext + India Compliance stack in Docker

## Goal

`make up` starts ERPNext with India Compliance, plus Postgres with pgvector and the two TEI model servers. docling-serve starts only when ingesting.

## Context

- Ticket: `docs/implementation-tickets.md`, section `CC-102`. It has the build commands, `apps.json`, and notes on Apple Silicon.
- Already in the repo (CC-101):
  - `deploy/docker-compose.yml`: postgres, tei-embed, tei-rerank, and docling under the `ingest` profile. It is complete; change it only if something is broken.
  - `deploy/erpnext/apps.json`: ERPNext and India Compliance on `version-15`.
  - `Makefile`: `up` and `down` drive `deploy/docker-compose.yml` and, once it exists, `deploy/erpnext/docker-compose.yaml`.
- **Don't edit the Makefile.** CC-002 owns it in this round. One-off steps (image build, site creation, setup wizard) go in scripts under `deploy/erpnext/`, and `docs/setup.md` documents them.
- The owner's machine is macOS on Apple Silicon. Use `base64 -i` and confirm the image is arm64. TEI's tag comes from `TEI_IMAGE_TAG` in `.env` (`cpu-arm64-1.9` on arm64).
- `.env.example` already has `ERP_BASE_URL=http://localhost:8080` and `ERP_SITE=erp.localhost`. Don't add variables to it: scripts read `ERP_ADMIN_PASSWORD` and `ERP_DB_ROOT_PASSWORD` from the environment, with local-only development defaults, and `docs/setup.md` says so.

## Subtasks

- [ ] Add frappe_docker as a git submodule at `deploy/frappe_docker`, pinned to a commit. This creates `.gitmodules`. Record the commit and why it was chosen in `docs/setup.md`.
- [ ] Check that `deploy/erpnext/apps.json` builds. If the build needs `payments` or another app, add it on the same branch. If India Compliance has no `version-15` branch that matches the ERPNext release, stop and report; don't switch branches silently.
- [ ] `deploy/erpnext/build-image.sh`: builds `close-copilot/erpnext:15` from `images/custom/Containerfile` with `FRAPPE_BRANCH=version-15` and `APPS_JSON_BASE64`, using the ticket's commands with the macOS-safe `base64`.
- [ ] Generate `deploy/erpnext/docker-compose.yaml` with `docker compose ... config` from `compose.yaml` plus the mariadb, redis and noproxy overrides, with `CUSTOM_IMAGE=close-copilot/erpnext`, `CUSTOM_TAG=15` and `PULL_POLICY=never`.
  - Commit the generated file.
  - Set `FRAPPE_SITE_NAME_HEADER=erp.localhost` on the frontend, so that `http://localhost:8080` resolves to the site.
  - The file must contain only frappe_docker's development defaults, no real secrets.
  - `deploy/erpnext/generate-compose.sh` regenerates it.
- [ ] `deploy/erpnext/new-site.sh`:
  - Creates `erp.localhost` with `--install-app erpnext --install-app india_compliance` inside the `backend` container. Check frappe_docker's docs for the database flags on this branch.
  - Is idempotent: if the site already exists, it exits 0 and changes nothing.
- [ ] `deploy/erpnext/setup-wizard.sh`:
  - Completes the setup wizard **without demo data**: country India, currency INR, fiscal year April to March, first company "Sharma Traders Pvt Ltd" (abbreviation `STPL`).
  - Prefer scripting it (`bench --site erp.localhost execute frappe.desk.page.setup_wizard.setup_wizard.setup_complete --kwargs ...`, or the method that matches this branch).
  - If it can't be scripted reliably, write the manual UI steps in `docs/setup.md` and say so in your report.
  - Is idempotent.
- [ ] `deploy/wait-healthy.sh <timeout-seconds>`:
  - Polls until all of these succeed, or the timeout passes: ERPNext's `/login` on 8080, TEI `/health` on 8081 and 8082, and Postgres `pg_isready`.
  - Exits non-zero, naming the service that isn't up, on timeout.
  - On first start, TEI downloads its models, which takes minutes.
- [ ] `docs/setup.md`: every step from a clean machine to a working stack, in order:
  - prerequisites (Docker Desktop with about 10 GB of memory, git submodules);
  - `cp .env.example .env`;
  - build the image, `make up`, create the site, run the wizard, `make down`;
  - the arm64 notes;
  - how to reset the ERPNext volumes.

## Follow-up (2026-10-08, owner-approved): allow deleting cancelled vouchers

CC-202's integration test inserts, submits, cancels and then deletes a ₹1 Journal Entry. ERPNext refuses to delete a cancelled voucher while its GL Entries exist unless Accounts Settings `delete_linked_ledger_entries` ("Delete Accounting and Stock Ledger Entries on deletion of Transaction") is on. Its default is off. See `AccountsController.on_trash` in erpnext/controllers/accounts_controller.py. CC-307's reset will need the same setting.

- [ ] `deploy/erpnext/setup-wizard.sh` sets `Accounts Settings.delete_linked_ledger_entries = 1` through `bench`, **also when the wizard has already completed**. Today the script exits early in that case, so the new step must run before or regardless of that check. It stays idempotent: if the value is already 1, it changes nothing and says so. It verifies the value afterwards.
- [ ] `docs/setup.md`: one short paragraph in the setup-wizard section naming the setting and why it's on. This is a local development and demo site; the product never deletes ledger entries.
- Acceptance for the follow-up: `deploy/erpnext/setup-wizard.sh` exits 0 twice in a row, the second run reporting no change, and the setting reads back as 1.
