# CC-805 · `search_documents` tool

## Goal

Document search becomes the MCP tool `search_documents` on the evidence server (`/mcp` only), limited to the run's company, with snippets of at most 600 characters.

## Context

- Ticket: `docs/implementation-tickets.md`, section `CC-805` (do not open it; everything needed is quoted here).
- Plan row: phase 3, integration-engineer, data-sensitive, depends on CC-804 and CC-503. Check: "Contract test; snippets at most 600 characters". Acceptance: the contract test passes and no snippet exceeds 600 characters; under a Sharma scope the tool never returns a Mehta chunk.
- Tool catalog row: evidence `/mcp` · `search_documents` · inputs `query, company?, doc_types?, k` · outputs `doc_id, doc_type, section, title, snippet, score`.
- Ticket description: "the tool serves MCP clients such as Inspector and Claude Desktop, and the workflow's retrieve step (CC-806). **No agent loop gets it.** The company filter comes from the run scope (CC-506), not from the caller's arguments." Subtasks: register the tool with a schema snapshot and contract test as in CC-505; force the company filter to the scope's company; an explicit other company returns `out_of_scope`.
- Invariants this ticket must keep (CLAUDE.md): retrieved document text never reaches a model that can call tools; the explainer's only tool is `emit_explanation`; the investigator has no `search_documents` and no admin tool; every MCP call is scoped to the run's company and month (CC-506); the company filter sits inside the SQL before ranking (CC-804).
- **Scope semantics (CC-506).** `mcpkit.Scope{RunID, Company, From, To, Exp}` is verified on every `/mcp` request. `Scoper.CheckCompany(req, company)` returns an `out_of_scope` tool error for another company, for a call without a valid scope, and for the discovery scope (its window is empty: `From > To`, company `-discovery-`), so it also refuses a session that has no month. `search_documents` has **no date argument**: documents are not month-bound, so the "month" check is exactly that the call carries a valid scope with a non-empty window. Do not invent a date argument. A nil `*Scoper` allows everything (stdio and unit tests only).
- **Search itself is not a scope check.** `retrieval.Searcher.Search(ctx, query, company string, docTypes []string, k int) ([]Hit, error)` rejects only an empty company; a blank or unknown company id otherwise gets just the shared policy (`company_id IS NULL`). Therefore the handler must check scope **before** calling Search and must pass Search the scope's company, never an unchecked caller value.
- `doc_chunks` columns: `doc_type` is `policy | contract | close_note`; `company_id` is NULL only for the shared policy `POL-001`, readable by every company; company ids are `sharma` and `mehta`.
- Search ranking SQL (`internal/retrieval/search.go`, `buildSQL`): the company predicate `(company_id IS NULL OR company_id = $2)` is inside the vector CTE and the full-text CTE. The final select is `FROM fused f JOIN doc_chunks c ON c.id = f.id`, which has **no company predicate**; CC-805 adds one.

### Behaviour

Input `SearchDocumentsInput` (json tags as the catalog): `query` (required), `company` (optional), `doc_types` (optional, `[]string`), `k` (optional int, default 5).

Output `[]SearchDocumentsOutput{DocID, DocType, Section, Title, Snippet string; Score float64}`, best first (an array, like the other evidence tools; an empty result is `[]`, not null). `Score` is `Hit.RerankScore` (TEI's raw cross-encoder score; do not normalise it or mix it with `RRF`).

Handler order, each step returning a tool error and calling nothing after it:

1. Scope. If `o.scope != nil`: take the verified scope with `o.scope.Scope(req)`; a call without a valid scope is refused by `CheckCompany` below. `company` resolves as: scoped and `in.Company == ""` → the scope's company; otherwise `in.Company` as given. Then `o.scope.CheckCompany(req, company)` **before anything else is validated or read**, so another company, an unknown id, the discovery scope and an unscoped call are all `out_of_scope` and never reach Search. Unscoped (`o.scope == nil`, stdio or tests): `company` is required (`errors.New("company is required")`) and must be non-blank.
2. `query` required and non-blank; at most 500 characters (else a tool error).
3. `doc_types`: each entry must be exactly one of `policy`, `contract`, `close_note` (exported constants in `tools.go`); anything else is a tool error naming the allowed values; duplicates are collapsed; an empty list means all types. Validation is against this fixed list, never against caller text.
4. `k`: 0 → 5; negative or above 10 is a tool error (`k must be 1 to 10`).
5. `o.searcher == nil` → tool error `document search is not configured`.
6. Call `searcher.Search(ctx, in.Query, company, docTypes, k)`; wrap errors `fmt.Errorf("search documents: %w", err)`. Do not put the query or hit text in the error.
7. Defence in depth on the way out: drop any hit whose `CompanyID` is non-nil and not equal to `company` (it should never happen; if it does, log one `slog` warn line with the hit's `doc_id` and the two company ids, never the text). Then build the output.

Snippet: `MaxSnippetChars = 600` (exported constant). Snippet is the hit's `Content`, whitespace-collapsed (`strings.Fields` joined by one space), cut to at most 600 **runes** at a rune boundary; if cut, the last rune of the 600 is `…` (so the total never exceeds 600). Never a byte slice through a multi-byte rune. A test feeds multi-byte (Devanagari and `₹`) content longer than 600 runes.

Wiring: add `type DocSearcher interface { Search(ctx context.Context, query, company string, docTypes []string, k int) ([]retrieval.Hit, error) }` and `func WithSearcher(s DocSearcher) Option` in `tools.go`. `RegisterTools` **always** registers `search_documents` (so schema listing and the contract test need no searcher); with no searcher a call returns `document search is not configured`. The tool has `Annotations: &mcp.ToolAnnotations{ReadOnlyHint: true}` (the agent registry refuses a server whose tools are not read-only). It is registered with `mcpkit.AddTool`, like the others, so audit and scope plumbing apply unchanged.

`cmd/mcp-evidence/main.go`: build the searcher once in `run` (`retrieval.NewTEI(cfg)` for the embedder and the reranker, `retrieval.NewSearcher(st.Pool(), tei, tei)`), add `config.EnvTEIEmbedURL` and `config.EnvTEIRerankURL` to the required env list passed to `cli.Main`, pass `evidence.WithSearcher(...)` through `newEvidenceServer`, in both transports. Fail fast at start-up rather than serve a tool that cannot answer. Update `cmd/mcp-evidence/main_test.go` for the new required variables and the new signature (it uses a fake searcher; no TEI).

### Second company filter (retrieval)

In `internal/retrieval/search.go`, the final join gets its own predicate:

```sql
FROM fused f JOIN doc_chunks c ON c.id = f.id AND (c.company_id IS NULL OR c.company_id = $2)
```

`$2` is already bound in every mode. This is **in addition to** the two predicates in the ranking CTEs, which must stay exactly where they are (before `ORDER BY ... LIMIT`, so no other company's row is ever ranked). Do not move, merge or loosen them. Extend the existing SQL-text unit test (`TestBuildSQLTenantFilterInsideCTEs` in `search_test.go` (line 160)) to assert, for all three modes, that the join carries the company predicate and that the CTE predicates are still present. The join predicate cannot be exercised in isolation through Search (the CTEs already filter), so the SQL-text test is its proof; keep the existing tenant assertions in `TestIntegrationSearchTenant` as they are.

## Acceptance (human-readable)

Tests, in `internal/evidence/tools_search_test.go` (names start `TestSearchDocuments`, no Postgres, fake searcher):

- **Out-of-scope company refused before Search.** Under a Sharma scope, `company: "mehta"` is an `out_of_scope` tool error and the fake searcher is never called. The same for an unknown id (`"nobody"`), for the discovery scope, and for a call with no `X-Run-Scope` (401 at the HTTP layer; also a direct handler call with a missing scope, if the harness allows it).
- **Blank company is the scope's company.** `company` omitted or `""` under a Sharma scope: the searcher is called with `"sharma"`.
- **Same company accepted.** `company: "sharma"` reaches the searcher with `"sharma"`.
- **docTypes validation.** `policy`, `contract`, `close_note` pass through (and combinations, de-duplicated); `"invoice"`, `""`, `"POLICY"`, `"policy,contract"` and `"%"` are tool errors naming the allowed values; the searcher is not called.
- **k and query bounds.** `k` 0 → 5, 11 and -1 refused; blank and 501-character queries refused.
- **Snippets.** A hit with 5,000 characters of content, with multi-byte runes, gives a snippet of at most 600 runes ending in `…`; a short hit is whitespace-collapsed and unchanged otherwise; an empty result is `[]`.
- **Defence in depth.** A fake searcher that returns a `mehta` hit under a Sharma scope: the hit is dropped (a NULL-company hit is kept).
- **Unconfigured searcher** is a tool error, not a panic.
