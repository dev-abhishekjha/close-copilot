# CC-403 · GSTR-2B loader and invoice-number normalisation

## Goal

`go run ./cmd/load gstr2b --company sharma --month 2026-09` loads that month's `gstr2b.json` into `gstr2b_entries` with a normalised invoice number for matching.

## Context

- Ticket: `docs/implementation-tickets.md`, section `CC-403`. Plan row: Phase 2, implementer, data-sensitive, depends on CC-401 and CC-305; check "Normalisation table tests; idempotent reload". Gates G1-G3 and G5; G4-tier1 because it touches evidence.
- Why: the same invoice is written differently by supplier and buyer ("abc/101" vs "ABC-0101"). One normalisation function, shared by this loader and the GSTR-2B matcher (CC-604), removes that noise. CC-604 will import `evidence.NormInvoiceNo`.
- File path: `data/external/<company>/<YYYY-MM>/gstr2b.json` (default; `--file` and `--data-dir` override, like `load bank`).
- Input shape (shared spec "GSTR-2B", simplified portal B2B section):

```json
{"data": {"gstin": "29AAACS1234A1ZX", "rtnprd": "092026",
  "docdata": {"b2b": [{"ctin": "27AABCC5678D1ZX", "trdnm": "Cloudly SaaS",
    "inv": [{"inum": "CLD/2026/0912", "dt": "12-09-2026", "val": 141600.00,
             "txval": 120000.00, "igst": 21600.00, "cgst": 0, "sgst": 0, "itcavl": "Y"}]}]}}}
```

- Mapping to table `gstr2b_entries` (PK `company_id, period, supplier_gstin, invoice_no_norm`):
  - `period` = `rtnprd` (MMYYYY) as `YYYY-MM`. Take it from `rtnprd`, never from `dt`: a late-filed invoice dated in the previous month sits in this return and is a genuine `gstr2b_wrong_period` finding for CC-604.
  - `supplier_gstin` = `ctin`; `supplier_name` = `trdnm`; `invoice_no` = `inum` as written; `invoice_no_norm` = `NormInvoiceNo(inum)`.
  - `invoice_date` = `dt` (dd-mm-yyyy) as a UTC-midnight `time.Time`.
  - `taxable_paise` = `txval`; `igst_paise`, `cgst_paise`, `sgst_paise` from the same-named fields; `val` is not stored.
  - `itc_available` = `itcavl` "Y" true, "N" false; anything else is a row error.
- Normalisation rule: uppercase; drop spaces, `/`, `-`, `_` and `.`; strip leading zeros from each run of digits (an all-zero run becomes `0`). Cases: `"abc/101"`, `"ABC-0101"`, `"ABC 101"` all give `"ABC101"`; `"INV/2026/007"` gives `"INV20267"`.
- Rules: money is `int64` paise; decode amounts as `json.Number` and convert with `money.FromJSONNumber` (never float). Dates are parsed to `time.Time` at UTC midnight. Synthetic data only.
- Evidence tool contract (CC-503, already merged) reads these rows: `list_gstr2b_entries` returns supplier_gstin, supplier_name, invoice_no, invoice_no_norm, invoice_date, taxable, igst, cgst, sgst, itc_available. Do not change store columns or the MCP schemas.
